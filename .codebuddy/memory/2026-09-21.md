## 一条来单：180nm CMOS 的 SHA 算法设计 —— 判定「不接」

- 他贴来一条闲鱼/客户需求："基于 180nm CMOS 工艺的 SHA 算法的设计与实现，对这个有把握的联系我"，问"这个可以接？"
- **判定：不接。** 理由三条（已写入 `MEMORY.md`「接单筛选规则」「能力边界」「已拒实例」）：
  - **学科不对**：这是**数字 IC 设计**（Verilog 写 RTL → 功能仿真 → 综合 → 时序收敛），要 180nm PDK；他是软件侧（Python / RAG / Agent），中间隔着一整个专业。**"算法"两个字最容易骗人**——他要的是硬件实现，不是写个 SHA-256 的 Python 函数。
  - **工具拿不到**：Verilog + ModelSim/VCS + Design Compiler + 180nm 工艺库都是商业授权，个人没有合法副本；学校实验室有，但拿来做私活违规。
  - **性质是毕设/课设代做**：交付物是别人的学位材料，风险与收益完全不对等。
- **对他额外危险的两点**：① 闲鱼号 **2026-09-18 才起步**，第一单翻车（做不出来 → 退款 + 差评 + 可能封号）会直接毁掉账号权重 ② 从零学到能交付要 6-12 个月，接管它等于关掉主线（找实习）。
- **给出的筛选规则（三问，任一答不上就拒）**：① 这个活要的工具现在装在我电脑里吗 ② 我交过一个同类产物吗（"学过相关知识"不算）③ 这东西最终交给谁（学校作业 / 毕设 → 直接拒）。
- **给了可直接复制的话术**（软拒 + 留客情）："这个方向我不做，我做软件侧的知识库/Agent 开发。如果您有文档问答、资料检索、Python 自动化这类需求，我这边可以接。"
- 提醒他：这类需求是群发的（挂"软件开发接单"都能收到硬件需求），客户通常价格敏感、验收标准模糊（"能不能跑通"由对方定义）。
