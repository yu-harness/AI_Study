# 简历八股生成

以本地简历为源头，把每条条目会遇到的面试问题出全、答全，写进一份可以反复背的问答文档。

## 何时使用

- 用户要求「按简历出题」「把所有面试问题写完整」「整理简历八股」。
- 用户对某道题说「不知道」「答不上来」，需要查证后给答案。
- 用户想知道简历里的说法在项目里是否站得住，或者项目还能补什么。

## 何时不使用

- 用户要知识讲解、概念解释、论文解读。
- 用户要改简历措辞、排版、投递策略。
- 用户要脱离简历的纯知识点出题。

## 工作流

### Step 1 读简历

先读最终简历 PDF：用 `pypdf` 提取文本，按页面顺序抄出全部条目，这是唯一的口径来源。
再读 `claim-map.md` 查每个数字的状态；`内容稿.md` 只作素材补充，页面上没有的条目不许写进八股。
以 PDF 上的条目标题为准，一条一条列出来，不许漏，也不许改标题措辞。

### Step 2 逐条展开问题

对每条条目出 4 到 8 个问题，覆盖四个角度：

- 机制：这一步具体在做什么，输入输出是什么。
- 数字：这个数怎么测出来的，口径是什么。
- 取舍：为什么选这套做法，换一种会怎样，代价是什么。
- 边界：什么情况下失效，现在哪里还没做好。

另外单独出一节「简历整体」，覆盖自我介绍、项目选型、两个项目的差别、最弱的一块。

### Step 3 每题同时给答案

不用等用户作答。答案按「答题规范」的三层写，控制在一段到三段，能直接念出口。

### Step 4 查证缺失的依据

答案里每个数字都要能在本地找到出处。查证顺序：设计文档 → 代码 → 评测结果 json → git log。
查不到就写明「本地没有这项证据」，并把简历里对应的说法记成口径问题。

### Step 5 写入八股文件

写入 `简历/简历八股.md`：

- 文件不存在就新建，开头写文件头：简历版本、生成日期、材料索引。
- 按「简历整体、项目、技能栏、口径防线」四部分组织，项目下按条目标题分小节。
- 同名小节已存在就跳过，只补缺的问题，不重写已有内容。
- 口径防线一节写清楚不能对外报的数字与说法。
- 只写问答，不写评分、评级、考察意图。

### Step 6 整理改进项

查证里发现的问题在对话里输出，不进八股文件：

- 口径不一致：简历写了，本地证据对不上。
- 能力缺失：简历暗示的能力，代码里没有对应实现。

每条写成「现状 → 证据 → 最小改进动作」。用户点头后再改代码。

### Step 7 自检后输出

逐条对照「验收标准」，任意一条不满足就重做。

## 答题规范

答案分三层，讲完控制在两到三分钟：

- **事实与口径**：哪个项目、什么时间、数字是多少、怎么测的。
- **机制**：这个数字对应的代码在做什么，关键步骤是哪些。
- **边界**：这套做法什么时候失效，代价是什么，哪里还没做好。

只讲机制不讲口径，会被当成背文档；只讲口径不讲边界，会被继续追问。

## 查证规范

- 数字先看 `claim-map.md` 的状态标注，标了 ⛔ 与 ❓ 的一律不许当成事实讲。
- 机制去看对应设计文档；设计文档与代码不一致时以代码为准，并把不一致记成口径问题。
- 评测数字去看原始 json 或 `eval/results/`，口头话术里的数字只能当线索。
- 引用证据时给出相对路径与能定位的字段名或函数名。

## 输出模板

### 八股文件（`简历/简历八股.md`）

```
# 简历八股

> 简历版本：<版本与日期>｜生成日期：<日期>
> 数字来源：`简历/大模型Agent开发/work/claim-map.md`

## 一、简历整体
### <小节名>

**问**：<面试官原话>
**答**：<一段到三段，含数字与机制>

## 二、<项目名>
### <条目标题>

**问**：……
**答**：……

## 三、技能栏
## 四、口径防线
```

### 对话里（本轮新增部分的摘要）

只报这次新增了哪些小节、几个问题、查出哪几处问题，不重复八股正文。

## 提问规范

- 口语化，能直接念出口。用「你能不能说说」「如果……你会怎么处理」「我这边遇到个情况……」。
- 一次只问一件事，带具体场景与数字。
- 从简历原话出发。简历写「权限治理」，就问一次越权尝试被拦下来的经过。
- 可以写一句带错误前提的问法，让题目有区分度。
- 提问里不出现答案。

## 禁忌清单

- 不编造论文、数据、API、公司案例，不虚构项目经历里没有的能力。
- 不报分数、不给评级表、不写及格线和考察意图。
- 数字只能用 `claim-map.md` 里标为已确认的来源。
- 八股文件里不写改进项，改进项只在对话里给。
- 改进项不许直接改代码，先列出，等用户确认。

## 验收标准

输出前逐条确认：

- [ ] 最终简历 PDF 上每条条目都有对应小节，标题措辞与 PDF 一致
- [ ] 页面没有的条目没有写进八股
- [ ] 每条条目至少 4 个问题，覆盖机制、数字、取舍、边界
- [ ] 每道题都有答案，答案含数字与机制
- [ ] 数字都能在本地找到出处
- [ ] 口径不一致与能力缺失写进了「口径防线」或在对话里给出
- [ ] 八股文件里没有评分与考察意图
