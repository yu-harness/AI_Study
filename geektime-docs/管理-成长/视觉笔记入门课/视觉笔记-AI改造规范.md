# 视觉笔记改造规范（给 AI 用）

> [!abstract] 用途
> 把一份线性文字的笔记改造成"视觉笔记结构"时，按本文件执行。本文件本身就是可直接粘进对话的规则说明，也可以只取第 8 节的 prompt。

## 0. 一句话

视觉笔记 = **有层次的模块 + 明确的连接 + 一致的视觉语言**。装饰服务于结构，结构服务于内容。

---

## 1. 三条铁律

| 铁律 | 含义 | 违规示例 |
| --- | --- | --- |
| **内容为王** | 视觉元素只为让关系更清楚，不为好看 | 给每段配一个不相关的图标，信息量零增加 |
| **先文字后容器** | 先把要点写出来，再决定用什么框装 | 先画三个框，结果第一个框写两行就满了 |
| **少而准** | 一种主强调 + 黑白灰打底 | 全文五种颜色、八种 callout，读者找不到重点 |

---

## 2. 转换流程（按顺序执行）

| 步骤 | 动作 | 产出 |
| --- | --- | --- |
| 1 提问 | 为原文生成 3~5 个"读之前想知道什么"的问题 | 问题清单（用来筛选要点，防止抄书） |
| 2 抽点 | 一个要点一条，**用原文措辞**，关键词写成完整短语 | 要点池（不排序、不合并） |
| 3 归类 | 把要点分成 3~7 个模块，每模块一个标题 | 模块表 |
| 4 判关系 | 模块两两判关系，按第 4 节选构图 | 构图方案 |
| 5 落版式 | 标题 → 模块 → 连接 → 强调 | 成稿 |
| 6 自检 | 按第 9 节清单过一遍 | 修改项 |

**硬约束**：新增的只有"结构"和"标记"，事实、数字、公式、原文结论一律不改、不删、不合并改写。

---

## 3. 视觉元素 → Markdown 映射

| 视觉元素 | 原始语义 | Markdown 实现 |
| --- | --- | --- |
| 点（无序） | 并列要点 | `- ` |
| 点（有序） | 步骤、优先级 | `1. ` |
| 直线 | 强连接、"就是这样" | `→`；表格相邻列 |
| 虚线 | 未发生、推测、弱关系 | `⇢`；mermaid `-.->` |
| 折线 | 波动、起伏、情绪曲线 | 两列"时间 / 状态"表；mermaid 多次转折 |
| 电话线 | 纠结、反复 | `↺` + 一句说明 |
| 弹簧线 | 张力、拉扯 | `⇄` |
| 单线箭头 | 串联、流转 | `→`；mermaid `-->` |
| 空箭头（双线） | 连接 + 能装内容 | 表格首列为箭头、次列为内容；或 callout 内写流转 |
| 回旋箭头 | 走了弯路、复盘 | mermaid 回边；或用"尝试 → 失败原因 → 修正"三段表 |
| 发散-收敛箭头 | 一个起点分头做、最后汇总 | mermaid 多分支汇聚 |
| 复盘箭头（分层递进） | 时间推进 + 分维度 | 三列表：阶段 / 问题 / 改进 |
| 圆形 | 包含、并列、占比、共识 | 括号嵌套；"占比"用两列表（项 / 百分比） |
| 三角形 | 层级、三点循环、对立 | 缩进列表（金字塔）；对立用两列对照表 |
| 方形 | 分割、排序、前后叠加 | 表格；`>` 引用块 |
| 方形对话框 | 不容置疑的指示 | `> [!important]` + 标注发言人 |
| 圆形 / 云状对话框 | 讨论、不确定、猜测 | `> [!question]` / `> [!note]` |
| 爆炸框 | 强烈情绪、突发 | `> [!warning]` / `> [!danger]` |
| 一大一小对话框 | 强弱、压制 | 两列表，列宽或缩进体现强弱 |
| 容器（笔记本） | 个人思考 | `> [!quote]` |
| 容器（A4 纸 / 大白纸） | 正式条文、对外通告 | `> [!abstract]` |
| 容器（白板） | 分享者的板书补充 | `> [!info]` |
| 容器（电脑 / 手机） | 线上、App、私密 | 行内代码标注来源 `app: 飞书` |
| 人物 | 谁说的、谁做的 | 段落开头 `**主持人**：` |
| 图标 | 概念速记 | 术语加 `**加粗**`；有独立笔记则 `[[链接]]` |
| 单线字 | 正文 | 普通段落 |
| 双线字 | 模块标题 | `##` |
| 立体字 / 创意字 | 全篇标题、关键词 | `#` + 一句主旨；关键词加粗 |
| 红色 | 警示、重要 | `> [!warning]`，全文 ≤ 1 处 |
| 黄色 | 轻快、底色 | 背景说明用 `> [!note]` |
| 蓝色 | 理性、商务、科技 | 流程/机制说明 |
| 绿色 | 生命、成长、和平 | 结论/收益 |
| 紫色 | 神秘、精神、女性主题 | 谨慎使用，一般不用 |
| 橙色 | 温暖、重点 | 关键结论强调 |
| 黑白灰 | 主体内容 | 正文默认样式 |

**配色落地原则**：一份笔记最多 **1 个主强调**（选一种 callout 类型贯穿）+ 黑白灰正文。颜色不是越多越好，原文反复强调"用最少的颜色达到最好的效果"。

## 4. 内容关系 → 构图选择

先判关系，再选版式。判据看**连接词与提问方式**。

| 关系 | 判据 | 构图 | 具体做法 |
| --- | --- | --- | --- |
| **并行** | "几个方面""分别""模块" | 分栏 / 模块化 | 每块一个 `###` 小标题 + 3~5 条要点 |
| **并行（散点）** | 同一主题下要点很多且互不相关 | 散点 | 用一张表收敛，标出主次（重要项加粗），不要真的散排 |
| **重叠 / 交叉** | "共同点""交集""都涉及" | 文氏图 | 三列表：(A 独有 / 共有 / B 独有) |
| **层级** | "上级""包含""从属""优先级" | 金字塔 / 缩进 | 缩进列表；超过三层改用表（层 / 内容） |
| **对立 / 共识** | "vs""优缺点""分歧""共识" | T 字网格 | 上方"共识"一行，下方两列对照 |
| **矩阵比较** | "对比""评分""交叉判断" | 2×2 或行列矩阵 | 表头为两个维度，格内写结论不写形容词 |
| **线性** | "首先/然后/最后""流程""时间" | 时间轴 | 有序列表；或 mermaid `flowchart LR` |
| **循环** | "闭环""迭代""反馈""回到" | 闭环 | mermaid 带回边的环；列表形式用"回到第 1 步" |
| **发散** | "围绕""多个角度""影响因素" | 中心辐射 | mermaid `mindmap`；或"主题 + 分支表" |
| **发散 + 收敛** | "汇总""归纳""多个来源得出" | 漏斗 | mermaid 多分支 → 单节点 |
| **具象场景** | 有"旅程/组织/成长/项目"隐喻 | 树形 / 旅程 / 汽车 | 阶段表 + 一行隐喻说明（如"像一棵树：根=资源，干=主线，叶=成果"） |

**默认优先级**：能判出"线性/层级/对比"就不要用"发散"，因为前三种读者一眼能读懂结构。

**mermaid 使用边界**：只在"关系本身就是图"时画（流程、闭环、分支汇聚、时间轴）；关系能用表格说清时不用图。

---

## 5. 版式规范

| 规范 | 要求 |
| --- | --- |
| 首屏 | 标题（`#`）→ 一句话主旨（callout）→ 结构总览（一张表或一张图），三段之内读完 |
| 标题分级 | 最多三级；`#` 全篇唯一，`##` 是模块（3~7 个），`###` 是模块内分组 |
| 模块标题 | 名词短语，不超过 12 字；同一层级的标题字数尽量接近 |
| 留白 | 模块之间空一行；单个段落不超过 3 行；表格前后各空一行 |
| 连接 | 相邻模块之间要有**显式关系**：承接词（因此/相比之下/具体到）或箭头；不允许模块直接堆叠 |
| 强调 | 每屏加粗 ≤ 2 处；全文 callout 类型 ≤ 3 种 |
| 结尾 | 一句总结（复述结构，不引入新信息） |
| 禁止 | 无信息量的装饰性图标、无意义的 emoji、为凑对称而编造的空格或空列 |

**必备三要素**：笔记标题、关键内容组成的模块、模块与模块之间的链接关系。三样齐了才算成稿，缺任何一样都只是"分段文字"。

## 6. 静态内容（书、文章、文档）处理流程

原始七步，压缩成 AI 可执行的五步：

| 步 | 动作 | 判定标准 |
| --- | --- | --- |
| 1 定目的 | 明确"给谁看、还原原文还是表达理解" | 目的不同，详略不同：还原→保结构；表达→保观点 |
| 2 框范围 | 划定处理边界，但先看上下文确认这段在全文中的作用 | 边界外的内容只在"作用说明"里出现一句 |
| 3 提问粗读 | 先列 3~5 个问题，再扫大模块 | 问题答不上来的段落，说明不是重点 |
| 4 细读抽点 | 一点一条，用原文措辞，关键词写全 | 不允许把"三个条件"缩成一个词 |
| 5 连线成构 | 归类 → 判关系 → 选构图 → 落版式 | 见第 2、4 节 |

---

## 7. 动态内容（会议、演讲、播客）处理流程

**四个阶段**：聆听 → 记录 → 整理 → 美化。整理与美化都可以放到会后。

### 7.1 什么信息值得记（聆听信号）

| 信号 | 说明 |
| --- | --- |
| 高响度 | 对方提高音量说的内容 |
| 有重复 | 讲了两遍以上的内容 |
| 有结构 | "首先、其次、然后、最后"后面的内容 |
| 有提纲 | "我今天讲三点"这类预告 |

### 7.2 记录五原则

1. **先文字，后画画**（画画会分心，跟不上语速）
2. **用原话，不阐释**（改写既慢又失真）
3. **关键词写全**（写成短语或整句，分享给别人也能看懂）
4. **重点要突出**（重要处先写大、后加框）
5. **文字之间留白**（为后续补视觉元素留位置）

### 7.3 整理逻辑的默认结构

动态信息的默认逻辑是**线性时间**：先讲了什么、后讲了什么。有明确分歧时升级为"对立/共识"，有多方发言时用"人物 + 对话框"结构。

## 8. 可直接使用的 Prompt

```text
你是一名视觉笔记编辑。请把下面的笔记按"视觉笔记结构"重排，规则如下：

【铁律】
1. 只加结构和标记，不改事实、不删信息、不改写原文结论；公式、数字、代码原样保留。
2. 先要点、后容器：先把内容抽成要点，再决定用表格还是 callout。
3. 一份笔记只用一个主强调（一种 callout 类型）+ 正文黑白灰。

【流程】
1) 用 3~5 个问题自检原文重点，答不上来的段落降级为补充说明。
2) 把内容抽成要点，一条一个信息，关键词写全，用原文措辞。
3) 归成 3~7 个模块，每个模块起一个不超过 12 字的名词短语标题。
4) 判定模块之间的关系：并行 / 重叠 / 层级 / 对立 / 矩阵 / 线性 / 循环 / 发散 / 发散收敛。
5) 按关系选版式：
   并行→分栏模块；重叠→三列交集表；层级→缩进或分层表；
   对立→共识一行+两列对照；矩阵→行列对比表；
   线性→有序列表或 flowchart LR；循环→带回边的 flowchart；
   发散→mindmap；发散收敛→分支汇聚的 flowchart。
6) 首屏放：标题 + 一句话主旨 + 结构总览（表或图）。
7) 每个模块之间补显式承接（因此/相比之下/具体到/之后）。

【版式】
- 标题三级以内；每屏加粗 ≤2 处；callout ≤3 种；段落 ≤3 行。
- 关系能用表格说清就不用图；只有流程、闭环、分支汇总才用 mermaid。
- 不加装饰性图标，不加无意义 emoji。

【输出】
A. 改造后的完整 Markdown；
B. 一份"改动说明"：模块划分理由、选用的构图、删除了哪些重复表述。
```

---

## 9. 自检清单

- [ ] 有没有一句话主旨，且首屏能读完
- [ ] 模块数是否在 3~7 之间，每个模块都有标题
- [ ] 模块之间是否有显式关系（承接词或箭头），有没有"平行堆叠但互不相干"的段落
- [ ] 每个要点是否都能归到某个模块，有没有孤立条目
- [ ] 加粗是否 ≤2 处/屏，callout 是否 ≤3 种
- [ ] 是否有"为装饰而装饰"的元素，删掉后信息量是否不变
- [ ] 原文的事实、数字、公式、限定条件是否完整保留
- [ ] 结尾是否只是复述结构，没有引入新结论
