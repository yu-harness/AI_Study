# 2.1 模型微调（SFT）

> [!abstract] 一句话
> SFT 用"指令 + 回答"的成对数据做监督学习，让基座模型学会**按要求回答**。

> [!info] 本节路线
> 1. SFT 在优化什么（目标函数，与预训练的分工）
> 2. 六类典型应用场景
> 3. 六条业界共识（含出处）
> 4. 全量微调与 PEFT 的取舍

---

## 一、SFT 在做什么

预训练让模型学会"预测下一个 token"，SFT 让模型学会"看到指令后该怎么答"。训练数据是一批 $(x, y)$ 对：$x$ 是用户指令，$y$ 是期望的回答。损失只在回答部分计算：

$$
\mathcal{L}_{\text{SFT}}=-\sum_{t}\log\pi_\theta\left(y_t\mid x,\ y_{<t}\right)
$$

也就是**最大化标准答案每个 token 的预测概率**，指令部分只作为条件、不参与损失。这一步与强化学习的区别在于：SFT 只模仿示范答案，不利用"A 比 B 好"这类相对偏好（后训练为什么不能停在 SFT，见 [[强化学习_面试真题]] 第 2 题）。

## 二、六类典型应用场景

1. **风格化交互输出**
   针对特定语料风格进行适配训练，典型应用如将模型输出调整为《甄嬛传》古风对话体，满足特定场景的文体一致性需求。

2. **限定域问答优化**
   适用于查询空间高度受限的业务场景（如 5-6 千条标准问题库），通过精准问答对训练提升查询匹配准确率；需注意当业务复杂度超出阈值时，需进行全参数后训练。

3. **轻量级领域知识注入**
   适用于专业不太复杂的垂直领域知识迁移。对于医学、法律等高复杂度专业领域，建议采用领域预训练（continued pre-training，即继续预训练）而非单纯微调方案。

4. **数学、代码等专项能力强化训练**
   主流技术路径包括代码生成优化与数理逻辑提升。例如 DeepSeek、Kimi 等发布新模型之前，都会基于特定数据集做定向微调来刷榜。

5. **Function calling 支持优化**
   通过结构化输出训练增强 API 调用、工具使用等函数执行能力，构建模型与外部系统的标准化交互接口。

6. **Agent 协作能力强化**
   针对多 Agent 协同、任务拆解与状态维护等复杂场景，通过特定训练模式提升模型的流程控制与策略规划能力。

## 三、业界共识

| #   | 共识                                                                                    | 出处                                                                              |
| --- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 1   | Prompt 的**质量和多样性远比数量重要**。工程经验值：全量微调 30B 量级的 base model 约需 10w 条数据，LoRA 微调 30B 约需 2w 条 | 经验值；参见《LIMA: Less Is More for Alignment》                                        |
| 2   | **合成数据很重要**。数据需要尽可能覆盖所有类别的业务问题，通过不同方式多路合成，减少合成数据的 bias                                | 《Phi-3 Technical Report: A Highly Capable Language Model Locally on Your Phone》 |
| 3   | 可以**加点预训练数据进去**，减少灾难性遗忘                                                               | 《The Llama 3 Herd of Models》                                                    |
| 4   | 一般训练 **1~3 个 epoch**                                                                  | 工程经验，无对应论文                                                                      |
| 5   | **能全量微调就不要 PEFT**。上述六类场景中，只有 1、2、6 适合做 PEFT                                           | 工程经验，无对应论文                                                                      |
| 6   | SFT 阶段**不能做太多知识注入**。过多知识注入，或超出模型能力本身的回答过多，会导致**对齐税**（Alignment Tax）                   | 工程经验，无对应论文                                                                      |

> [!warning] 两个数字不要混
> 《LIMA》的结论是 **1000 条精选数据**就能做出不错的对齐效果，衡量的是"对齐质量"；表中 10w / 2w 条是**覆盖业务分布**的工程经验值。两者口径不同，不能互相引用为证据。

## 四、全量微调与 PEFT

### 4.1 PEFT 是什么

**PEFT**（Parameter-Efficient Fine-Tuning）通过**最小化微调参数的数量和计算复杂度**，提升预训练模型在新任务上的性能，从而缓解大型预训练模型的训练成本：用特定领域数据对预训练模型做针对性优化，以提升其在特定任务上的表现。

### 4.2 两种方式的对比

| 维度 | 全量微调 | 参数高效微调（PEFT） |
| --- | --- | --- |
| 参数调整范围 | 更新预训练模型的**所有参数** | **仅更新少量新增参数**（如适配器、LoRA 层）或部分原参数 |
| 计算资源需求 | 高（需存储和计算全量梯度） | **低**（仅需计算部分梯度，显存和算力需求大幅降低） |
| 过拟合风险 | 较高（尤其在小数据集场景） | **较低**（冻结大部分参数，保留预训练知识） |
| 模型保存与部署 | 需保存完整模型参数（体积大） | 仅需保存少量新增参数（体积小，共享基础模型） |
| 多任务适配能力 | 需为每个任务保存完整模型 | 可复用同一基础模型，仅切换少量参数 |
| 典型方法 | 直接微调所有层 | LoRA、Adapter、Prefix-Tuning、Prompt Tuning 等 |
