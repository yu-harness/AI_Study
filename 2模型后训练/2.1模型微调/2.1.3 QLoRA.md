# 背景知识

## **Scaling Law
计算量 FLOP（假设算 $a\times b$ 和 $b\times c$ 矩阵的乘积，FLOP 为 $2abc$）与 数据集大小和模型参数量 成正比。
$C\approx 6ND$
Scaling Law 指出可以通过在**小计算量**时得到损失值，预测大计算量的损失。
![[Pasted image 20261111092934.png|600]]

**Scaling Law 的三条经验曲线**：**损失**会随计算量、数据量、参数量增加而下降，而且在双对数坐标下几乎是直线——也就是幂律。

 是关键：一次前向加反向，每个参数每个 token 大约要 6 次浮点运算，所以计算量约等于「参数量 × token 数 × 6」
$$L(N,D)=E+\frac{A}{N^{\alpha}}+\frac{B}{D^{\beta}}$$
右下角这条公式（Chinchilla）把损失拆成三块：$E$ 是数据本身的下限，$A/N^\alpha$ 是模型太小的损失，$B/D^\beta$ 是数据不够的损失。它带来的结论就是图下那句——**计算量固定时，宁可模型小一点、数据多一点，loss 更低**，这也是“20 个 token 配 1 个参数”的由来。

## 量化基础

​**非对称量化**，需要记录缩放因子 $q_x$ 和零点值 $zp_x$。
![[Pasted image 20261111093639.png]]
**对称量化**，记录缩放因子 $q_x$，使用更普遍，精度较低（当数据非对称分布时，会导致部分区间浪费）
![[Pasted image 20261111094005.png]]
**非均匀量化**，针对原始数值分布不均匀的情况，需要记录每一个桶的位置，参数更多。
![[Pasted image 20261111094044.png]]
对比以上三种量化，最常用的是**对称量化**。

| 特征    | 对称量化                           | 非对称量化                            | 非均匀量化           |
| ----- | ------------------------------ | -------------------------------- | --------------- |
| 量化范围  | 以零点对称（如 $[-a,a]\to[-127,127]$） | 允许非对称范围（如 $[0,2.5,8]\to[0,255]$） | 量化区间步长可变（如对数间隔） |
| 零点偏移  | 无（Zero Point = 0）              | 有（通过 Zero Point 对齐数据分布）          | 可能有（取决于具体实现）    |
| 硬件友好性 | 极优（适合 SIMD 指令加速）               | 良好（需额外存储 Zero Point）             | 较差（需查表或复杂计算）    |
| 精度损失  | 数据分布对称时最优                      | 非对称数据下精度更高                       | 关键区域精度保持最佳      |
| 存储开销  | 仅需存储缩放因子（scale）                | 需存储 scale 和 zero point           | 需存储量化表或参数化步长函数  |
**量化的粒度**：粒度大时损失的值会更多，且异常值影响到的参数更多。粒度小需要存储更多的scale factor![[Pasted image 20261111094225.png]]

训练时计算资源消耗分布：
- **模型参数和梯度**：完整的模型参数和需要更新的参数的梯度。
- **优化器**：Adam 需要维护一阶和二阶动量
- **激活函数**：在反向传播时，需要前向传播的 activation 的值。

LoRA 能大量减少梯度和激活值需要的计算资源，但**参数仍然占据很大空间**。
# 正文

QLoRA通过减少每个参数对应的bit数，实现计算量的减少。在训练过程中，QLoRA首先将**模型用4-bit存储**，然后在训练时把数值**反量化到bf16**后进行训练。这样的设计使得训练所需的显存大大减少。

![[Pasted image 20261111094442.png]]

这张是 QLoRA 论文的 Figure 1，把三种微调方式的**每参数显存开销**摊开算了一遍。

**全量微调**（16 bit）里，权重 16 + 梯度 16 + Adam 的一二阶动量 64，合计 96 bit，也就是 12 字节/参数——7B 模型光这部分就 84 GB。

**LoRA** 不存全量梯度和动量，只算 **adapter** 的，平摊下来 17.6 bit/参数；**QLoRA** 再把底座压到 4 bit，变成 4 + 0.4 + 0.8 + 0.4 ≈ 5.2 bit/参数，只有 LoRA 的三分之一左右。

右下角那条粉色箭头是另一个关键设计：**paged optimizer**，把优化器状态在显存峰值时**换到 CPU 内存**，躲开 OOM；绿色箭头是梯度流，蓝色是参数更新。

一句话总结：LoRA 省的是梯度和优化器状态，QLoRA 在此基础上连**底座权重**也省了。

**Qlora 使用 4-bit NormalFloat (NF4)**，也就是 Quantile Quantization，一种在信息论上最优的数据类型，确保输入向量落入到每个量化区间的值的数量相同。QLoRA 论文证明预训练神经网络权重通常遵循**以 0 为中心的正态分布**，因此可以通过缩放 $\sigma$ 使分布适应我们的数据范围（本文采用 $[-1,1]$）。

## **NF4 量化与反量化**

**第一步：按 $\mathrm{absmax}$ 归一化。** 针对输入向量 $X=[0.32,-1.76,0.025,-1.22]$，采用**对称量化**，找到 $\mathrm{absmax}(X)=1.76$，将 $X$ 归一化成 $[0.1818,-1,0.0142,-0.6932]$。

**第二步：舍入到最近的码点。** NF4 的码点为 $\mathrm{NF4}=[-1.0000,-0.6962,-0.5251,-0.3949,-0.2844,-0.1848,-0.0911,0.0,0.0796,0.1609,0.2461,0.3379,0.4407,0.5626,0.7230,1.0000]$（这张表怎么来的后面介绍），归一化后的每个数都到这里面找最近的那个，得到 $[0.1609,-1.0000,0.0796,-0.6962]$。注意尽管 $0.0142$ 距离 $0.0$ 更近，但是在神经网络中通常用 0 进行 padding，为了区分 padding 和较小的数，不能将较小的数舍入为 0，所以它只能往上取到 $0.0796$。

**第三步：存下标，不存数值。** 每个值在 NF4 表里的位置就是它的 **4-bit 编码**：$0.1609\to9$、$-1.0000\to0$、$0.0796\to8$、$-0.6962\to1$，于是原向量 $[0.32,-1.76,0.025,-1.22]$ 最终存成 $[9,0,8,1]$，每个参数只占 4 bit，整个 block 再额外存一个 $\mathrm{absmax}$。

**反量化**则是把上面倒着走：$[9,0,8,1]$ 查表还原成 $[0.1609,-1.0000,0.0796,-0.6962]$，再乘以 $\mathrm{absmax}(X)=1.76$ 回到原量级。**反量化存在一定误差**，如 $0.1609\times 1.76=0.283184$，右图中展示的是理想中不存在误差的情况。
![[Pasted image 20261111094919.png]]

总结一下，分为 3 个步骤。
1. 计算出量化常数 $N$（在对称量化中 $N=\mathrm{absmax}(X)$），将输入向量 $X$ 映射到目标量化区间 $D$（例如 $[-1,1]$）中。该区间的分位函数为 $Q_x$。
2. 对于 $X/N$ 中的每个元素，找到分位函数 $Q_x$ 中计算到的最相近的值 $q_i$
3. 将 $q_i$ 对应的索引 $i$ 存到输出向量 $T^Q$ 中。

## **分位数量化**

最理想的情况是，分位函数中的每一个数都以相同概率被用到。例如采用 NF4 作为分位函数，输入 $X$ 长度为 1600，其中的 16 个值每个被选中 100 次。

为了实现这一特性，可以将概率分布函数 $f_X$ 分为 $2^k$ 个区间（$k$ 表示量化后的一个数字占 $k$ bit），每个区间都有相同的面积，这些区间的中点即为 $q_i$。

为了找到 $q$ 值，就需要找到**具有相等概率质量**的累积分布函数 $F_X$ 的 $2^k$ 个不重复 $x$ 值，这些值可以通过使用其反函数，即分位函数 $Q_X=F_X^{-1}$ 找到。

下图为一个以 0 为中心的正态分布的累积分布函数的**反**函数 $F_X^{-1}$，横轴表示概率，纵轴表示值，$(0.5,0)$ 表示值小于 0 的概率为 0.5。
![[Pasted image 20261111100215.png]]

通过估计 $N(0,1)$ 分布的 $2^k+1$ 个分位数，来获取 $k$ bit 分位数量化的 $q$。
![[Pasted image 20261111100539.png]]

## **NF4**

对输入数据，经常用 0 进行 padding，以保持特定的空间维度或确保数据的对齐。因此对零的精确表示确保了这些 padding 能够准确地表示。对称的 $k$ 位量化意味着对于值零没有精确的表示。因此 NF4 采用**非对称**的量化，分别考虑**正值和负值**的分位数，然后合并它们。在负的部分创建 $2^{k-1}$ 个值，在正的部分创建 $2^{k-1}+1$ 个值，然后删除重叠的 0。
![[Pasted image 20261111111947.png|670]]
```Python
delta = 1/2*(1/32+1/30)
print(torch.linspace(delta, 0.5, 8))
print(norm.ppf(torch.linspace(delta, 0.5, 8)))
输出：
tensor([0.0323, 0.0991, 0.1659, 0.2327, 0.2996, 0.3664, 0.4332, 0.5000])
[-1.84813142 -1.28665578 -0.97040379 -0.72985929 -0.52568489 -0.34148556
 -0.16827238  0.        ]
```
![[Pasted image 20261111112305.png]]

```Python
print(torch.linspace(0.5, 1-delta, 9))
print(norm.ppf(torch.linspace(0.5, 1-delta, 9)))
结果：
tensor([0.5000, 0.5585, 0.6169, 0.6754, 0.7339, 0.7923, 0.8508, 0.9092, 0.9677])
[0.         0.14707497 0.29742005 0.45484772 0.6245116  0.81448966
 1.03979003 1.33611882 1.84813166]
```

将两部分q合并，去掉重复的0，就得到了N（0，1）分布的NF4。然后将q的值归一化到[-1, 1]范围内，就得到了[-1, 1]区间内的NF4。

## **二次量化**

二次量化的目的是为了**节省量化常数占用的空间**。为了降低**异常值**对量化的影响，量化的粒度一般比较小，这需要存储大量的量化常数。例如当粒度为 64，且采用 32 位的量化常数时，对于每个参数相当于增加 $32/64=0.5$ 个 bit，用于存储量化常数。

对于第一次量化的量化常数 $c_2^{\mathrm{FP32}}$，将其作为第二次量化的输入，产生新的第一次量化常数 $c_2^{\mathrm{FP8}}$ 和第二次量化常数 $c_1^{\mathrm{FP32}}$（这里选择 8 是出于模型性能考虑）。第二次量化的粒度为 256，即将 256 个 fp32 变成了 fp8，此外还需要存储第二次压缩的 fp32，即
$$\frac{8}{64}+\frac{32}{64\times256}$$
![[Pasted image 20261111112512.png]]

## **Paged optimizers**

使用 NVIDIA 统一内存特性，在 CPU 和 GPU 之间进行**页**传输。当 GPU 内存不足时，将部分状态转移到 **CPU RAM** 中，并在优化器更新步骤需要内存时分页回到 GPU 内存中。

## QLoRA总结

单个线性层的 QLoRA：
![[Pasted image 20261111112705.png]]
**前向公式**
$$Y^{\mathrm{BF16}}=X^{\mathrm{BF16}}\cdot\mathrm{doubleDequant}\left(c_1^{\mathrm{FP32}},c_2^{k\text{-bit}},W^{\mathrm{NF4}}\right)+X^{\mathrm{BF16}}L_1^{\mathrm{BF16}}L_2^{\mathrm{BF16}}$$
- **第一项：冻结底座。** $W$ 常驻 4-bit NF4，计算前用两级量化常数反量化成 BF16，再与输入相乘。
- **第二项：LoRA 旁路。** $L_1$、$L_2$ 是 BF16 的低秩矩阵，只有它们需要梯度。

**doubleDequant 的两层**
![[Pasted image 20261111112843.png]]
$$\mathrm{doubleDequant}\left(c_1^{\mathrm{FP32}},c_2^{k\text{-bit}},W^{\mathrm{NF4}}\right)=\mathrm{dequantize}\left(\mathrm{dequantize}\left(c_1^{\mathrm{FP32}},c_2^{k\text{-bit}}\right),W^{\mathrm{NF4}}\right)$$

内层用 $c_1^{\mathrm{FP32}}$ 把 $c_2$ 还原成每个块的 fp32 量化常数，外层再拿这个常数把 NF4 权重还原成 BF16。多套一层的目的就是不让一堆 fp32 的 block 常数把省下来的显存再吃回去。

**梯度只算 LoRA 的**

参数更新只需要 $\dfrac{\partial E}{\partial L_i}$，不需要 $\dfrac{\partial E}{\partial W}$。但按链式法则求 $\dfrac{\partial E}{\partial L_i}$ 时中间会经过 $W$，所以前向和反向都得把 $W^{\mathrm{NF4}}$ 临时反量化成 $W^{\mathrm{BF16}}$，用完即弃，不会作为参数留下来。

**一句话收尾**

QLoRA 就是「一个存储类型 + 一个计算类型」：底座以 4-bit NF4 常驻显存，参与计算时反量化成 BF16，只有 BF16 的 LoRA 参数回写梯度。

```Python
qlora_config =BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_use_double_quant=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16 # 根据 GPU 支持选择 bf16 或 fp16
)
```
