### 1. PPO 和 GRPO 的区别是什么？
- **PPO (Proximal Policy Optimization，近端策略优化)：**
    - **结构：** 属于经典的 Actor-Critic 架构。训练时通常需要加载 **4 个模型**（Actor 模型、Reference 参考模型、Critic 价值模型、Reward 奖励模型），显存开销非常大。
    - **Critic 的作用：** Critic 模型用来估计状态的价值（Value），从而计算出**优势函数**（Advantage），帮助 Actor 判断生成的动作是“比预期好”还是“比预期差”。
- **GRPO (Group Relative Policy Optimization，群组相对策略优化，DeepSeek 广泛使用)：**
    - **结构：** 属于**无 Critic (Critic-less)** 的方法。它不需要单独训练一个庞大的 Critic 模型来估计基准价值。
    - **核心思想：** 对于同一个输入提示词（Prompt），让 Policy 模型同时生成一组输出（例如 $G$ 个不同的回答），然后直接在这一组输出内部计算奖励的平均值和标准差，通过**组内相对分数**来作为优势（Advantage）进行更新。
    - **最大优势：** 极大地**节省了显存和计算资源**（砍掉了 Critic 模型），在大模型对齐（如 DeepSeekMath / DeepSeek-R1 早期探索）中非常高效。

### 2. PPO 和 DPO 的区别是什么？

- **PPO (在线强化学习，Online RL)：**
    - **特点：** 它是**在线 (Online)** 训练的。在训练过程中，模型需要**实时采样**（Generate）新的文本，并由奖励模型打分。
    - **优点：** 能够探索模型自己生成的、未见过的轨迹，上限高。
    - **缺点：** 训练极不稳定，超参数难调，且需要同时在显存中跑多个大模型（Actor、Critic、Reward、Ref），工程实现极其复杂。
- **DPO (Direct Preference Optimization，直接偏好优化)：**
    - **特点：** 它是**离线 (Offline)** 训练的，属于**监督学习的变体**。它不需要奖励模型（Reward Model），也不需要在训练时实时生成文本。
    - **数据形式：** 依赖**固定好的偏好数据集**（包含 Prompt 以及标明哪个好、哪个差的一对回答：$y_{win}$ 和 $y_{lose}$）。
    - **优点：** 绕过了复杂的强化学习框架（不需要 PPO 的采样和 Critic），直接用**交叉熵损失函数**优化大模型，训练像微调一样稳定且省显存

### 3. PPO 的 Critic Model 的作用是什么？可不可以去掉？

- **作用：**
    - Critic（评论家）在 PPO 中负责学习一个**价值函数**（Value Function），用来预测当前状态下未来能够获得的**累积奖励期望**。
    - 它的存在是为了提供一个**精细的基准（Baseline）**。通过“实际得分减去 Critic 预估的基准分”，算出优势函数（Advantage），从而告诉 Actor 这一步走得究竟是**超预期还是低于预期，减小梯度方差**，让训练更稳定。
- **可不可以去掉？**
    - **在标准 PPO 中不能直接去掉**，否则缺乏可靠的基准，方差会过大导致模型崩塌。
    - **但在某些改进算法中可以去掉或替换：** 例如前面提到的 **GRPO**，它巧妙地用**同组生成结果的均值**替代了 Critic 的基准作用，从而成功去掉了 Critic 模型。

### 4. PPO 的 Reference Model 的作用是什么？
- **作用：**
    - Reference Model（参考模型，通常是 SFT 训练完的基础对齐模型，在训练过程中**参数冻结不更新**）的核心作用是**充当“锚点”或“刹车”**。
- **为什么需要它？**
    - 在 PPO 训练中，由于**奖励模型**（Reward Model）是学出来的，大模型很容易为了“钻奖励的空子”（Reward Hacking）而输出一些莫名其妙但得分很高的诡异文本。
    - 引入 Reference Model 后，我们在计算最终损失时会加入一个 **KL 散度惩罚项 (KL Penalty)**，限制当前被更新的 Actor 模型不要离最初的 SFT 模型偏离太远，防止大模型发生“灾难性遗忘”或语言能力退化（变成胡言乱语）。
