# 2.4.2 数据并行（Data Parallel，DP）

> [!abstract] 一句话
> 每张卡放一份**完整模型**，各吃一个 batch 的不同分片，训练完同步梯度——数据并行靠"多喂数据"提速，不减少单卡显存。

数据并行的前提是先把 `batch-size` 放大：本质是**多个设备分一个 batch 内的数据**。PyTorch 里最直接的实现是 `nn.DataParallel`。

四种并行的定位见 [[2.4.1分布式方法分类]]。

---

## 一、原理：四步循环

![[Pasted image 20261111145933.png]]

*图 1：数据并行——模型复制多份，一个 batch 切成多份，各卡算完再汇总*

| 步骤 | 做什么 | 代价 |
| --- | --- | --- |
| **scatter** | 把一个 batch 切成若干份，分给各卡 | 一次数据搬运 |
| **replicate** | 把模型复制到每张卡 | 每轮开始都要同步模型 |
| **parallel_apply** | 各卡独立前向 + 反向 | 受限于单进程多线程 |
| **gather** | 把各卡输出汇总回主卡 | 结果集中到一个设备 |

---

## 二、PyTorch 实现

### 2.1 核心流程

`nn.DataParallel.forward` 就是上面四步，源码主干如下：

```python
# 摘自 torch.nn.DataParallel.forward
inputs, kwargs = self.scatter(inputs, kwargs, self.device_ids)              # 数据分发
replicas = self.replicate(self.module, self.device_ids[:len(inputs)])       # 模型分发
outputs = self.parallel_apply(replicas, inputs, kwargs)                     # 并行训练
return self.gather(outputs, self.output_device)                             # 结果聚合
```

### 2.2 怎么用

```python
model = torch.nn.DataParallel(model, device_ids=None)
# 如果不指定 device_ids 参数，PyTorch 会自动使用所有可用的 GPU

output.loss.mean().backward()
# 否则 output.loss 会变成多个 GPU 上的 loss 值，不是标量，无法 .backward()
```

两个坑：`device_ids` 不写就默认吃满所有卡；输出要 `.mean()` 才是标量。

### 2.3 transformers 里已经内置

如果使用 transformers，其 `trainer.train()` 里包含了 DataParallel 操作，无需额外代码。

## 三、实测：调用了多卡，但速度没提升

**现象**：确实调用了多 GPU 进行训练，但训练速度没有多大的提升。

**四个原因**：

1. **单进程、多线程**：受 GIL 锁限制，不能充分发挥多卡优势。
2. **负载不均**：由于 DataParallel 的训练策略，会导致**一个主节点占用比其他的节点高很多**。
3. **每轮重同步**：效率低，尤其是模型很大、batch_size 很小的情况，每次训练开始时都要**重新同步模型**。
4. **只能单机**：只适用于**单机训练**，无法支持真正的分布式多节点训练。

> [!important] 官方建议
> 新项目不要再用 `nn.DataParallel`，改用 **DDP**：多进程、无 GIL、支持多机，见 [[2.4.3 分布式数据并行（Distributed Data Parallel，DDP)]]。

---

## 四、什么时候还值得用

- 主要针对**不需要进行模型更新**的场景（因为模型更新后又要重新进行模型分发），例如并行推理；
- 在 RAG 模型中，对大量数据进行向量编码时，可以通过 DP 并行化这个过程，提高效率。

大规模训练里 DP 与 TP、PP 怎么叠加，见 [[2.4.6 Megatron-LM#5.4 PTD-P]]。
