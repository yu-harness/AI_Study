知识蒸馏的是通过从大模型中提取知识，教给小模型，来增强小模型的性能。但是根据 Scaling law，采用小模型的准确度普遍低于大模型，所以知识蒸馏效果比较一般。

- **黑盒蒸馏**：**使用大模型生成数据，通过这些数据去微调更小的模型**，来达到蒸馏的目的。例如[中文基于满血 DeepSeek-R1 蒸馏数据集（Chinese-Data-Distill-From-R1）](https://github.com/YunwenTechnology/Chinese-Data-Distill-From-R1)
![[Pasted image 20261111144924.png]]

**优点：**
- 实现简单，只需大模型生成数据、小模型学习
- 不需要直接访问大模型的参数或中间状态
- 可以生成针对特定任务的专用数据

**缺点：**
- 蒸馏效率低，需要大量样本
- 生成的数据可能包含大模型的偏见或错误
- 无法直接学习大模型内部表示



- **白盒蒸馏**：可以大致分为三种：
    - **Knowledge-based:** 对结果进行蒸馏
	![[Pasted image 20261111145002.png]]
    - **Feature-based:** 对**中间层特征进行蒸馏**,ZeroQuant用的就是中间层特征蒸馏。当教师模型和学生模型采用不同的架构时，选择教师模型中的那些层作为作为激活，以及学生模型中那些层模仿激活是需要考虑的。
	![[Pasted image 20261111145044.png]]
	- **Relation-based：** 蒸馏**样本间的关系信息**（例如，教师模型在处理不同样本时会学到这些样本之间的相似性或距离。）和**结构化的知识**（教师模型的不同层或不同特征之间的关系信息）。例如将教师模型中两层 feature maps 之间的 Gram 矩阵（网络层输出之间的关系）作为知识，或者将样本在教师模型上的特征表示的概率分布（样本之间的关系）作为知识。
	![[Pasted image 20261111145120.png]]


**黑盒蒸馏 vs 白盒蒸馏**

黑盒蒸馏的效率低于白盒蒸馏，可能需要大量的数据进行 SFT 训练，但仍是现实中使用最多的方法，主要原因有下：

1. **实现简单**：黑盒蒸馏不需要访问教师模型的内部结构、参数或中间层输出，只需要能够获取教师模型对输入的响应（输出）即可。这大大降低了实施难度。
2. **适用范围广**：可以应用于任何能提供输出的模型（包括未开源模型），甚至以可以用于 API 形式提供的模型（如 OpenAI 的 GPT 系列或 Claude 等商业模型），无需获取模型权重。
3. **模型异构性支持**：教师模型和学生模型可以完全不同的架构、大小和设计，因为只关注输入-输出对应关系，不需要层级匹配。
4. **数据扩充能力**：可以使用教师模型生成大量无标签数据的标注，创建专门针对特定领域或任务的合成数据集。
5. **隐私保护**：当教师模型包含敏感数据或专有技术时，黑盒蒸馏允许知识转移而不泄露模型内部结构。
6. **部署灵活性**：可以选择性地只蒸馏模型在特定领域的能力，而不是完整复制所有功能。
7. **无需模型权重访问权限**：对于商业模型，往往无法获取完整的模型权重，黑盒蒸馏是唯一可行的知识迁移方案。


知识蒸馏的一些其他考虑：

- 学习的形式：在线学习？离线学习？自蒸馏（即一个模型同时作为教师和学生模型，一种常见的实现方式是教师模型训练整个模型得到输出，而学生模型训练前边一些层后接一个全连接层得到输出）？
- 教师模型和学生模型的关系：学生模型是教师模型的简化版本？量化版本？无关？
- 蒸馏数据集的选择：真实数据集？教师模型生成的假数据集？
