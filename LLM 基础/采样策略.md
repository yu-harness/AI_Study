# 解码策略（采样策略）

先说位置：**解码发生在模型算完之后、下一个词被定下来之前**。模型本身只给出「词表里每个词有多大概率」，把这个分布变成一个具体的词，是解码策略的事。

![[采样策略-解码位置.svg|865]]

*图 1：解码策略的位置——模型算出 logits 之后、序列被延长之前。橙色那段是解码，左边是前向计算。*

图里橙色那段就是本文的全部内容。左边到 logits 为止是模型前向计算，参数固定；右边从解码策略开始是「怎么从分布里挑一个词」，不训练、不改权重，只影响生成结果。

## 0. 主线

模型每一步只输出一个分布 $p(x_t \mid x_{<t})$，即词表里每个词一个概率。**解码策略就是拿到这个分布后怎么选词**：

- 逐步选词：Greedy、Top-K、Top-P，外加调分布形状的 Temperature

- 整句搜索：Beam Search

## 1. Temperature

**它是推理时对打分表做的一次锐化或钝化调节。** 模型每步会输出一组分数（logits），温度就是一个除数：把每个分数除以 T，再交给 softmax 变成概率。

除数小于 1，分数之间的差距被放大，概率更集中；除数大于 1，差距被缩小，概率被摊平。T 恰好等于 1 时什么都不改，那就是模型本来的样子。

名字借自物理：温度高，粒子运动剧烈、状态更混乱；温度低，趋向稳定。挪到采样上就是，T 越高，抽到冷门词的机会越大。

它只改变分布的形状，**不删除任何候选词**，也**不参与训练**——模型权重一点不动，只是推理时多做一次除法。

$$p_i = \text{softmax}(z_i / T)$$

- $T<1$：分布更尖，更确定

- $T>1$：分布更平，更随机

- $T\to 0$：等价于 argmax

- 它只改分布的形状，不砍掉任何词

### 1.1 位置：Linear 之后、Softmax 之前

```
(B,S,d) hidden
   │ Linear            ← 这里没有温度
   ▼
(B,S,V) logits
   │ ÷ T               ← 温度在这里
   ▼
scaled logits
   │ softmax
   ▼
probs
   │ top-k / top-p（可选，也在概率上做）
   │ 采样
   ▼
下一个 token
```

```
logits = lm_head(hidden)      # Linear，无温度
logits = logits / T           # ← 温度加在这一行
probs  = softmax(logits)
```

温度**不参与训练、不改权重**，只是推理时对 logits 做一次除法——这是它和微调最根本的区别。

### 1.2 怎么改变分布

softmax 只认相对差距，除以小于 1 的数放大差值，除以大于 1 的数缩小差值。以 $z=[2,0]$ 为例：

| $T$ | 除以 $T$ 后 | softmax |
| --- | --- | --- |
| 0.5 | `[4, 0]` | `[0.982, 0.018]` — 差距放大 |
| 1.0 | `[2, 0]` | `[0.881, 0.119]` — 原始 |
| 2.0 | `[1, 0]` | `[0.731, 0.269]` — 差距缩小 |
| 10 | `[0.2, 0]` | `[0.550, 0.450]` — 几乎五五开 |

两个端点：$T\to0$ 收敛成 one-hot，$T\to\infty$ 变成均匀分布。**温度不改变谁排第一，只改变第一名领先多少。**

![[采样策略-温度路径对比.svg]]

*图 6：温度对两条解码路径的影响——同一分布下，低温走大概率主干，高温可能拐向次优词。*

### 1.3 三个取值区间与常见取值

| $T$ | 分布 | 效果 |
| --- | --- | --- |
| < 1 | 更尖锐 | 保守、确定、易重复 |
| = 1 | 原始 | 模型本来的样子 |
| > 1 | 更平坦 | 多样、发散、可能胡说 |

| 场景 | $T$ |
| --- | --- |
| 数学 / 代码（要准确） | 0 ~ 0.3 |
| 一般问答 | 0.7 左右 |
| 创意写作 / 头脑风暴 | 1.0 ~ 1.3 |
| 纯随机测试 | 2+ |

### 1.4 两个易混点

**一、只在推理时用，训练永远是 1。** 训练是「对照标准答案算 loss」，不采样，所以没有温度。

**二、不影响 argmax。** 除以正数不改变大小顺序，$z_1>z_2 \iff z_1/T > z_2/T$，所以贪心解码加不加温度结果完全一样；温度只在**采样**时才有意义——它改变的是「抽到第二名的概率」。

```
flowchart LR
    L["logits"] --> A["argmax 贪心"]
    L --> D["÷T → softmax → 采样"]
    A -.->|"T 不影响"| A2["同一个结果"]
    D -.->|"T 影响"| D2["分布形状改变"]
```

## 2. Greedy（argmax）

**Greedy 是最省事的做法：每一步都选当前概率最高的那个词。**选完就往前进一格，不回头看，也不考虑后面的路好不好走。它快、稳、结果可复现，是很多系统的默认档。

打个比方：下山时每步都朝最陡的方向迈一脚。局部看每一步都在下坡，但走到的可能只是一个小山坳，不是谷底。词序生成也是这样，每步都挑最像的词，串起来未必是整句最像的那条。

它平时表现不差，问题在于三处：容易掉进次优路径、容易陷入复读、完全没有随机性。下面分开说。

![[采样策略-贪心分叉.svg|784]]

*图 6：贪心与更优路径的分叉——每步都选局部最陡，走到的是小山坳而不是谷底。*

每步**取概率最大的词**，直到输出 `<eos>`。

它有三个明显的问题：

- 只保证每一步最优，**不保证整句最优**

- 容易复读：重复内容进入上下文后，会让「继续重复」的概率更高，形成正反馈

- 完全确定，没有多样性

**为什么不是全局最优**：后面每一步的概率取决于前面选了什么（条件概率）。

| 路径           | 整句概率                                                |
| ------------ | --------------------------------------------------- |
| 贪心 A→B→C→eos | $0.5\times0.4\times0.4\times0.6=0.048$              |
| 更优 A→C→C→eos | $0.5\times0.3\times0.9\times0.9\approx0.122$（2.5 倍） |

贪心在 t2 因为 $0.4>0.3$ 选了 B，但选 C 之后，模型**对后两步给出的是另一套分布**（那些 0.9 只在”走 C”这条前缀下成立），**贪心看不到这一点**。

## 3. Top-K

**Top-K 的做法很直接：只在概率最高的 K 个词里抽签，其余全部丢掉。** 它治的是「长尾」——词表几万个词，单个概率很低，但数量庞大，加起来仍是可观的一块，放任不管偶尔就会抽到很离谱的词。

丢掉之后有个麻烦：剩下几个词的概率加起来不到 1，不能再当概率用。所以要按比例放大，让它们的和回到 1，这一步叫**重新归一化**。比例关系不变，只是把这一小块重新当成完整的分布。

拿三个候选举例：概率是 0.5、0.3、0.2，取 K = 2 只留前两个，和是 0.8。各自除以 0.8，变成 0.625 和 0.375，谁高谁低没变，总和回到 1。

取概率最高的 K 个词，**重新归一化**后按概率抽样。

- 例：概率 0.5、0.3、0.2，取 K=2，**归一化后**为 $0.5/0.8=0.625$ 和 $0.3/0.8=0.375$

- K 大：多样性高，质量可能下降；K 小：稳，但单一

- K=1 就是 Greedy

- 缺点：K 固定，不看模型有没有把握  有把握时（“中国的首都是”，北京 0.9），K=3 会把上海、南京也放进来 拿不准时，K 又可能砍掉合理的词

![[采样策略-TopK.svg|833]]

*图 2：Top-K 截断与重新归一化——K=3 时砍掉长尾，再按 0.90 的比例把前三名放大回总和为 1。*

## 4. Top-P（核采样）

**Top-P 换了个切法：不按「留几个词」切，按「留多少概率」切。**名字里的「核」（nucleus）指的就是概率最集中的那一块。

做法是把候选按概率从大到小排好，从头开始累加，累到刚好达到 P 就停。这一段前缀就是候选集，然后照 Top-K 那样归一化、抽样。

好处在于候选集大小会自己变。模型很有把握时，第一个词就占了 0.9，累加一步就够，候选集只有 1 个；模型拿不准时，得一路累加六七个才凑够 P，候选集自然变大。同一个阈值，宽严由模型自己的把握程度决定。

常见取值 0.9 到 0.95。设成 1 等于不截断，什么词都留着；设得太小（比如 0.5）就只有一两个词，退化成贪心。

按概率降序累加，取累计概率 $\ge P$ 的**最小集合**，重新归一化后抽样。

按概率降序累加，取累计概率 $\ge P$ 的**最小集合**，重新归一化后抽样。

- 候选集大小自适应：有把握时很小，拿不准时自动变大

- 例：$P=0.9$ 时，“中国的首都是”候选集只有 1 个（北京 0.9）；“今天天气真”（好 .30、不错 .22、热 .15、冷 .12、糟 .08、棒 .06……）候选集是 6 个（累计 0.93）

- 既保留多样性，又避开概率极低的词

## 5. 三者关系

| 控制什么 | 候选集大小 |  |
| --- | --- | --- |
| Temperature | 分布的形状 | 不变 |
| Top-K | 保留几个词 | 固定 |
| Top-P | 保留累计多少概率 | 自适应 |

实际流程：logits → 除以 T → softmax → Top-K / Top-P 截断 → 重新归一化 → 按**概率**抽样。

### 5.1 两个容易漏掉的前提

> **你的问题（整理后）**：用 Top-K / Top-P 要注意两件事：一是必须先按概率排序，二是二者可以同时使用，候选集取较小的那个。

**① 必须先排序。**

Top-K 的”K 个最高”和 Top-P 的”累计概率 ≥ P”都定义在**降序排列**上，没有排序这两件事都没有意义：

- Top-P 必须从大到小累加，否则”累计到 0.9”的集合取决于加的顺序，结果完全不同

- 实践中不必做全排序：Top-K 用堆或 `torch.topk` 取第 K 大的阈值（$O(V\log K)$），Top-P 只要对前若干名做前缀和即可。词表 10 万+、每生成一个 token 都要算一遍，这一步的开销不能忽略

**② 两者可以同时用，取更小的那个集合。**

同时设置 `top_k` 和 `top_p` 时，实际流程是**先 Top-K 截断，再在剩下的 K 个词里做 Top-P**：

```
排序 → 取前 K 个 → 在这 K 个里累加到 P → 重新归一化 → 抽样
```

因为两者都是”保留概率最高的一段前缀”，它们的交集就是**较小的那个集合**：

- $K$ 更紧（比如 K=5、P=0.95）→ 结果就是 5 个词，Top-P 不起作用

- $P$ 更紧（比如 K=50、P=0.3）→ 结果由 Top-P 决定，K 只是个上限

所以”取最少”是**交集**，不是相加，也不是相乘：谁截得更狠听谁的。

补充： - HuggingFace `generate` 默认 `top_k=50, top_p=1.0`；`top_p=1.0` 意为不截断，此时只有 Top-K 生效 - 只有 `top_k=0`（HF 里表示关闭）才是纯 Top-P 采样 - 两者同时开启的好处：Top-K 挡住长尾的极端垃圾词，Top-P 在模型有把握时进一步收紧，避免 Top-K 在”北京 0.9”时还硬塞进 2 个陪跑词

## 6. Beam Search

**Beam Search 把贪心放宽了一点：每一步不只留 1 条路，留 B 条。**B 叫 beam width，就是同时并行的「半成品句子」条数。

每一步做两件事。先扩展：B 条路径各自往后接一个词，每条能接出 V 个（V 是词表大小），一共 B×V 个候选。再剪枝：按「从开头累积到现在」的总概率排序，只留前 B 个，其余丢掉。

关键在排序依据用的是**整句的累计概率**，单步概率不参与。所以某条路这一步暂时落后，只要前面积累得好，仍然能留在 beam 里；反过来，某步突然冒出一个高分词，也不会因为这一步就挤进前 B。

代价是计算量按 B 倍增长：每步要算 B×V 个候选，B 条序列并行解码，显存和时间都线性上涨。

B = 1 就退回贪心；B 越大越接近穷举，但代价越高。它是个预算可调的近似搜索，不保证全局最优。

每步保留 B 条累计概率最高的候选序列，各自向后扩展，再从所有扩展结果里留 top-B，最后取整句概率最高的一条。

每步保留 B 条累计概率最高的候选序列，各自向后扩展，再从所有扩展**结果里留 top-B**，最后取整句概率最高的一条。

$$p(x_1,\dots,x_n)=\prod_t p(x_t\mid x_{<t})$$

实际实现用 log 概率求和（连乘会下溢），并做**长度归一化**，否则句子越长概率越小，会偏爱短句。

例（B=2，只看以 A 开头这一支）：

- t2：保留 A→B（0.20）和 A→C（0.15），贪心在这里就把 C 丢了

- t3：A→B→C 是 0.08，A→C→C 是 0.135，后者反超

- t4：0.048 对 0.122，选 A→C→C→eos

B=1 就是 Greedy，B 越大越接近序列级最优，代价是计算量更大。

**实现上有四件事必须处理。**

- **用 log 概率相加，不用连乘。**只有三步时看不出问题，实际几百个 token，`0.1^100` 会直接下溢成 0，所有候选分数一起归零，比较就没意义了。

- **做长度归一化。**log 概率恒为负，序列越长总和越小，不修正会系统性偏爱短句。常用除以 `L^α`，α 一般取 0.6 到 1.0。

- **遇到 `<eos>` 的序列要移出 beam。**完成的序列放进「已完成」池，空出的位置由其他未完成序列补上，全部结束才停止；粗暴地继续扩展会在终止符后面生成无意义内容。

- **不同 beam 可能扩展出同一串前缀。**需要合并分数或去重，否则 B 个位置会被重复项浪费掉。

**和 Top-K、Top-P 不在一个层面。**Top-K / Top-P 处理的是单个时间步的候选集，结果带随机性；Beam Search 处理的是跨时间步的整句路径，结果是确定的。严格说 Beam 内部也可以对每步分布做 Top-K 截断，用来控制 B×V 的规模，那就是「beam search + 采样」的混合做法。

特点：质量稳定，但保守、缺乏多样性。

## 7. 怎么选

| 场景 | 常用策略 |
| --- | --- |
| 翻译、摘要等有较标准答案的任务 | Beam Search |
| 代码、事实问答、结构化输出 | Greedy 或低温度 |
| 对话、写作、开放式生成 | Top-P（常见 0.9~0.95）+ Temperature（常见 0.7~1.0） |

## 9. Beam Search 的图示解读：每一步都从 B×V 个扩展中保留整句累计概率最高的 B 条前缀

> **你的问题（整理后）**：结合这张示意图，讲解 Beam Search 的搜索过程与关键机制。

这张图是 §6 的图形版：图中 **beam width B = 2**（每层只圈两个节点）。它用抽象字母代替概率数值，便于关注搜索结构。

> 原图对应 HTML 版里的 SVG：Beam Search 搜索树（B=2，三个时间步）。

### 9.1 逐帧读图

图中有三列，对应三个时间步，每列都是一次「扩展 → 剪枝」：

| 时间步 | 扩展出多少候选 | 剪枝后保留 | 含义 |
| --- | --- | --- | --- |
| t1 | 5 个（A/B/C/D/E） | **A、C**（蓝圈） | 首词取概率前 2 |
| t2 | 2×5 = 10 个 | **AB、CE**（B 与 E 被加粗圈出） | 两条前缀各自扩展，10 个里留累计概率前 2 |
| t3 | 2×5 = 10 个 | **ABD、CED**（D 被圈出） | 同上，最后输出整句最优 |

图中候选 **2×5=10 个、留 2 个** 的点很关键：每一步实际计算量是 $B \times V$，剪枝后才回到 $B$。因此 Beam Search 的代价是 Greedy 的 $B$ 倍（$B$ 条序列并行解码），并非一次性搜索整句。

### 9.2 剪枝比的是整句概率，不是单步概率

这是理解 Beam Search 的关键，也是它和 Greedy 的唯一区别。

t2 那一步，从 A 扩展出的 A→B 与从 C 扩展出的 C→E 被保留，前提是：

$$\underbrace{p(\text{A})}_{\text{前一层的分}}\cdot p(\text{B}\mid\text{A}) \;>\; \ldots$$

**比较对象是“从 `<bos>` 到当前词”的累计概率**，不是当前这一步的条件概率。图中每个候选旁边的隐含分数，就是这样连乘出来的值。

笔记 §6 的数值例子正对应这一点：

- t2：A→B 是 $0.5\times0.4=0.20$，A→C 是 $0.5\times0.3=0.15$ → **Greedy 在这里把 C 永久丢掉**

- t3：A→B→C 只有 $0.08$，A→C→C 是 $0.135$ → **保留 C 后，它在下一步反超**

- t4：$0.048$ 对比 $0.122$ → 最终选 A→C→C→eos

图里 t2 保留的 AB 和 CE 分别来自两条不同的前缀。**Beam 的价值在于让“暂时落后但后续概率高”的分支仍能参与比较。**

### 9.3 B=1 与 B=∞ 两个端点

- **B=1**：等价于 Greedy，每层只有一个候选，退化回逐步贪心

- **B=V^L**：等价于穷举，得到真正的全局最优，但不可行

所以 Beam Search 是**在 Greedy 与穷举之间调整预算**：B 越大越接近序列级最优，代价是显存与计算线性上涨。它是**启发式近似**，不保证全局最优，只在每一步对当前 $B$ 条前缀做局部最优剪枝。

### 9.4 实现必须处理的四件事

1. **用 log 概率相加，不用连乘** 图中只有三步，看不出问题；实际几百个 token，$0.1^{100}$ 会直接下溢成 0，所有候选分数一起归零，比较失去意义。实现里改为 $\sum \log p$。

2. **长度归一化** $\log p$ 恒为负，序列越长总和越小，不修正会**系统性偏爱短句**（模型学会输出“我不知道”）。常用除以长度 $L^\alpha$（$\alpha$ 通常 0.6~1.0）。

3. **遇到 `<eos>` 的序列要移出 beam** 完成序列进入「已完成」池，beam 空出的位置由其他未完成序列补上；所有 beam 都结束时停止。若粗暴继续扩展已完成的序列，会在 `<eos>` 后面生成无意义内容。

4. **不同 beam 可能扩展出相同前缀** t2 图中 A 与 C 的子节点集合一样，因此容易出现重复；实际词表上两条 beam 完全可能同时扩展出同一串 token，需要合并分数或去重，否则 $B$ 个位置会被浪费。

### 9.5 和 Top-K / Top-P 的关系

两者属于不同层面：

|  | 处理对象 | 随机性 |
| --- | --- | --- |
| Top-K / Top-P | 单个时间步的**候选集** | 有（按概率抽样） |
| Beam Search | 跨时间步的**整句路径** | 无（确定性） |

严格说，Beam Search 内部也可以先对每步的分布做 Top-K 截断来控制 $B\times V$ 的规模（这就是「beam search + 采样」的混合做法），但标准 Beam Search 本身是确定性的、只追求概率最大。因此笔记 §7 把它留给翻译、摘要这类有较标准答案的任务，开放式对话仍用采样。

### 9.6 一句话

**Beam Search 把“每一步只留 1 个”放宽成“每一步留 B 个”，用累计概率而非单步概率做剪枝，因此能在若干步之后让暂时落后的分支反超；它是预算可调的启发式近似，必须配 log 概率、长度归一化与 `<eos>` 处理才能实际运行。**
