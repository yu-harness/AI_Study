# 学习率调度（Warmup / Cosine / Linear / WSD）

## 一句话

**学习率不是一个常数，而是一条随训练步数变化的曲线；warmup 是这条曲线的前半段——先升上去，再降下来。**

## 为什么不能全程用同一个学习率

三个矛盾同时存在：

| 阶段     | 需要的学习率   | 原因                              |
| ------ | -------- | ------------------------------- |
| 最开始几百步 | **很小**   | 参数随机初始化、Adam 二阶矩估计还没稳，此时梯度方向不可靠 |
| 中期     | **最大**   | 方向稳定了，大步走才有效率                   |
| 后期     | **逐渐变小** | 接近极小值时要细调，大步会反复跨过谷底             |

所以标准做法是「**warmup 升 → 峰值平台 → 衰减到接近 0**」。

## 四种常见曲线

设总步数 $T$、峰值学习率 $\eta_{\max}$、warmup 步数 $T_w$。

| 曲线 | 形状 | 公式（衰减段） | 用在哪 |
| --- | --- | --- | --- |
| **Constant** | 全程不变 | $\eta_t=\eta_{\max}$ | 短训练、调试、小数据微调 |
| **Linear** | 线性降到 0 | $\eta_t=\eta_{\max}\left(1-\frac{t}{T}\right)$ | 简单可控，常见于早期 BERT 类 |
| **Cosine** | 余弦曲线缓降 | $\eta_t=\eta_{\min}+\frac{1}{2}(\eta_{\max}-\eta_{\min})\left(1+\cos\frac{\pi t}{T}\right)$ | 大模型主流（GPT、Llama 早期） |
| **WSD** | 平台 + 末段急降 | 前段恒定 $\eta_{\max}$，最后 10%–20% 快速衰减 | Llama 3 之后的常见选择，便于中途延长训练 |

warmup 段统一是线性上升：

$$\eta_t=\eta_{\max}\cdot\frac{t}{T_w},\qquad 0\le t\le T_w$$

## Warmup 具体在防什么

**防早期的大梯度把参数带坏。** 反向传播的梯度取决于当前参数，参数越离谱、梯度越极端；一上来就用 $\eta_{\max}$，等于在"最不准的方向上"迈最大的一步，很容易进入 loss 长期降不下来的区域。

**配合 Adam 的偏差修正。** 二阶矩 $s_t$ 从 0 起步，前几步的估计严重偏小，除下来步长会异常大；warmup 把这段时间的学习率压住，等到 $s_t$ 估准了再放开。

**稳定混合精度训练。** fp16 下大梯度更容易溢出成 inf；warmup 显著降低前几百步出现 NaN 的概率。

## 比例怎么定

`warmup_ratio` 指 warmup 占总步数的比例，常见 1%–10%：

| 场景 | 典型比例 | 说明 |
| --- | --- | --- |
| 全参预训练 | 0.5%–2% | 总步数几十万，几千步 warmup 足够 |
| LoRA / SFT | 3%–10% | 总步数少（几千步），比例要大些才有实际效果 |
| batch 很大 | 取偏大 | 每步梯度更稳但更"冲"，需要更长缓冲 |
| 学习率偏大 | 取偏大 | 峰值越高，前期越需要缓冲 |

**判断标准**：看前 5% 步数内 loss 是否平稳下降。若一开场就抖或跳高，说明 warmup 太短或峰值太高；若 loss 前几百步几乎不动，说明 warmup 过长，浪费步数。

## 一个具体例子

设在 3000 步上微调，`lr=5e-5`、`warmup_ratio=0.1`：

| 步数区间 | 学习率 |
| --- | --- |
| 1 → 300 | 从 0 线性升到 $5\times10^{-5}$ |
| 301 → 3000 | 余弦衰减，逐步逼近 0 |

也就是 $T_w=300$，第 150 步时学习率约为 $2.5\times10^{-5}$，正好是峰值的一半。

## 代码

```python
from transformers import get_cosine_schedule_with_warmup

scheduler = get_cosine_schedule_with_warmup(
    optimizer,
    num_warmup_steps=int(0.1 * total_steps),   # 10% 用于 warmup
    num_training_steps=total_steps,
)

for step, batch in enumerate(loader):
    loss.backward()
    clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()
    scheduler.step()      # 每步都要推进，否则学习率停在初值
    optimizer.zero_grad()
```

两个易错点：**`scheduler.step()` 必须在 `optimizer.step()` 之后**；**梯度累积时也按真实步数推进**，不能每个 micro-batch 都推进一次。

## 和相邻概念的关系

| 概念 | 管什么 |
| --- | --- |
| 学习率调度 | 每步用多大的 $\eta$ |
| warmup | 调度曲线的前段：从 0 升到峰值 |
| 梯度裁剪 | 单步梯度太大时缩短步长，与调度互不替代 |
| 梯度累积 | 显存不够时攒几批再更新 |
| 权重衰减 | 每步把权重往回拽，防过拟合 |

一句话区分：**调度管"步长随时间怎么变"，裁剪管"这一步会不会太大"，两者一个宏观一个微观。**

## 面试可能的问法

**Q：为什么需要 warmup？**
训练初期参数随机、Adam 二阶矩估计偏小，梯度方向与步长都不可靠；直接上峰值学习率容易一步走坏。warmup 把前几百步的学习率压小，等估计稳定后再放开。

**Q：warmup 比例怎么选？**
按总步数与稳定性定：全参预训练 0.5%–2%，微调 3%–10%；batch 或峰值学习率越大，比例越偏大。判断依据是前 5% 步数内 loss 是否平稳。

**Q：Cosine 和 WSD 有什么区别？**
Cosine 全程平滑衰减到接近 0；WSD 先保持恒定、最后一段才急降，好处是可以在平台期随时截断或延长训练，不必预先定死总步数。

**Q：warmup 太长有什么坏处？**
前期学习率被压得很低，等价于浪费训练步数；短训练任务里（比如几百步的 SFT）过长的 warmup 会明显拉低最终效果。
