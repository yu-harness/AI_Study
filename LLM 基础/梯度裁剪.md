# 梯度裁剪（Gradient Clipping）

## 一句话

**更新参数之前，先量一下这组梯度有多"长"；超过阈值就按比例缩短，方向不变。**

梯度裁剪只改步长，不改方向。

## 为什么需要它

反向传播时，梯度是逐层连乘出来的。一旦某几步的数值偏大，乘积会指数放大：

| 场景 | 为什么会炸 |
| --- | --- |
| RNN / LSTM 长序列 | 同一组权重沿时间步反复相乘，$T$ 步后 $w^T$ 失控 |
| 深层 Transformer 早期 | 初始化不当，浅层梯度还没稳定，反向信号被逐层放大 |
| 长上下文 + 注意力 | $S\times S$ 的分数矩阵里出现极端值，softmax 与梯度同时爆 |
| 脏数据 / 异常样本 | 一条超长或格式错误的样本，能让单步 loss 突然飙升（loss spike） |
| 多智能体长轨迹 | 一条轨迹几百步，中间任何一步异常都会累积成超大梯度 |

典型表现：**loss 曲线突然跳高、甚至变成 NaN，之后再也降不下来**——因为权重已经被一步更新到数值不可恢复的区域。

## 两种做法

### 1. 按值裁剪（clip by value）

把每个梯度分量挤到 $[-c, c]$ 区间：

$$g_i \leftarrow \max(-c,\ \min(c,\ g_i))$$

逐元素独立处理，会**改变方向**（把大的分量压扁，小的不动），实践中用得少。

### 2. 按范数裁剪（clip by norm，最常用）

先算整组梯度的全局范数：

$$\|g\|_2=\sqrt{\sum_i g_i^2}$$

若超过阈值 $\theta$，整组按同一比例缩放：

$$g \leftarrow g \cdot \frac{\theta}{\|g\|_2}$$

若没超过，原样不动。因为乘的是同一个标量，**方向完全不变，只是步子变短**。

PyTorch 的 `clip_grad_norm_` 默认就是这个，阈值通常 `max_norm=1.0`。

## 一个算例

设梯度向量 $g=[3, 4]$，阈值 $\theta=1.0$：

| 步骤 | 计算 | 结果 |
| --- | --- | --- |
| 求范数 | $\sqrt{3^2+4^2}$ | 5.0 |
| 判断 | $5.0>1.0$ | 需要裁剪 |
| 缩放系数 | $1.0/5.0$ | 0.2 |
| 得新梯度 | $[3,4]\times0.2$ | $[0.6,\ 0.8]$ |

方向仍是"右上 53°"，长度从 5 变 1。若梯度是 $[0.3,0.4]$（范数 0.5），低于阈值，就保持原样。

## 代码位置很关键

```python
loss.backward()                       # ① 先算出梯度

torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # ② 裁剪

optimizer.step()                      # ③ 再更新
optimizer.zero_grad()
```

三条规矩：

1. **必须在 `backward()` 之后、`step()` 之前**。放在 `backward` 前裁剪的是上一次的旧梯度，等于没裁。
2. **多卡/梯度累积时只裁一次**，放在 `optimizer.step()` 之前那一步，而不是每个 micro-batch 都裁。
3. **混合精度下要先反缩放**（`scaler.unscale_(optimizer)`）再裁剪，否则裁的是放大了 $2^{16}$ 倍的梯度，阈值完全失真：

```python
scaler.scale(loss).backward()
scaler.unscale_(optimizer)            # 先把梯度还原成真实量级
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
scaler.step(optimizer)
scaler.update()
```

## 阈值怎么定

| 做法 | 说明 |
| --- | --- |
| 默认 1.0 | 大多数 LLM 训练的直接选择（GPT-2、Llama 系列都用 1.0） |
| 0.5 更严 | 数据质量差、loss spike 频繁时下调，牺牲少量有效更新换稳定 |
| 观察再定 | 训练日志里打印 `grad_norm`，看正常步的分布，阈值取"正常上限的 2–3 倍" |

判断依据是**裁剪触发频率**：如果几乎每步都在裁，说明阈值太低，模型被绑住走不动；如果从不触发，说明阈值形同虚设。

## 它解决什么、不解决什么

| 问题 | 梯度裁剪管用吗 |
| --- | --- |
| 梯度爆炸（loss 跳高、NaN） | ✅ 直接对症 |
| 梯度消失（浅层学不动） | ❌ 无效，那要靠残差连接、归一化、更好的初始化 |
| loss spike 的根因 | ❌ 只是兜底，真正该查数据与学习率 |
| 学习率过大导致的震荡 | 部分有用，但调学习率更直接 |

还有一层容易被忽略的代价：**梯度裁剪会掩盖 bug**。如果训练一直靠裁剪维持，说明本来就有异常样本或数值问题，稳定只是被"压"出来的。所以看到裁剪频繁触发，第一反应应该是查数据，而不是调阈值。

## 和相邻技术的关系

| 技术 | 解决的问题 |
| --- | --- |
| 梯度裁剪 | 单步梯度太大 → 限制步长 |
| warmup | 训练早期参数离最优很远 → 先小步后大步 |
| 梯度累积 | 显存不够 → 多批攒一次更新 |
| loss scaling | fp16 下小梯度下溢成 0 → 放大后再缩回 |
| 权重衰减 | 权重长太大 → 每步往回拽 |

这五件事互不替代：**裁剪管"爆炸"，loss scaling 管"下溢"，warmup 管"起步"，累积管"显存"，衰减管"过拟合"**。

## 面试三问

**Q1：梯度裁剪和梯度消失是一回事吗？**
不是。裁剪针对梯度太大（爆炸），梯度消失是梯度趋近 0、浅层几乎不更新，要用残差、归一化、合适初始化解决。

**Q2：为什么按范数裁剪不改方向，按值裁剪会改？**
按范数是整组乘同一个标量 $\theta/\|g\|$，向量方向不变；按值裁剪对每个分量单独设上下界，大的被压扁小的不变，向量方向就偏了。

**Q3：混合精度训练时为什么先 unscale 再裁剪？**
`scaler` 为了让 fp16 梯度不下溢，把 loss 放大了 $2^{16}$ 倍，梯度同比例放大。不先还原就裁剪，等于拿放大后的量去比阈值，几乎每步都会触发，正确梯度被压成极小的值。
