# 大模型重点基础 习题简答

## 一、预训练、SFT 与 Transformer 架构

### 1.【面试高频】大模型预训练和 SFT 的任务、数据、Loss 有什么区别？

**简答**：两者通常都采用自回归语言模型的 next-token cross entropy：

$$
L=-\sum_t m_t\log p_\theta(x_t\mid x_{<t})
$$

区别主要在数据和 loss mask：预训练使用大规模通用语料，通常预测几乎所有有效 token；SFT 使用「指令—回答」数据，常只对 assistant 回答部分计算损失，prompt 部分只作为条件。具体是否屏蔽 prompt 取决于训练模板和实现。

**追问**：SFT 时为什么经常不对用户问题计算 Loss？

**答**：目标是学习「给定指令后如何回答」，并非让模型复述用户输入；屏蔽 prompt 还可避免不同提示模板占用过多训练权重。

**追问**：训练时标签为什么常写成输入右移一位？

**答**：位置 $t$ 的输出用于预测位置 $t+1$ 的 token。工程上常通过对 logits 和 labels 做错位切片实现。

---

### 2.【面试高频】Encoder-Decoder 与 Decoder-Only 有什么区别？

**简答**：Encoder-Decoder 先用 Encoder 双向编码输入，再由 Decoder 使用因果自注意力和 Cross-Attention 生成输出；Decoder-Only 只使用带因果 mask 的自注意力，把指令、上下文和回答拼成一个序列统一建模。

**追问**：Decoder-Only 就等于把 Encoder-Decoder 的 Decoder 原样拿出来吗？

**答**：不完全是。它在结构思想上接近「去掉 Cross-Attention 的 Decoder」，但现代 Decoder-Only 模型在归一化、激活函数、位置编码和 FFN 结构上通常有自己的设计。

**追问**：为什么生成式大模型普遍偏向 Decoder-Only？

**答**：训练目标统一、架构简单、数据可直接做 next-token prediction，并且参数都服务于生成；但在特定条件生成任务中 Encoder-Decoder 仍可能更高效。

---

### 3.【面试高频】一个 Decoder-Only Transformer Block 通常包含哪些部分？

**简答**：通常包含归一化、带因果 mask 的多头自注意力、残差连接、第二次归一化、前馈网络和第二个残差连接。现代大模型常使用 Pre-Norm：

```text
x = x + Attention(Norm(x))
x = x + FFN(Norm(x))
```

**追问**：Pre-Norm 与 Post-Norm 的主要区别是什么？

**答**：Pre-Norm 在子层前归一化，梯度可沿残差主干更稳定传播，深层训练通常更容易；Post-Norm 在残差相加后归一化，原始 Transformer 使用这种形式，但深层时更依赖初始化和训练技巧。

---

### 4.【手算高频】FFN 的张量形状怎样变化？

**简答**：输入通常为 `[B,L,D]`，逐 token 执行相同的两层或门控 MLP：

```text
[B,L,D] -> [B,L,D_ff] -> [B,L,D]
```

实现时也可暂时展平为 `[B*L,D]`。$D_{ff}$ 通常大于 $D$，扩张倍数由模型设计决定，并不固定为 2 倍。

**追问**：FFN 会混合不同 token 的信息吗？

**答**：不会。FFN 只在每个 token 的通道维度上独立变换；token 之间的信息交互主要发生在 Attention 中。

---

### 5.【面试高频】Self-Attention 和 Cross-Attention 的区别是什么？

**简答**：Self-Attention 的 Q、K、V 来自同一序列；Cross-Attention 的 Q 来自当前解码序列，K、V 来自另一个序列或模态，例如 Encoder 输出或视觉特征。

**追问**：Cross-Attention 的分数矩阵形状是什么？

**答**：若 Query 长度为 $L_q$，Key 长度为 $L_k$，则分数形状为 `[B,H,L_q,L_k]`，不要求两个长度相同。

---

## 二、MHA、Mask 与手撕代码

### 6.【面试高频】Scaled Dot-Product Attention 为什么除以 $\sqrt{d_k}$？

**简答**：若 Q、K 各维独立、均值为 0、方差约为 1，则点积 $q\cdot k$ 的方差约为 $d_k$。除以 $\sqrt{d_k}$ 后，分数方差回到常数量级，避免 softmax 过早饱和、梯度变小。

**追问**：除以 $d_k$ 可以吗？

**答**：会缩放过强，使注意力分布过平。标准推导对应的是标准差 $\sqrt{d_k}$，并非方差 $d_k$。

---

### 7.【手撕高频】MHA 的完整形状变化是什么？

**简答**：设输入 `X=[B,L,D]`，头数为 $H$，每头维度 $D_h=D/H$：

```text
Q/K/V: [B,L,D]
reshape: [B,L,H,Dh]
transpose: [B,H,L,Dh]
score: [B,H,Lq,Lk]
head output: [B,H,Lq,Dh]
concat: [B,Lq,D]
output projection: [B,Lq,D]
```

**追问**：为什么 $D$ 必须能被 $H$ 整除？

**答**：常见实现把通道平均分给各头；若不能整除，就需要不等宽头或额外投影设计，标准高效算子通常不支持。

---

### 8.【代码审查高频】分头后应该除以 $\sqrt{\text{embed\_size}}$ 还是 $\sqrt{\text{head\_dim}}$？

**简答**：应该除以 $\sqrt{\text{head\_dim}}$。每个头单独计算点积，参与求和的是该头的 $D_h$ 个维度。使用 $\sqrt{\text{embed\_size}}$ 会让头数越多时缩放越强，改变注意力温度。

**追问**：这个错误一定会报运行时异常吗？

**答**：不会，维度和代码都能运行，但优化行为会发生变化，因此属于「结果可能不对」的隐蔽错误。

---

### 9.【面试高频】Causal Mask、Padding Mask、Attention Mask 分别是什么？

**简答**：

- Causal Mask：屏蔽未来 token，保证自回归条件成立。
- Padding Mask：屏蔽补齐位置。
- Attention Mask：工程中的统称，可能由前两者及业务约束组合而成。

Decoder-Only 训练通常同时需要因果约束和有效 token 约束。

**追问**：为什么 mask 要在 softmax 前加入？

**答**：把非法分数设为极小值后，softmax 概率自然接近 0，剩余合法位置仍保持归一化。

**追问**：FP16 中直接写 `-1e20` 有什么风险？

**答**：可能溢出为 `-inf`；通常可使用框架提供的 mask 算子，或使用与 dtype 匹配的最小有限值。全行都被 mask 时还要避免 softmax 产生 NaN。

---

### 10.【手撕高频】写 MHA 时最容易出现哪些错误？

**简答**：

1. Q、K、V 的序列长度或维度混淆。
2. 缩放因子误用 $\sqrt{D}$，正确写法是 $\sqrt{D_h}$。
3. softmax 维度写错，应沿 Key 长度维。
4. mask 形状不能广播到 `[B,H,Lq,Lk]`。
5. `permute` 后直接 `view`，未处理非连续内存。
6. 忘记最终输出投影 $W_O$。

**追问**：为什么多头拼接后还需要 $W_O$？

**答**：拼接只是把各头放回通道维，$W_O$ 用于重新混合各头信息，并把输出映射到后续残差所需的模型空间。

---

### 11.【面试高频】在 $D$ 不变时，MHA 参数量会随头数增加吗？

**简答**：若 Q、K、V、O 都是 $D\to D$ 的线性层，忽略 bias，参数量约为：

$$
3D^2+D^2=4D^2
$$

只改变头数、保持 $D$ 不变，参数量基本不变；改变的是每头维度和计算组织方式。

**追问**：头数越多一定越好吗？

**答**：不一定。头过多会使单头维度过小，可能削弱每头表达能力，还会增加调度开销。

---

### 12.【面试高频】为什么 `permute` 后常写 `.contiguous().view(...)`？

**简答**：`permute` 改变 stride，不保证底层内存连续；`view` 要求兼容的内存布局。`contiguous()` 重新整理内存后再 `view` 最稳妥。`reshape` 在必要时会自动复制，但要意识到额外开销。

**追问**：这个问题为什么常在 MHA 代码里出现？

**答**：MHA 频繁在 `[B,L,H,Dh]` 与 `[B,H,L,Dh]` 之间转置，拼接前后都涉及维度重排。

---

## 三、KV Cache、MQA/GQA、FlashAttention 与 PagedAttention

### 13.【面试高频】KV Cache 缓存的是什么？为什么只缓存 K、V，不缓存 Q？

**简答**：在自回归解码中，历史 token 在每一层产生的 K、V 后续会被新 token 反复使用，因此缓存它们可避免重复计算。Q 只用于当前查询位置，下一步会产生新的 Q，旧 Q 通常不再需要。

**追问**：KV Cache 是跨层共享的吗？

**答**：不是。每个 Transformer 层都有自己的 K、V 投影和缓存。

**追问**：训练时通常使用 KV Cache 吗？

**答**：标准并行训练通常不使用，因为整段序列一次前向即可完成；KV Cache 主要用于逐 token 自回归推理。

---

### 14.【面试高频】Prefill 和 Decode 阶段有什么区别？

**简答**：

- Prefill：一次处理完整 prompt，生成每层 KV Cache，矩阵规模大，并行度高，通常更偏计算密集。
- Decode：每步只输入一个或少量新 token，读取大量历史 KV Cache，矩阵较小，常受显存带宽和调度影响。

**追问**：为什么增加并发请求有时能提高 Decode 吞吐？

**答**：单请求 decode 的矩阵太小，GPU 利用率低；连续批处理可把多个请求的新 token 合并计算，提高算子利用率，但会增加 KV Cache 占用和排队延迟。

---

### 15.【显存估算】KV Cache 大小怎样计算？

**简答**：不考虑并行切分和内存填充开销时：

$$
\mathrm{Memory}_{KV}\approx 2\times N_{layer}\times B\times L\times N_{kv\_head}\times D_h\times \mathrm{Bytes}
$$

前面的 2 表示 K 和 V。MHA 中 $N_{kv\_head}=N_{head}$，GQA 中更少，MQA 中通常为 1。

**追问**：40 层、8 个 KV 头、head_dim=128、长度 4096、batch=1、BF16，大约多大？

**答**：约 $2\times40\times8\times4096\times128\times2$ 字节，即约 640 MiB，尚未计入内存填充、分页和框架开销。

**追问**：上下文长度翻倍，KV Cache 怎样变化？

**答**：近似线性翻倍；若同时提高并发 batch，也会再次线性增长。

---

### 16.【面试高频】MHA、GQA、MQA 的区别是什么？

**简答**：

- MHA：每个 Query 头都有独立 K、V 头。
- GQA：若干 Query 头共享一组 K、V 头。
- MQA：所有 Query 头共享同一组 K、V。

从 MHA 到 GQA、MQA，KV Cache 和读取带宽逐步下降，解码更快，但共享过强可能带来一定质量损失。

**追问**：GQA 为什么常被认为是折中方案？

**答**：它保留多个 KV 组，比 MQA 有更强表达能力，同时又比 MHA 显著减少 KV Cache。

---

### 17.【面试高频】FlashAttention 优化了什么？它是近似 Attention 吗？

**简答**：FlashAttention 是 IO-aware 的精确 Attention 算法，通过分块计算和在线 softmax，避免把完整 $L\times L$ 注意力矩阵频繁写入显存，减少 HBM 读写和中间激活占用。它属于精确算法，数学结果在浮点误差范围内与标准 Attention 等价。

**追问**：FlashAttention 和 KV Cache 是同一类优化吗？

**答**：不是。FlashAttention 优化单次注意力计算和内存访问；KV Cache 避免自回归解码时重复计算历史 K、V。

---

### 18.【面试高频】PagedAttention 解决什么问题？

**简答**：PagedAttention 借鉴虚拟内存分页，把每个请求的 KV Cache 划分为固定大小 block，并通过映射表使用非连续物理显存。它减少连续大块预留、内存碎片和扩容复制，并支持多个候选输出共享公共前缀 block。

**追问**：PagedAttention 会减少理论 KV Cache 字节数吗？

**答**：通常不会改变单 token K、V 的理论大小，主要减少碎片和过度预留，提高可用显存利用率与并发能力。

**追问**：它与 FlashAttention 的核心区别是什么？

**答**：PagedAttention 重点是推理服务中的 KV Cache 内存管理；FlashAttention 重点是 Attention 算子的计算和 IO。

---

## 四、浮点精度、显存估算与 LoRA

### 19.【面试高频】FP32、FP16、BF16 的区别是什么？

**简答**：FP32 为 4 字节，FP16 和 BF16 为 2 字节。BF16 保留与 FP32 相同数量的指数位，因此动态范围大、较不易溢出，但尾数位少、精度低；FP16 尾数精度高于 BF16，但指数范围更小，更依赖 loss scaling。

**追问**：BF16 为什么通常不需要像 FP16 那样强依赖 GradScaler？

**答**：BF16 动态范围接近 FP32，梯度上溢或下溢风险更低；但它仍有较低尾数精度，并不代表所有计算都不需要 FP32 累加或数值保护。

---

### 20.【显存估算高频】14B 模型全参数训练大约需要多少显存？

**简答**：先看组成，不背固定数字。以常见混合精度 AdamW 为例，每参数可能包含：FP16/BF16 权重 2B、梯度 2B、FP32 master weight 4B、Adam 一阶矩 4B、二阶矩 4B，共约 16B/参数。

$$
14\,\mathrm{B}\times16\,\mathrm{Bytes}\approx224\,\mathrm{GB}
$$

这还不含激活、临时张量、通信 buffer 和碎片。若实现不保留 FP32 master weight，参数状态可能约 12B/参数；实际值依框架、精度和并行策略而变。

**追问**：为什么不能只按「参数量 × 2 字节」估算训练显存？

**答**：那只计算了低精度权重，没有计算梯度、优化器状态、激活和临时工作区。

---

### 21.【显存估算高频】14B 模型做 FP16 LoRA，显存下限大约是多少？

**简答**：仅加载 FP16 基座权重就约为：

$$
14\,\mathrm{B}\times2\,\mathrm{Bytes}\approx28\,\mathrm{GB}
$$

LoRA 参数、梯度和优化器状态相对较小，但训练仍要保存激活，所以实际通常明显高于 28GB。若使用 4-bit QLoRA，基座权重理论原始大小约 7GB，再加量化元数据、LoRA 状态、激活和框架开销。

**追问**：LoRA 是否会给冻结的基座权重保存 `.grad`？

**答**：正常冻结时不会。基座参数 `requires_grad=False`，不保存其参数梯度；但反向传播仍需计算经过基座算子的激活梯度，以便更新 LoRA 分支。

---

### 22.【手撕高频】LoRA 的公式和矩阵形状是什么？

**简答**：对原权重 $W\in\mathbb{R}^{d_{out}\times d_{in}}$，只学习低秩增量：

$$
W'=W+\frac{\alpha}{r}BA
$$

其中 $A\in\mathbb{R}^{r\times d_{in}}$，$B\in\mathbb{R}^{d_{out}\times r}$，秩 $r$ 远小于输入、输出维度。输入输出维度不变。

**追问**：输入 128、输出 1024、rank=8 时，A、B 形状是什么？

**答**：$A=[8,128]$，$B=[1024,8]$，$BA=[1024,128]$，与原权重一致。

**追问**：LoRA 新增参数量是多少？

**答**：$r(d_{in}+d_{out})$，远小于全量参数 $d_{in}\times d_{out}$。

---

### 23.【面试高频】LoRA 为什么常把一个矩阵随机初始化、另一个初始化为 0？

**简答**：常见做法是 A 随机小值、B 为 0，使初始 $BA=0$，模型一开始与原模型完全一致；同时 B 的首步梯度依赖 A，因此可以立即更新，随后 A 也会获得有效梯度。

**追问**：A、B 都初始化为 0 可以吗？

**答**：不可以。此时 $\partial L/\partial A$ 含 B，$\partial L/\partial B$ 含 A，二者首步都为 0，训练无法启动。

**追问**：A 为 0、B 随机可以吗？

**答**：数学上也能启动，此时 A 先获得梯度；但主流实现通常采用 A 随机、B 为 0 的约定。

---

### 24.【面试高频】哪些层适合加 LoRA？

**简答**：常见目标包括 Attention 的 `q_proj/k_proj/v_proj/o_proj`，以及 FFN 的 `up_proj/down_proj/gate_proj`。只加 Q、V 参数更少；覆盖 Attention 和 FFN 通常容量更强，但显存、训练时间和过拟合风险也增加。

**追问**：LoRA rank 越大越好吗？

**答**：不一定。rank 增大提高可学习容量，也增加参数、通信和过拟合风险；应根据任务难度、数据量和目标层调节。

**追问**：`alpha` 起什么作用？

**答**：通过 $\alpha/r$ 缩放低秩更新，控制 LoRA 分支相对基座权重的更新幅度。

---

### 25.【面试高频】LoRA 和 Adapter 有什么区别？

**简答**：LoRA 对已有线性层的权重更新做低秩重参数化，训练后可把增量合并进原权重，通常不增加推理分支；Adapter 在网络中插入新的瓶颈模块，结构更直观，但未融合时会增加额外前向计算和延迟。

**追问**：LoRA 合并后还能方便切换多个任务吗？

**答**：物理合并后不方便；服务多个任务时通常保留基座权重，按请求动态挂载不同 LoRA adapter。

---

### 26.【项目追问】大模型训练有哪些省显存方法？分别省什么？

**简答**：

- 混合精度：减少权重、激活和部分通信字节。
- LoRA/QLoRA：减少可训练参数、梯度和优化器状态。
- Gradient Checkpointing：少存激活，反向时重算，用计算换显存。
- ZeRO/FSDP：跨 GPU 切分优化器状态、梯度和参数。
- CPU/NVMe Offload：把状态移到更慢的存储，用带宽换显存。
- FlashAttention：减少注意力中间矩阵和 IO。
- 缩短序列、减小 micro batch：直接降低激活与注意力开销。

**追问**：Gradient Checkpointing 会减少参数和优化器显存吗？

**答**：不会，主要减少激活显存，并增加重计算时间。

---

## 五、位置编码与长度外推

### 27.【面试高频】为什么 Self-Attention 需要位置编码？

**简答**：不加入位置信息时，Self-Attention 对输入 token 的排列近似置换等变，无法仅凭内容区分先后顺序。位置编码把顺序信息注入表示或注意力分数。

**追问**：位置编码一定加在 token embedding 上吗？

**答**：不一定。绝对位置编码常与 token embedding 相加；RoPE 直接旋转 Q、K；ALiBi 直接给注意力分数加入与相对距离相关的偏置。

---

### 28.【面试高频】RoPE 的核心思想是什么？为什么只作用于 Q、K？

**简答**：RoPE 按位置对 Q、K 的二维子空间做旋转。对于位置 $m$、$n$：

$$
\langle R_m q,\ R_n k\rangle=q^{\top}R_{n-m}k
$$

因此点积能体现相对位置差。V 是被权重聚合的内容，不直接参与相似度计算，通常不需要旋转。

**追问**：RoPE 是可学习参数吗？

**答**：标准 RoPE 的旋转频率由公式确定，不是可学习的位置 embedding；但频率缩放和外推方案可能引入额外超参数。

---

### 29.【面试高频】绝对位置编码、相对位置编码各有什么优缺点？

**简答**：绝对位置编码实现简单，直接表示「第几个位置」，但超出训练长度时泛化通常较弱；相对位置编码直接建模 token 间距离或偏置，更符合注意力关系，也更有机会做长度外推，但实现和缩放策略更复杂。

**追问**：有相对位置编码就一定能无限外推吗？

**答**：不能。模型只在有限长度和距离分布上训练，超过范围后旋转频率、注意力尺度和模式都可能失真，通常仍需要位置插值、频率缩放或长文本微调。

---

### 30.【手算高频】位置插值把上下文扩大 3 倍时，两个原始整数位置之间要插入几个点？

**简答**：扩大 3 倍相当于把新位置按 $1/3$ 压缩回原训练区间。相邻原始位置之间会出现 3 个等分间隔，因此新增 2 个中间点。

**追问**：位置插值和直接外推有什么区别？

**答**：插值把更长序列映射回已见过的位置范围，避免访问未训练位置；直接外推继续使用训练范围之外的位置，可能导致注意力分数和旋转相位失真。

---

## 六、DDP、ZeRO 与全局 Batch

### 31.【面试高频】DDP 的训练流程是什么？

**简答**：每个 GPU 保存完整模型和优化器状态，读取不同数据分片，独立前向、反向；反向过程中通过 All-Reduce 汇总并平均梯度，随后各 GPU 执行相同参数更新，因此模型副本保持一致。

**追问**：DDP 主要解决显存还是速度问题？

**答**：主要通过数据并行提高吞吐；每张卡仍保存完整模型和优化器状态，单卡模型容量并未明显增加。

---

### 32.【面试高频】DeepSpeed ZeRO-1、2、3 分别切分什么？

**简答**：

- ZeRO-1：切分优化器状态。
- ZeRO-2：切分优化器状态和梯度。
- ZeRO-3：切分优化器状态、梯度和模型参数。

阶段越高，单卡状态冗余越少，可训练模型或 batch 通常更大，但通信和调度更复杂。

**追问**：ZeRO-3 前向时参数都不在本卡，怎样计算？

**答**：在需要某一层参数时，通过通信临时聚合相应分片，计算后再释放或重新切分。

---

### 33.【面试高频】从 DDP 到 ZeRO-3，训练速度一定越来越快吗？

**简答**：不一定。ZeRO 主要目标是省显存，并非无条件提速。阶段越高，参数和梯度通信越频繁；在高速互联和大模型场景可能收益明显，在小模型或慢网络下反而可能更慢。

**追问**：能开的最大 Batch Size 通常怎样变化？

**答**：在其他条件相同下，显存冗余越少，可留给激活和 batch 的空间越多，因此最大 batch 通常变大。

---

### 34.【手算高频】全局 Batch Size 怎样计算？

**简答**：

$$
B_{global}=B_{micro}\times N_{accum}\times N_{DP}
$$

其中 $N_{DP}$ 是数据并行副本数，不应直接把 tensor parallel 或 pipeline parallel 卡数都乘进去。

**追问**：8 张卡，张量并行 2，数据并行 4，每卡 micro batch=2，累积 8 次，全局 batch 是多少？

**答**：$2\times8\times4=64$。

---

## 七、解码与采样策略

### 35.【面试高频】Greedy、Top-K、Top-P、Temperature 分别做什么？

**简答**：

- Greedy：每步选择最大概率 token，确定性强但多样性差。
- Top-K：只在概率最高的 K 个 token 中重新归一化采样。
- Top-P：选择累计概率达到阈值 P 的最小候选集合，再采样，集合大小自适应。
- Temperature：对 logits 除以 $T$；$T<1$ 更尖锐，$T>1$ 更随机。

**追问**：先做 Temperature 还是先做 Top-P？

**答**：通常先调整 logits 温度，再计算概率并执行 Top-K/Top-P 过滤，最后重新归一化采样。

---

### 36.【面试高频】Greedy Search 为什么不是全局最优？

**简答**：它只选择当前一步概率最大的 token，不比较完整序列概率。例如第一步 $A=0.6$、$B=0.4$；若 A 后最佳概率为 0.1，序列概率 0.06，而 B 后最佳概率为 0.9，序列概率 0.36。Greedy 会选 A，却错过更优完整序列。

**追问**：Beam Search 是否保证全局最优？

**答**：有限 beam width 仍可能提前剪掉最终最优路径，不能保证；beam 足够大接近穷举，但计算量不可接受。

---

### 37.【面试高频】Beam Search 有什么问题？

**简答**：它保留多个高累积概率候选，常用于翻译等较确定任务，但生成可能保守、重复、缺乏多样性；直接累加 log probability 还会偏向短序列，因此常加入长度归一化或长度惩罚。

**追问**：开放式对话为什么通常不直接使用大 Beam？

**答**：高概率序列往往更模板化，beam 会进一步降低多样性；对话常使用温度、Top-P 等随机采样。

---

### 38.【项目追问】模型出现复读、循环生成，可能怎样处理？

**简答**：检查训练数据重复和模板偏差；推理时可使用 repetition penalty、frequency penalty、no-repeat n-gram、合适的温度和 Top-P，并设置停止词。参数过强会损伤事实性和连贯性，需要按任务调节。

**追问**：提高 Temperature 一定能解决复读吗？

**答**：不一定。它只让分布更平，可能同时增加低质量 token；复读也可能来自数据、模型退化或停止条件错误。

---

## 八、RLHF、PPO、DPO 与 GRPO

### 39.【面试高频】经典 PPO-RLHF 里有哪些模型？

**简答**：通常包括：

1. Policy/Actor：生成回答并被更新。
2. Reference Model：冻结，用于计算 KL 约束。
3. Reward Model：对回答打分。
4. Critic/Value Model：估计状态价值，帮助计算 advantage。

训练流程是采样回答、计算奖励与 KL、估计 advantage，再用 PPO clipped objective 更新 policy，同时拟合 value。

**追问**：Reward Model 和 Critic 是同一个作用吗？

**答**：不是。Reward Model 给完整回答或过程打偏好分；Critic 估计当前状态的期望回报，作为基线降低策略梯度方差。

---

### 40.【面试高频】PPO 的 Critic Model 有什么作用？能不能去掉？

**简答**：Critic 提供 value baseline，用于构造低方差 advantage，例如配合 GAE。标准 PPO 通常依赖 Critic；理论上可改成 REINFORCE、规则 baseline 或组内相对奖励，不再使用独立 Critic，但方差、采样量和稳定性会发生变化。

**追问**：GRPO 为什么可以不训练独立 Critic？

**答**：它对同一 prompt 采样一组回答，用组内奖励的相对标准化结果作为 advantage 近似，省去 value model，但需要更多并行 rollout。

---

### 41.【面试高频】Reference Model 有什么作用？可以去掉吗？

**简答**：Reference Model 用于约束新策略不要偏离 SFT 模型过远，常通过 token 级 KL penalty 保持语言质量、稳定训练并抑制 reward hacking。可以设计无显式 reference 的算法，但必须用其他方式限制策略漂移，否则训练容易失控。

**追问**：Reference Model 会更新吗？

**答**：经典 PPO-RLHF 中通常冻结；若随 policy 同步更新，KL 约束的锚点会不断移动，意义会改变。

---

### 42.【面试高频】PPO 和 DPO 的区别是什么？

**简答**：PPO 属于在线或近在线强化学习：需要 policy rollout、Reward Model、通常还要 Critic，并通过 clipped policy objective 优化；DPO 直接使用「chosen/rejected」偏好对，把相对偏好转成监督式目标，不需要在训练循环中单独训练 Critic 或调用 Reward Model，工程更简单、稳定。

**追问**：DPO 是否完全不需要 Reference Model？

**答**：标准 DPO 目标包含 policy 相对 reference 的 log-ratio，通常需要冻结 reference，或预先缓存 reference log-prob。

**追问**：DPO 的局限是什么？

**答**：依赖离线偏好数据质量，不能像在线 RL 那样持续探索当前策略的新输出，对复杂可验证奖励的直接利用也较弱。

---

### 43.【面试高频】PPO 和 GRPO 的区别是什么？

**简答**：两者都可使用策略比率裁剪和 KL 约束。PPO 通常训练 Critic 估计 value；GRPO 对同一问题采样多条回答，以组内相对奖励构造 advantage，不需要独立 Critic。GRPO 省 value 模型显存，但增加组采样和奖励计算开销。

**追问**：组内所有回答奖励都一样时会怎样？

**答**：标准化后的相对 advantage 接近 0，该组几乎不给策略提供有效学习信号。

---

### 44.【手算高频】PPO 为什么要做 ratio clipping？

**简答**：策略比率为：

$$
r_t(\theta)=\frac{\pi_\theta(a_t\mid s_t)}{\pi_{old}(a_t\mid s_t)}
$$

PPO 使用 $\operatorname{clip}(r,1-\epsilon,1+\epsilon)$ 限制单次更新幅度，避免新策略因少量高 advantage 样本发生过大跳变，提高训练稳定性。

**追问**：有 clipping 后还需要 KL 约束吗？

**答**：常常仍需要。Clipping 约束当前更新相对旧 policy，Reference KL 约束策略相对 SFT 锚点，二者目标不同。

---

## 九、多模态与综合项目追问

### 45.【多模态选做】CLIP 的核心训练目标是什么？

**简答**：CLIP 使用图像编码器和文本编码器得到两个向量，通过批内对比学习提高匹配图文的相似度、降低不匹配图文的相似度。损失通常同时做 image-to-text 和 text-to-image 两个方向的交叉熵。

**追问**：CLIP 为什么可以做零样本分类？

**答**：把类别写成文本提示并编码，与图像向量计算相似度，选择最匹配的文本类别，不需要为该分类任务重新训练线性分类器。

---

### 46.【多模态选做】ViT 怎样把图像输入 Transformer？

**简答**：把图像切成固定大小 patch，每个 patch 展平并线性映射成 token embedding，再加入位置编码，送入 Transformer。若图像为 $H\times W$、patch 为 $P\times P$，patch token 数约为 $HW/P^2$。

**追问**：图像分辨率翻倍，标准全局 Attention 计算量怎样变化？

**答**：高和宽都翻倍时 token 数约变为 4 倍，注意力的 $L^2$ 部分约变为 16 倍。

---

### 47.【项目追问】多模态大模型通常怎样把视觉特征接入语言模型？

**简答**：常见流程是视觉编码器提取 patch 特征，再用线性层、MLP、Q-Former 或其他 projector 映射到语言模型 embedding 空间，将视觉 token 与文本 token 拼接，或通过 Cross-Attention 融合。训练通常至少包括视觉—语言对齐和多模态指令微调。

**追问**：第一阶段为什么经常冻结视觉编码器和语言模型，只训练 projector？

**答**：先用较低成本建立两个预训练空间的对齐，避免一开始同时更新大模型导致训练不稳定和灾难性遗忘。

---

### 48.【项目追问】大模型推理 OOM 或吞吐低，如何系统排查？

**简答**：

1. 先分别看权重、KV Cache、临时算子和碎片各占多少。
2. OOM：降低并发、最大上下文或输出长度，使用量化、GQA/MQA、PagedAttention、KV Cache 低精度、Tensor Parallel。
3. Prefill 慢：关注长 prompt、Attention/FFN 算力、FlashAttention 和批处理。
4. Decode 慢：关注 KV 读取、连续批处理、GPU 利用率和请求调度。
5. 检查 tokenizer、停止条件、动态 batch 和 CPU-GPU 数据传输是否成为瓶颈。

**追问**：为什么只看模型权重大小会低估在线服务显存？

**答**：在线服务还要为每个并发请求保存每层 KV Cache，并预留算子工作区和调度 block；长上下文、高并发时 KV Cache 可能成为主要增量。

**追问**：吞吐和单请求延迟能同时无限优化吗？

**答**：不能。增大动态 batch 通常提升吞吐，但请求等待和排队时间可能增加；需要按 TTFT、TPOT、吞吐和 SLA 做权衡。
