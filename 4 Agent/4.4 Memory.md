正文开始之前先放一个吴恩达老师对Agent的理解图，其中的很多方法已经介绍过了：

- **任务分解**是指借助LLM将任务拆解为若干个子任务，并依次对每个子任务进行规划。可以分为先分解后规划（HuggingGPT，plan and solve）和边分解边规划（COT，react，pal）两个思路
- **多方案选择**是指大型语言模型深入“思考”，针对特定任务提出多种可能的方案。接着，利用针对性的任务搜索机制，从中挑选一个最合适的方案来实施。例如ToT，GoT，LAT
- **外部模块辅助规划**。该策略专门设计用于引入外部规划器，以增强规划过程的效率和计划的可行性，同时大型语言模型主要负责将任务规范化。分为符号规划器（LLM+P）和神经规划器（利用强化学习训练深度学习模型，作为决策模型）
- **反思与优化**。这种策略着重于通过自我反思和细节完善来增强规划能力。它激励大型语言模型Agent应用在遭遇失败后进行深入反思，并据此优化规划方案。例如Reflexion，critic
- **记忆增强规划**。该策略通过引入一个附加的记忆组件来提升规划能力，该组件中存储了各种宝贵信息，包括基本常识、历史经验、领域专业知识等。在进行规划时，这些信息会被调取出来，充当辅助提示，以增强规划的效果。分为RAG记忆（即接下来要介绍的Memory）和嵌入式记忆（将RAG知识通过微调嵌入到模型参数里）

![[Pasted image 20260801133619.png]]
这张图分类总结了现有的 **大语言模型智能体（LLM-Agent）规划方法**，将其归纳为五大核心范式：
- **任务分解（Task Decomposition）：** 采用“分而治之”策略，将复杂问题拆解为多个子任务按顺序求解（代表作：CoT, ReAct, HuggingGPT）。
- **多计划选择（Multi-plan Selection）：** 生成多条潜在的规划路径，从中评估并选择最佳方案（代表作：ToT, GoT, CoT-SC）。
- **外部规划器辅助（External Planner-aided）：** 由 LLM 将问题形式化表达，再借助外部专业求解器生成精确规划（代表作：LLM+P, LLM+PDDL）。
- **反思与优化（Reflection & Refinement）：** 基于执行反馈或历史经验进行自我反思，迭代修正规划方案（代表作：Reflexion, CRITIC, Self-Refine）。
- **记忆辅助规划（Memory-aided Planning）：** 从长期记忆库中检索历史经验与上下文，以辅助当前规划的生成（代表作：REMEMBER, MemoryBank）。

记忆模块是智能体存储内部日志的关键组成部分，负责存储过去的思考、行动、观察以及与用户的互动。
- **短期记忆**关注于**当前情境的上下文信息**，是短暂且有限的，通常通过上下文窗口限制的学习实现。
- **长期记忆**储存智能体的历史行为和思考，通过**外部向量存储**实现，以便快速检索重要信息。
- **混合记忆** -通过整合短期和长期记忆，不仅优化了智能体对当前情境的理解，还加强了对过去经验的利用，从而提高了其长期推理和经验积累的能力。

>长期记忆存储到外部存储器中，最常见的做法是将记忆的embedding存储到支持快速的最大内积搜索（MIPS）的向量存储数据库中。不只是文本，图像、音视频等非结构化数据也可以存储为结构化向量，降低了存储和计算的成本，同时加速了检索效率。

#### 4.4.6 Langchain实现Memory-based agent
langchain中使用memory的例子（本代码是基于v0.1.7构建的，新版本请自行查看官方[InMemorySaver](https://docs.langchain.com/oss/python/langchain/short-term-memory)）：
	创建一个简单的自定义代理，该代理可以访问搜索工具并使用`ConversationBufferMemory`类。首先定义搜索工具

```Python
from langchain.agents import ZeroShotAgent, Tool, AgentExecutor
from langchain.memory import ConversationBufferMemory
from langchain import OpenAI, LLMChain
from langchain_core.tools import Tool
from langchain_community.utilities import SerpAPIWrapper
from langchain_openai import ChatOpenAI
import os
os.environ["SERPAPI_API_KEY"] = (
    "Your serpapi key"
)
search = SerpAPIWrapper()
from langchain.agents import load_tools
# 4. 初始化 OpenAI 聊天模型实例 
# - model: 从环境变量 "LLM_MODELEND" 中读取具体的模型名称（如 "gpt-4o" 等） 
# - temperature=0: 将随机度设为 0，使输出更加确定和稳定，适合 Agent 进行逻辑推理与工具调用
llm = ChatOpenAI(model=os.environ["LLM_MODELEND"], temperature=0)
# 5. 加载指定的工具列表 # 传入 "serpapi" 工具名称以及初始化好的 LLM 实例，将其整合为 Agent 可调用的工具集
tools = load_tools(["serpapi"], llm=llm)
```
接下来定义一个`prompt`，prompt中的的chat_history需要与ConversationBufferMemory的key对应，存储对话记录。

```Python
# 1. 定义 Prompt 前缀（System Prompt / 人设与任务说明）
# 用于设定 Agent 的基本行为模式，这段话会被放置在工具列表说明的前面
prefix = """Have a conversation with a human, answering the following questions as 
           best you can. You have access to the following tools:"""
# 2. 定义 Prompt 后缀（结构化模板与变量占位符）
# 包含了历史对话、当前用户提问以及 Agent 思考过程（Scratchpad）的注入位置
suffix = """Begin!"

{chat_history}
Question: {input}
{agent_scratchpad}"""
# 3. 创建适用于 ZeroShotAgent 的完整 Prompt 模板
# 自动将工具列表（tools）、前缀、后缀组合，并声明 Prompt 所依赖的变量名
prompt = ZeroShotAgent.create_prompt(
    tools,
    prefix=prefix,
    suffix=suffix,
    input_variables=["input", "chat_history", "agent_scratchpad"],
)
# 3. 创建适用于 ZeroShotAgent 的完整 Prompt 模板
# 自动将工具列表（tools）、前缀、后缀组合，并声明 Prompt 所依赖的变量名
memory = ConversationBufferMemory(memory_key="chat_history")
```

接下来创建一个LLMChain，然后将momory加入到agent中。

```Python
# 1. 创建底层 LLM 链（LLMChain）
# 将之前定义好的 LLM 模型与包含了 Prompt 模板绑定在一起，作为 Agent 的推理大脑
llm_chain = LLMChain(llm=llm, prompt=prompt)

# 2. 实例化 ZeroShotAgent 智能体
# - llm_chain: 传入推理链
# - tools: 传入 Agent 可以使用的工具列表
# - verbose=True: 开启详细日志，终端会实时打印 Agent 的思考与推理步骤（ReAct 过程）
agent = ZeroShotAgent(llm_chain=llm_chain, tools=tools, verbose=True)

# 3. 创建 Agent 执行器（AgentExecutor）
# 执行器负责管理 Agent 的运行循环（选择工具 -> 执行工具 -> 读取结果 -> 决策下一步）
# 此处将 agent、tools 以及之前定义的对话记忆 memory 统一整合在一起
agent_chain = AgentExecutor.from_agent_and_tools(
    agent=agent, tools=tools, verbose=True, memory=memory
)

# 4. 执行第一轮对话
# Agent 接收问题后，会通过工具（如 SerpAPI）查询加拿大的人口并返回答案
agent_chain.run(input="How many people live in canada?")

# 5. 执行第二轮对话
# 提问中的 "their" 属于指代模糊。因为绑定了 memory，Agent 能通过历史上下文识别出 "their" 指的是 "Canada"，展示连续对话与记忆能力
agent_chain.run(input="what is their national anthem called?")
```

langchain中为我们实现了多种记忆，常见的有：
- **ConversationBufferMemory**：**所有聊天记录**都被存入chat_history中，导致下一轮的prompt很长
- **ConversationBufferWindowMemory**：只保留**最近几次**人类与AI的互动，只适应短对话。
- **ConversationSummaryMemory**：在回答新问题的时候，对之前的问题进行了**总结性的重述**，再传递给chat_history 参数，这种基于总结的方法能避免过度使用token，适合长对话。总结由LLM完成，虽然最初使用的 Token 数量较多，但随着对话的进展，汇总方法的增长速度会减慢；并且，总结的过程中并没有区分近期的对话和长期的对话（通常情况下近期的对话更重要）。
- **ConversationSummaryBufferMemory**：**总结较早的对话，保留近期的对话原始内**

#### 4.4.7 Mem0 + Qdrant 向量数据库实现记忆

Mem0 是一个为 AI 应用设计的智能记忆层，旨在通过保留用户偏好并随时间不断适应，提供个性化且高效的交互体验。特别适合聊天机器人和 AI 驱动的工具，Mem0 能够创建无缝、上下文感知的体验。

Mem0 支持**多种向量存储后端**，包括 Milvus、Chroma、Pinecone、PGVector 等。本节选用 **Qdrant 本地模式**——相比 Milvus Lite，Qdrant 在本地文件模式下更稳定，无需处理集合（collection）的加载/释放（load/release）状态问题。

同时，LLM 使用 **DeepSeek**（兼容 OpenAI 接口，性价比高），Embedding 使用 **sentence-transformers**（免费本地模型，无需额外 API 费用）。

> 📓 完整可运行的 Jupyter Notebook 见 [Memory.ipynb](Memory.ipynb)

##### 安装依赖

```bash
pip install mem0ai qdrant-client sentence-transformers
```

##### 配置 Mem0（DeepSeek + Qdrant）

```python
import os
from mem0 import Memory

# 请替换为您的 DeepSeek API Key（控制台: https://platform.deepseek.com/api_keys）
os.environ[“OPENAI_API_KEY”] = “sk-your-deepseek-key”

# 定义 Mem0 配置：LLM → DeepSeek，Embedder → 本地模型，向量库 → Qdrant
config = {
    “llm”: {
        “provider”: “openai”,                                     # DeepSeek 兼容 OpenAI 接口
        “config”: {
            “model”: “deepseek-chat”,
            “openai_base_url”: “https://api.deepseek.com/v1”,     # 指向 DeepSeek API
        },
    },
    “embedder”: {
        “provider”: “huggingface”,
        “config”: {
            “model”: “sentence-transformers/all-MiniLM-L6-v2”,    # 免费本地嵌入模型
            “embedding_dims”: 384,                                 # 该模型输出 384 维向量
        },
    },
    “vector_store”: {
        “provider”: “qdrant”,
        “config”: {
            “collection_name”: “quickstart_mem0”,
            “embedding_model_dims”: 384,                           # 与 embedder 维度一致
            “path”: “./qdrant_db”,                                 # 本地持久化存储
            “on_disk”: True,                                       # 向量存入磁盘
        },
    },
    “version”: “v1.1”,
}

# 初始化 Memory 实例
m = Memory.from_config(config)
```

> **关键注意**：`embedding_model_dims` 必须与所选 Embedding 模型的实际输出维度一致。`all-MiniLM-L6-v2` 输出 384 维，OpenAI `text-embedding-ada-002` 输出 1536 维。维度不匹配会导致写入或搜索失败。

##### 添加记忆

`add` 函数将非结构化文本作为记忆存储到向量库中，并将其与特定用户和可选元数据关联。Mem0 内部会自动调用 LLM 从原文中**提炼关键事实**，而非原样存储。

```python
# 添加 Alice 的第一条记忆 —— 兴趣爱好
res1 = m.add(
    messages=”Working on improving my tennis skills.”,
    user_id=”alice”,
    metadata={“category”: “hobbies”},
)
print(“添加第一条记忆结果：\n”, res1)
```
输出结果：
```json
{'results': [{'id': 'd96ac99b-95f7-4778-897d-64e337b14fe5',
  'memory': 'User is working on improving their tennis skills.',
  'event': 'ADD'}]}
```

可以看到 Mem0 自动将原文提炼为第三人称表述 `”User is working on improving their tennis skills.”`。

##### 架构对比与选型建议

| 组件 | 本节方案 | 原 Milvus 方案 | 说明 |
|------|----------|----------------|------|
| **LLM** | DeepSeek Chat | OpenAI GPT | 成本更低，兼容 OpenAI SDK |
| **Embedding** | all-MiniLM-L6-v2 (384d) | text-embedding-ada-002 (1536d) | 免费本地运行，无需 API |
| **向量库** | Qdrant 本地模式 | Milvus Lite | Qdrant 本地模式更稳定，无集合状态管理问题 |
| **mem0 API** | `filters={“user_id”: ...}` | `user_id=...` | mem0 v2.x 统一改用 filters 传参 |

**选型建议**：
- **数据量 < 百万级**：Qdrant 本地模式足够，零运维成本
- **生产环境 / 大规模**：可切换为 Milvus 服务端或 Qdrant Cloud
- **Embedding 质量优先**：可换回 OpenAI `text-embedding-3-small`，将 `embedding_dims` 改为 1536
