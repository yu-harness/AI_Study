# 知识库搜索问答 Skill

在本地 markdown 知识库中搜索相关内容，基于搜索结果生成有据可查的回答。

## 知识库约定

### 目录结构

默认知识库路径为 `./knowledge-base/`（相对于项目根目录）。用户可以在项目根目录的 `AGENTS.md` 或 `.Codex/settings.json` 中通过注释配置自定义路径。如果默认路径不存在，**主动询问**用户知识库所在目录。

知识库内的文件按主题/类别组织为子目录，例如：

```
knowledge-base/
├── python/
│   ├── decorators.md
│   └── async-io.md
├── database/
│   ├── sql-optimization.md
│   └── indexing.md
└── devops/
    └── docker-basics.md
```

### 文件格式（推荐）

每个 markdown 文件推荐包含 YAML 前置元数据（frontmatter），格式如下：

```yaml
---
title: "清晰的文档标题"
tags: ["标签1", "标签2"]
category: "分类名"
date: 2024-01-15
summary: "一句话描述本文内容"
---
```

- **title**：文档标题，用于搜索结果展示。如未提供，以文件第一个 H1 标题为准；若都没有，使用文件名
- **tags**：标签列表，用于精确匹配和分类筛选。标签使搜索更精准
- **category**：所属分类，与目录名可互为补充
- **summary**：内容摘要，可帮助 AI 快速判断相关性
- 以上字段均为推荐项。没有 frontmatter 的文件依然可被搜索到，只是匹配精度可能下降

### 文件命名

- 使用有意义的文件名，如 `python-decorators.md` 而非 `doc1.md`
- 文件名中的关键词也会被搜索匹配
- 支持中文文件名

## 搜索问答流程

### 第一步：定位知识库

1. 检查默认路径 `./knowledge-base/` 是否存在
2. 如果不存在，检查项目 `AGENTS.md` 中是否有知识库路径说明
3. 如果都没有，询问用户："未找到默认知识库目录。请告诉我你的知识库（markdown 文件集合）在哪个目录下？"
4. 确认目录存在且包含 `.md` 文件后，进入下一步

### 第二步：理解问题并提取搜索词

分析用户问题，提取关键词组合：

- **核心概念词**：问题的主题词，如 "decorator"、"docker"、"索引优化"
- **限定词**：缩小范围的词，如 "Python 中"、"MySQL 8.0"、"生产环境"
- **同义词/相关词**：如用户问"加速查询"，应同时搜索 "优化"、"性能"、"索引" 等

**重要**：提取搜索词时不要照搬整句，要拆分出 2-5 个关键搜索词组。对于中文问题，同时考虑中英文混合搜索（如用户用中文问 Python 相关问题）。

### 第三步：多阶段搜索

采用**渐进式搜索策略**——先用精准匹配，逐步扩大范围：

#### 阶段 1：精准全文搜索

使用 Grep 工具搜索知识库目录，匹配核心关键词组合：

```
Grep: pattern="核心关键词" path=<知识库路径> glob="*.md" output_mode="files_with_matches"
```

- 如果匹配文件数量在 3-15 个之间 → 进入第四步
- 如果匹配文件超过 15 个 → 追加限定词缩小范围，重新搜索
- 如果匹配文件少于 3 个 → 进入阶段 2

#### 阶段 2：分词宽搜索

将问题拆分为独立关键词，分别搜索：

```
Grep: pattern="关键词1|关键词2|关键词3" path=<知识库路径> glob="*.md" output_mode="files_with_matches"
```

- 也可以对每个关键词单独搜索，然后合并结果
- 如果仍不足 3 个匹配文件 → 进入阶段 3

#### 阶段 3：标签和文件名搜索

1. 搜索 frontmatter 中的 tags 字段：
   ```
   Grep: pattern="tags:.*关键词" path=<知识库路径> glob="*.md" output_mode="content"
   ```
2. 用 Glob 搜索文件名中包含关键词的文件：
   ```
   Glob: pattern="**/*关键词*.md" path=<知识库路径>
   ```
3. 搜索文档标题（H1）：
   ```
   Grep: pattern="^# .*关键词" path=<知识库路径> glob="*.md" output_mode="content"
   ```

如果三阶段后仍无结果 → 进入优雅降级处理（见第五步）

### 第四步：提取相关内容并生成回答

#### 4.1 读取候选文件

对搜索结果中排名靠前的文件（优先选择匹配行数多的），使用 Read 工具读取：

- 如果匹配文件 ≤ 5 个：全部读取
- 如果匹配文件 > 5 个：读取匹配行数最多的前 5 个

#### 4.2 提取相关内容

从每个文件中提取与问题最相关的段落：

- 优先展示匹配行所在段落及其上下文（前后各 3-5 行）
- 如果文档有 frontmatter summary，检查其相关性
- 跳过明显不相关的匹配（如仅是脚注或引用中提到关键词）

#### 4.3 生成回答

基于提取的内容生成回答，遵循以下原则：

1. **先给结论**：用 1-2 句话直接回答问题
2. **展开细节**：引用文档中的具体内容支撑结论
3. **标注来源**：每个引用点注明来源文件和位置，格式 `[文件名:行号](路径)`
4. **区分确定性**：
   - 知识库有明确答案 → "根据文档记载..."
   - 知识库有部分相关但不够完整 → "文档中提到...但未涉及...，以下是相关内容的整理"
   - 多处信息需要综合 → "综合多份文档的信息..."

**回答模板**：

```markdown
## 🔍 [问题的简短概括]

[直接回答，基于知识库内容]

### 📂 相关内容

**来源：[文件路径]**
> [引用的关键段落]

**来源：[文件路径]**
> [引用的关键段落]

### 📋 总结

[归纳要点]
```

#### 4.4 质量检查（内部自检）

在输出最终回答前，做一轮自检：
- 回答中的每个事实是否有文档依据？→ 没有依据的不写
- 来源标注是否准确（文件路径、大致位置）？
- 如果只找到部分相关材料，是否明确告知用户覆盖范围有限？

### 第五步：优雅降级——找不到相关内容时

当三阶段搜索均无结果时，不要编造答案。按以下格式诚实告知：

```markdown
## 🔍 未找到相关内容

我在知识库（`<知识库路径>`，共 <N> 个文档）中搜索了以下关键词：
- `<关键词1>`
- `<关键词2>`
- ...

**未能找到与"<用户原始问题>"直接相关的内容。**

### 💡 建议

1. **换个说法试试**：尝试用不同的关键词或同义词重新提问
2. **检查知识库范围**：当前知识库可能未覆盖该主题，可以确认一下知识库的内容范围
3. **扩展知识库**：如果你有相关文档，可以添加到知识库目录中
4. **相关主题**：[如果发现了间接相关的内容，在此列出并附上链接，如"虽然没有直接的XX文档，但有一篇关于YY的笔记可能对你有用"]

> 如果你需要的是通用知识而非本地文档的内容，可以不使用知识库搜索，直接向我提问即可。
```

## 知识库维护建议

在回答结束后，如果发现以下情况，可以给出简短建议：

- **信息过时**：如果文档内容明显是旧版本/过时信息，提醒用户更新
- **内容冲突**：如果不同文档对同一问题有矛盾说法，指出冲突并建议用户核实
- **覆盖空白**：如果用户频繁问某类问题但知识库明显缺少相关内容，建议补充

## 配置说明

### 自定义知识库路径

在项目根目录的 `AGENTS.md` 中添加：

```markdown
# 知识库配置
知识库路径: ./docs/wiki/
```

或者在 `.Codex/settings.json` 中添加：

```json
{
  "knowledgeBasePath": "./docs/wiki/"
}
```

### 搜索范围限制

如果知识库很大，用户可以在提问时指定搜索范围：
- "在 Python 分类下搜索..." → 限制在 `knowledge-base/python/` 子目录
- "搜索最近半年的笔记" → 筛选 date 在半年内的文件

## 注意事项

- **事实导向**：只回答知识库中有依据的内容，不编造信息。如果知识库内容不足以回答问题，诚实说明
- **隐私意识**：知识库内容可能包含敏感信息，回答时不要在未授权的情况下将内容发送到外部服务
- **大文件处理**：对于超过 500 行的文档，先用 Grep 定位相关段落再分段读取，避免不必要地消耗上下文
- **中文分词**：中文搜索时注意分词粒度，如"数据库索引优化"应拆为"数据库"、"索引"、"优化"分别搜索
- **增量搜索**：如果第一轮回答不够好，用户可以追加"再搜一下 XX"，此时在上一轮基础上扩大搜索范围
- **时效性标注**：如果文档有 date 字段，在引用时标注日期，让用户判断信息是否过时
