# 法律合同风险审查 Skill

审查用户提交的合同文本，自动识别风险条款，输出结构化的风险审查报告。

## 输入参数

| 参数 | 必填 | 说明 |
|------|:----:|------|
| 合同文件路径 | ✅ | Markdown (`.md`) 或 Word (`.docx`) 格式的合同文件路径 |
| 委托方角色 | ✅ | 用户是 **甲方** 还是 **乙方**。如用户未指定，**必须主动询问**后再继续 |
| 合同类型 | 否 | `买卖` / `租赁` / `服务` / `劳动`。未指定时，根据合同内容自动识别。识别规则见 `references/contract-types.md` |
| 特殊标签 | 否 | 在用户输入中检测以下标签，触发对应行为：<br>• `[包含优势分析]` → 在报告末尾追加 🟢 对我方有利 板块 |

> ⚠️ **输出控制铁律**：默认仅输出 🔴高风险、🟡中风险、ℹ️提示 三个板块。**仅当用户的输入中明确包含 `[包含优势分析]` 标签时**，才在报告末尾追加 🟢对我方有利 板块。即使在审查过程中发现了对我方有利的条款，只要用户未提供该标签，就不得在报告中输出该板块。

---

## 审查流程

### 第零步：文件格式检测与转换

1. 检查合同文件扩展名：
   - `.md` → 直接使用 Read 工具读取
   - `.docx` → 运行 `python .Codex/skills/contract-reviewer/scripts/parser.py "<文件路径>"` 将 Word 转为 Markdown 后读取输出结果
   - 其他格式 → 提示用户："当前仅支持 Markdown (.md) 和 Word (.docx) 格式。请将文件转换为上述格式后重新提交。"

2. 如果 `parser.py` 执行失败（如 python-docx 未安装），提示用户：
   ```
   ⚠️ 读取 Word 文件需要 python-docx 库。请运行：
   pip install python-docx
   或直接将合同内容粘贴为 Markdown 格式提交。
   ```

### 第一步：读取合同文本

使用 Read 工具读取合同文件（如果是 .docx，则读取 parser.py 转换后的输出），获取完整合同内容。

### 第二步：确定合同类型

1. 如果用户已指定合同类型（买卖/租赁/服务/劳动），直接使用
2. 如果未指定，根据合同内容关键词自动识别：
   - 买卖合同：买卖、货物、交付、验收、所有权转移、价款
   - 租赁合同：租赁、租金、出租、承租、押金、续租
   - 服务合同：服务、开发、咨询、委托、技术服务、外包
   - 劳动合同：劳动、试用期、工资、社保、解除、竞业
3. 如果无法判断，默认使用 **通用审查模板**（即仅启用四项内置规则）

### 第三步：加载审查规则

按以下优先级合并审查规则（高优先级覆盖低优先级）：

```
优先级 1（最高）：references/custom-rules.md 中的自定义规则（如果文件不为空）
优先级 2          ：references/contract-types.md 中匹配合同类型的专项规则
优先级 3（基础）  ：references/review-rules.md 中的四项内置通用规则
```

> 📌 **合并逻辑**：如果自定义规则与内置规则审查同一维度（如都审查"违约金"），以自定义规则的阈值/标准为准。自定义规则中新增的审查维度与内置规则并列输出。

### 第四步：逐项审查

#### 4.1 通用审查（所有合同类型，来自 review-rules.md）

1. **违约金过高/过低** — 查找违约条款，⚠️ **必须先区分违约主体（我方/对方）**，再计算违约金年化比例。详细规则见 `references/review-rules.md` 第一章
2. **管辖法院是否不利** — 查找争议解决条款，判断对委托方是否不利。详细规则见 `references/review-rules.md` 第二章
3. **保密条款是否缺失** — 检查合同中是否包含保密/NDA 相关内容。详细规则见 `references/review-rules.md` 第三章
4. **付款条件是否模糊** — 检查付款条款中是否存在不明确的触发条件和交付标准。详细规则见 `references/review-rules.md` 第四章

#### 4.2 专项审查（根据合同类型，来自 contract-types.md）

读取 `references/contract-types.md`，匹配 `<type name="{合同类型}">` 标签内的专项检查点，与通用审查同步执行。

各合同类型的专项审查项摘要：

| 合同类型 | 专项审查项 |
|----------|-----------|
| 买卖合同 | 质量标准与验收、交付与所有权转移、瑕疵担保、不可抗力范围 |
| 租赁合同 | 维修责任划分、转租限制、押金退还条件、续租与优先购买权 |
| 服务合同 | 服务SLA与验收标准、知识产权归属、竞业限制、分包限制 |
| 劳动合同 | 试用期合法性、竞业限制补偿金、社保与公积金、单方解除条件 |

#### 4.3 自定义规则审查（如有）

如果 `references/custom-rules.md` 文件存在且包含有效规则条目，将每条自定义规则作为额外的审查维度执行。自定义规则的审查结果与内置规则的审查结果合并，按风险等级归类输出。

### 第五步：风险分级

按风险等级归类：

- 🔴 **高风险**：管辖法院完全对委托方不利、违约金为0或极其不合理、完全缺失关键条款。**必须修改。**
- 🟡 **中风险**：对方违约金偏低（惩罚不足）、我方违约金偏高（违约成本过高）、付款条件存在模糊之处、保密条款不够完善。**建议修改。**
- ℹ️ **提示**：风险程度较低、仅作为提醒的事项。

> ⚠️ **再次强调**：除非用户输入中包含 `[包含优势分析]` 标签，否则**不输出** 🟢对我方有利 板块。该标签不存在时，关于"对我方有利"的分析仅作为内部判断使用，不得出现在最终报告中。

### 第六步：生成报告

按照以下模板输出审查报告（严格遵守板块顺序和格式）：

```markdown
# 📄 合同风险审查报告

> ⚠️ AI审查仅供参考，不构成正式法律意见。重大合同请咨询专业律师。

## 🔴 高风险 (N项)
[逐条列出高风险，每条包含：]
- **[风险标签]** 第X条/第X款约定"原文引用"
- 风险：(说明具体风险)
- 建议：(给出具体的修改建议)
- 📖 依据：(如该风险项来自自定义规则，标注"自定义规则"；如来自合同类型专项审查，标注合同类型；否则标注"通用规则")

## 🟡 中风险 (N项)
[逐条列出中风险，格式同上]

## ℹ️ 提示 (N项)
[逐条列出提示项，格式同上]

---
**总计：高风险 X | 中风险 X | 提示 X**
```

> 📌 仅当用户输入包含 `[包含优势分析]` 标签时，才在上述报告末尾追加：

```markdown
## 🟢 对我方有利 (N项)
[逐条列出对我方有利的条款，格式同上，但标注为"有利"而非"风险"]
```

> 📌 最终总计行也相应更新：**总计：高风险 X | 中风险 X | 提示 X | 对我方有利 X**

## 注意事项

- **引用原文**：每个风险项必须引用合同中对应的条款原文，让用户能快速定位
- **具体建议**：建议要具体可操作，不要只说"需要修改"，要给出修改后的参考表述
- **委托方视角**：所有风险判断必须站在委托方角色（甲方或乙方）的立场
- **⚠️ 违约金必须主体绑定**：审查违约金时，必须先区分违约主体是我方还是对方。我方违约金低=对我方有利，对方违约金低=对我方不利。两者方向相反，绝对不能混淆
- **不做无中生有**：只审查合同实际存在的条款，不虚构问题
- **免责声明必须写在报告最前面**：AI审查仅供参考，不构成正式法律意见
- **输出板块严格控制**：无 `[包含优势分析]` → 仅输出 🔴🟡ℹ️；有 `[包含优势分析]` → 可追 🟢
- **自定义规则溯源**：来自自定义规则的审查结果，在报告的建议末尾标注 `📖 依据：自定义规则`
- **Word 文件处理**：.docx 文件需先通过 `scripts/parser.py` 转换为 Markdown，再进入审查流程
