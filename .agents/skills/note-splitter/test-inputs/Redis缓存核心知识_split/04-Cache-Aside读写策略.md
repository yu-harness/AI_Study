# 🎯 Cache-Aside 读写策略与三大问题

**这个知识点要回答：Cache-Aside 模式的读写流程是什么？会遇到哪三个经典问题？怎么解决？**

---

## ✍️ 自测

① Cache-Aside 模式的读流程是怎样的？


② Cache-Aside 模式的写流程是怎样的？为什么是删除缓存而不是更新？


③ 缓存穿透是什么？怎么解决？


④ 缓存击穿和缓存雪崩有什么区别？各自怎么解决？


---

## ✅ 参考答案

① **读流程**：先查缓存 → 命中直接返回 → 未命中则查数据库 → 将结果写入缓存 → 返回给调用方

② **写流程**：先更新数据库 → **再删除缓存**。删除而非更新的原因：更新缓存存在并发写风险，且某些缓存数据是经过复杂计算得到的，直接删让下次读时重建更简单

③ **缓存穿透**：查询一个**不存在的数据**，缓存和数据库都没有，每次请求都穿透到数据库。**解决**：①**布隆过滤器**（Bloom Filter）拦截不存在 key ②缓存**空值**（即使查不到也缓存一个空结果，设置短 TTL）

④ **缓存击穿**：**单个热点 key** 过期，大量并发请求同时穿透到 DB。**解决**：互斥锁（只让一个请求去查 DB 重建缓存）、热点 key **永不过期**（后台异步更新）。**缓存雪崩**：**大量 key 同时过期**，导致大量请求打到 DB。**解决**：过期时间加**随机值**打散过期时间、**多级缓存**（本地缓存+Redis）、服务降级
