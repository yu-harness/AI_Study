## 二、四层楼，每一层学什么

### 第 1 层 通用原理（已完成 ✅）

你已经做完的：MQ 本质、三大价值、可靠性链路、幂等、积压、RPC vs MQ、选型决策树。
> **够不够？** 面试基础题约 60% 已覆盖；但如果目标是后端/中间件岗，还需要往下走。

### 第 2 层 产品机制（下一步：核心）

**为什么先学这个**：通用原理是"抽象层"，面试官追问的"Kafka 怎么保证顺序""Offset 是什么"全在这层。**没学产品机制，原理答得再顺也落不了地。**

按"先掌握一个产品，再横向对比"的顺序学：

| 产品 | 必须掌握的机制 | 学完能回答 |
|---|---|---|
| **Kafka**（推荐先学） | Topic / Partition / Consumer Group / Offset / 副本与 ISR | 为什么 Kafka 吞吐高？消息怎么保证顺序？消费进度存在哪？ |
| **RabbitMQ** | Exchange / Binding / Queue / ACK / 死信 | Exchange 四种类型怎么路由？RabbitMQ 什么时候掉队？ |
| **RocketMQ** | Topic / Queue / 事务消息 / 延时消息 / 消费模式 | 事务消息怎么保证本地事务与消息一致？ |

> **建议顺序**：先 Kafka 再 RabbitMQ。Kafka 的 Partition+Offset 是理解"高吞吐/顺序/积压"的关键骨架，很多公司面试主问 Kafka；RabbitMQ 作为对照理解路由灵活性。

### 第 3 层 落地实践（产品机制学完后）

- 用 Docker 起一个 Kafka（KRaft 模式，无 Zookeeper）+ 一个 RabbitMQ；
- 写一个 Producer 发消息、一个 Consumer 消费并打印；
- 故意制造一次"重复消费"（消费后不 ACK），观察消息重新投递；
- 配置一个死信队列，看处理失败的消息如何流转。

> **验证标准**：能自己跑通一条消息从发送到确认，并在日志里看到"重复投递""死信"现象，才算真的懂，而不是看过。

### 第 4 层 生产级工程（进阶 / 按需）

- 积压的排查流程（对应笔记六）；
- 幂等的落地（唯一索引 / 状态机 / Redis 去重）；
- 对账与告警、消费者优雅停机、消息轨迹（链路追踪）。

## 四、一个自测：学完第 2 层后，你应该能回答

1. Kafka 为什么吞吐高？（顺序写盘 + Partition 并行 + 批量）
2. Kafka 怎么保证顺序？（同一 key → 同一 Partition；只能保证 Partition 内有序）
3. Offset 存在哪？消费者重启怎么续读？（存在 Kafka 内部 topic `__consumer_offsets`）
4. RabbitMQ 的 Exchange 四种类型是？（direct / fanout / topic / headers）
5. RocketMQ 事务消息怎么保证一致？（半消息 + 回查）

> 现在答不全没关系——这正是第 2 层要补的。答全了，说明你已经站上第 3 层。
