## 一、一条消息是怎么流动的？

```text
生产者发送消息
    ↓
Broker 接收并保存消息
    ↓
消费者拉取或接收消息
    ↓
消费者执行业务逻辑
    ↓
处理成功后确认
```

例如，用户下单后，订单服务可以发送一条"订单已创建"消息：

```json
{
  "event": "OrderCreated",
  "orderId": "O1001",
  "userId": "U9527",
  "amount": 99.9
}
```

财务服务可以消费它来扣款，仓储服务可以消费它来扣库存，通知服务可以消费它来发送短信。订单服务不需要逐个调用这些服务，也不需要知道每个服务什么时候处理完。

## 二、5 个核心角色

| 角色 | 一句话理解 | 初学者要记住什么 |
|---|---|---|
| **Producer** | 消息发送者 | 负责把消息发给 Broker |
| **Message** | 要传递的数据 | 最好包含业务唯一 ID 和事件类型 |
| **Broker** | 消息中间件服务器 | 负责接收、保存、投递和管理消息 |
| **Queue / Topic** | 消息的组织方式 | Queue 更像任务队列，Topic 更像事件频道 |
| **Consumer** | 消息处理者 | 处理成功后才确认，失败要重试或补偿 |

> 不同产品对这些概念的叫法不同，但整体角色基本一致。

## 三、Queue 和 Topic 有什么区别？

| 模型 | 类比 | 一条消息通常被谁消费？ | 常见用途 |
|---|---|---|---|
| **点对点 / Queue** | 取餐台上一张订单只能被一个厨师接走 | 一个消费组中的一个消费者 | 任务分发、订单处理、异步任务 |
| **发布/订阅 / Topic** | 广播一条通知，多个部门都能收到 | 多个订阅者或消费组都可以收到 | 领域事件、日志、业务通知 |

> **注意**：不同 MQ 的消费模型和命名会有差异，不能只看"Queue"或"Topic"字面判断语义。Kafka 的 Topic 还会继续切分为多个 Partition；顺序通常只能保证在某个队列或 Partition 内，而不是整个 Topic 全局有序。

![[mq-basic-model.png]]

> **图释**：生产者把消息放入消息队列，消费者稍后再取出处理；生产和消费的时间不必完全同步。

## 四、为什么它也叫"中间件"？

中间件就是**夹在应用程序之间，为应用程序提供通用能力的软件**。数据库为应用提供数据存储，RPC 框架提供远程调用，消息队列则为应用提供异步通信、消息存储、重试和流量缓冲。

所以，消息队列不是直接服务用户的业务系统，而是帮助业务系统互相协作的基础设施。

## 五、JMS、AMQP 和消息模型：它们不是同一种东西

这几个名词容易混淆，先看结论：

| 名词 | 本质 | 解决什么问题 |
|---|---|---|
| **JMS** | Java 的消息 API 规范 | 规定 Java 程序如何发送、接收消息 |
| **AMQP** | 跨语言的消息协议 | 规定客户端和 Broker 如何通信 |
| **RabbitMQ** | 消息中间件产品 | 常用 AMQP，并提供 Exchange、Queue 等能力 |
| **Kafka / RocketMQ / Pulsar** | 各自的消息/流平台 | 有自己的协议和架构，不等于 JMS 或 RabbitMQ |

### 5.1 JMS

JMS（Java Message Service）是 Java 生态中的 API 规范。它定义了 Java 程序发送和接收消息的接口，也定义了 `TextMessage`、`BytesMessage` 等消息类型。

JMS 常见的两种模型：

**点对点（P2P）**：一条消息进入 Queue 后，通常由一个消费者处理；多个消费者可以共同分担消息，但同一条消息不会被同一个消费组里的所有消费者都处理。

![[mq-p2p-model.png]]

**发布/订阅（Pub/Sub）**：生产者向 Topic 发布消息，不同订阅者或消费组可以各自收到一份消息。

![[mq-pub-sub-model.png]]

### 5.2 AMQP

AMQP（Advanced Message Queuing Protocol）是面向消息中间件的开放协议，关注的是**消息如何在客户端和 Broker 之间传输和路由**。

以 RabbitMQ 为例，常见关系是：

```text
Producer → Exchange → Binding → Queue → Consumer
```

Exchange 负责路由，Queue 负责暂存，Consumer 负责处理。RabbitMQ 还支持 MQTT、STOMP 等协议，但这不意味着所有 MQ 都使用 AMQP。

### 5.3 JMS 和 AMQP 的区别

| 对比方向 | JMS | AMQP |
|---|---|---|
| 类型 | Java API 规范 | 跨语言网络协议 |
| 适用范围 | 主要服务 Java 应用 | Java、Go、Python 等都可以使用 |
| 关注点 | 程序调用接口和消息类型 | 客户端、Broker、路由和传输 |
| 代表性实现 | 一些 Java 消息中间件 | RabbitMQ 等 |
