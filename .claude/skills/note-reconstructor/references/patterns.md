# note-reconstructor：任务导向模式速查

本文件只提供可复用的表达模板。它不能替代 `SKILL.md`，也不能把可选格式变成强制要求。

## 顶层知识地图

````markdown
## 学习目标

## 总体任务

## 知识地图

```text
任务目标
  -> 模块 A：建立必要概念
  -> 模块 B：理解核心机制
  -> 模块 C：完成实现
  -> 模块 D：验证和优化
```
````

## 模块依赖表

```markdown
| 模块 | 类型 | 前置知识 | 解决的问题 | 输出能力 | 后续连接 |
|---|---|---|---|---|---|
| 基础概念 | 主线必学 | 无 | 建立共同语言 | 能解释核心对象 | 核心机制 |
| 性能优化 | 按需选学 | 核心机制、实现 | 处理规模或延迟问题 | 能做优化决策 | 扩展场景 |
```

## 任务驱动模块模板

```markdown
## 模块 N：模块名称

> **本模块要解决的问题**：...

### 模块目标
完成后，读者能够：...

### 前置知识
- [[前置模块]]：...

### 问题场景
...

### 核心概念
...

### 工作机制
输入：...
处理：...
输出：...

### 解决方案
1. ...
2. ...
3. ...

### 验证方法
...

### 与下一模块的关系
本模块产出的 ... 将作为 [[下一模块]] 的输入。

### 掌握检查
- 能解释 ...
- 能判断 ...
- 能完成一个最小任务：...
```

## 主线与按需选学

```markdown
### 主线必学
完成当前任务必须掌握的内容。

### 按需深入
当前任务不依赖，但在 ... 场景下有用。
```

只有在“按需深入”中的内容真正被用户要求或当前任务需要时，才展开完整推导、代码或工程细节。

## 渐进式讲解

```markdown
### 一句话结论
...

### 关键机制
用最短流程、公式或伪代码说明为什么可行。

### 完整细节
按需展开假设、推导、实现、验证和边界条件。
```

## 条件式视觉表达

```plaintext
只有在存在清晰的数据流、调用链或状态变化时使用：

输入
  -> 预处理
  -> 核心机制
  -> 输出
  -> 验证
```

使用规则：

- 知识地图和依赖表优先用 Markdown。
- 表格用于关系、对比和参数，不用于装饰。
- 类比只用于建立抽象概念的第一层直觉。
- Mermaid、HTML 卡片和复杂图形默认不使用。

## Obsidian 双向链接

```markdown
重构自：[[原始笔记]]
重构版：[[主题-总览]]
前置：[[主题-01-基础概念]]
后续：[[主题-03-实现方案]]
返回总览：[[主题-总览]]
```

## 重构版文件说明

```markdown
> **来源**：[[原始笔记]]
> **重构目标**：...
> **处理方式**：保留原笔记，当前文件为任务导向重构版。
```

## 过渡句

```markdown
到这里，我们已经知道了 ...，但还无法完成 ...。下一步需要引入 ...，因为它将把 ... 转化为 ...。
```

## 质量检查

```markdown
- [ ] 目标是可检查的任务，而不是泛泛的主题名
- [ ] 先有顶层地图，再进入细节
- [ ] 每个主线模块都有前置关系和输出能力
- [ ] 解决方案具体到可执行动作
- [ ] 无关知识没有被硬塞进主线
- [ ] 必要内容有验证方法和掌握检查
- [ ] 拆分笔记使用 Obsidian wikilink
- [ ] 原笔记未被默认覆盖
```
