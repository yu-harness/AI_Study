# Redis 缓存核心知识点

Redis 是一个开源的内存数据结构存储系统，常用作缓存、消息代理和数据库。

## Redis 基础数据结构

Redis 支持五种基本数据结构：String（字符串）、Hash（哈希）、List（列表）、Set（集合）、Sorted Set（有序集合）。

- **String**：最简单的类型，可以存字符串、数字或二进制数据，最大512MB。常用场景：缓存 HTML 片段、计数器。
- **Hash**：键值对集合，适合存对象。比 String 更省内存，可以单独读写某个字段。
- **List**：有序字符串列表，支持两端插入。常用场景：消息队列、最新消息列表。
- **Set**：无序唯一集合，支持交集并集差集运算。常用场景：标签系统、好友关系。
- **Sorted Set**：有序唯一集合，每个元素带 score 分数。常用场景：排行榜、延时队列。

## 缓存淘汰策略

当内存满时，Redis 根据配置的策略淘汰 key：

- **noeviction**：不淘汰，直接返回错误（默认）
- **allkeys-lru**：从所有 key 中淘汰最近最少使用的
- **allkeys-lfu**：从所有 key 中淘汰最不常用的
- **volatile-lru**：从设置了 TTL 的 key 中淘汰最近最少使用的
- **volatile-lfu**：从设置了 TTL 的 key 中淘汰最不常用的
- **volatile-ttl**：从设置了 TTL 的 key 中淘汰即将过期的

推荐使用 `allkeys-lru`，通常表现最好。

## 缓存读写策略

### Cache-Aside（旁路缓存）
这是最常用的策略：
- 读：先查缓存 → 命中直接返回 → 未命中查 DB → 写入缓存 → 返回
- 写：先更新 DB → 再删除缓存

### Cache-Aside 的问题
- 缓存穿透：查不存在的数据，每次都穿透到 DB。解决：布隆过滤器或缓存空值
- 缓存击穿：热点 key 过期，大量请求同时穿透。解决：互斥锁或永不过期
- 缓存雪崩：大量 key 同时过期。解决：过期时间加随机值、多级缓存

## Redis 持久化

- **RDB**：快照持久化，定期生成全量数据快照。优点：文件紧凑适合备份；缺点：可能丢数据
- **AOF**：追加日志，记录每次写操作。优点：数据更安全；缺点：文件大恢复慢
- 可以两者同时开启，Redis 重启时优先用 AOF 恢复

## Redis 应用场景

1. **会话缓存**：分布式 session 共享
2. **页面缓存**：缓存整个页面或片段，减少渲染
3. **计数器**：视频播放量、点赞数，INCR 命令原子操作
4. **消息队列**：List 的 LPUSH + BRPOP 实现
5. **排行榜**：Sorted Set 按分数排序
6. **分布式锁**：SETNX + Lua 脚本实现
