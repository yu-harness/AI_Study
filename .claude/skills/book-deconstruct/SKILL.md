# 拆书 —— 微信读书 + 渐进式阅读伴侣

通过微信读书 API 搜索书籍、拉取章节目录、同步阅读进度和个人笔记，生成一个**渐进式、不剧透、跟着阅读进度生长**的 Markdown 文件写入 Obsidian vault。

## 核心设计理念：渐进式阅读

**笔记不是一次性生成完就扔在那的——它跟着你的阅读进度生长。**

- 已读章节 → 完整展开（含读前回顾、脉络分段、表格总结、思考题）
- 正在读的章节 → 给出读前提示和关键问题引导
- 未读章节 → 只给一句话钩子，不展开，不剧透
- 金牌拆书 → 放末尾，标"读完全书后再回来看"
- 热门划线 → 只显示已读章节的

## 核心能力

1. **搜索书籍**：自动回退搜索策略（中文 → English → 作者名）
2. **🏆 金牌拆书**：8 段深度分析（一句话封神、作者背景、逻辑骨架、三大核心概念、三条实操原则、反常识时刻、读后变化、劝退指南）
3. **📋 阅读路线图**：告诉读者三部分分别怎么读、时间不够怎么取舍、当前位置进度条
4. **📖 章节拆解**：每章按「🧭 读前 + 🏃 脉络（分段）+ 📝 总结（表格）+ 🤔 思考」格式
5. **✨ 当前章节高亮**：正在读的章节给专属读前提示区
6. **🔒 无剧透**：未读章节只给一句话钩子，热门划线也只展示已读部分
7. **同步笔记**：拉取个人划线和想法到对应章节
8. **写入本地**：单文件 → `读书/书名.md`

## 微信读书 API 参考

### 鉴权与请求

- 统一入口：`POST https://i.weread.qq.com/api/agent/gateway`
- Header：`Authorization: Bearer $WEREAD_API_KEY`
- `WEREAD_API_KEY` 从环境变量获取，格式 `wrk-xxxxxxxx`；若未设置，提示用户设置
- Body：JSON，`api_name` + 业务参数平铺 + `skill_version: "1.0.4"`，**禁止用 `params` 包裹**

### 接口速查

| 接口 | 用途 | 关键参数 |
|------|------|----------|
| `/store/search` | 搜索书籍 | `keyword`, `scope` |
| `/book/info` | 书籍基本信息（含 intro、评分） | `bookId` |
| `/book/chapterinfo` | 完整章节目录（含层级 level、字数、付费） | `bookId` |
| `/book/getprogress` | 阅读进度（百分比+当前章节 UID） | `bookId` |
| `/book/bookmarklist` | 个人划线内容 + 章节映射 | `bookId` |
| `/review/list/mine` | 个人想法/点评 | `bookid`, `synckey` 翻页 |
| `/book/bestbookmarks` | 热门划线（全书固定 20 条） | `bookId` |
| `/review/list` | 公开书评（用于金牌拆书分析） | `bookId`, `reviewListType=1` |

### 字段备忘录

- **时间戳** → `YYYY-MM-DD`，时长（秒）→ `X小时Y分钟`
- **progress**：0-100 整数，1 表示 1%，100 才是读完
- **评分**：`newRating` 百分制
- **deepLink**：有则用，无则留空，不自行拼接
- **chapterUid**：连接划线到章节的关键字段

## 工作流

### 第一步：搜索书籍（自动回退策略）

```
策略 1：scope=10, keyword=<用户输入的书名>
   ↓ 无结果
策略 2：scope=0, keyword=<用户输入的书名>  
   ↓ 无结果
策略 3：scope=10, keyword=<英文书名>
   ↓ 无结果
策略 4：scope=6, keyword=<作者名>
   ↓ 无结果
告知用户：所有搜索策略均未找到，建议换个关键词
```

多结果时列出编号让用户选择。

### 第二步：并行拉取全部数据

拿到 `bookId` 后，**同一轮并行调用以下全部接口**：

```
/book/info          → 基本信息
/book/chapterinfo   → 完整章节目录
/book/getprogress   → 阅读进度
/book/bestbookmarks → 热门划线 Top 20
/book/bookmarklist  → 个人划线
/review/list/mine   → 个人想法（count=20）
/review/list        → 公开书评（reviewListType=1, count=10）
```

### 第三步：处理分页

`/review/list/mine` 的 `hasMore == 1` 时用 `synckey` 翻页直到 0。

### 第四步：构建映射表

从各接口的 `chapters[]` 建立 `chapterUid → title` 映射，将划线归属到对应章节。

### 第五步：生成「📋 阅读路线图」

放在笔记最前面（书籍简介之后），包含三个子板块：

```
## 📋 阅读路线图

### 🗺️ 这本书应该怎么读？
（三部分各自的阅读方式和关键度说明表格）

### ⏱️ 如果你时间有限
（1 小时 / 2 小时 / 充足时间 三种场景的阅读建议）

### 📍 你当前的位置
（ASCII 进度条：已读/正在读/未读的视觉展示）
```

### 第六步：生成「🏆 金牌拆书」

放在笔记**最后面**（同步信息之前），标注 ⚠️ 含全书剧透。8 段结构不变。

### 第七步：生成「📖 章节拆解」（核心）

**这是最重要的部分。每章的拆解必须严格按以下格式，不可压缩、不可跳过任何子板块：**

```markdown
### ✅ 已读：第 X 章 · 章节标题

#### 🧭 读前
（1-3 句话回顾上一章，点出本章的核心悬念。不给结论，只给方向。）

#### 🏃 脉络
（分 2-4 段，每段有小标题 + 展开叙述。不要只列要点，要讲故事——发生了什么、为什么重要、和前章什么关联。）

**第一段：小标题（时间范围）**
（展开叙述...）

**第二段：小标题（时间范围）**
（展开叙述...）

#### 📝 总结
（表格：时间段 / 核心成就或事件 / 关键洞察 / 一章金句 / 与前章关联）

#### 🤔 思考
（1-3 道思考题，基于本章内容设计，引导读者把书里的洞见映射到自己身上）
```

**脉络分段的黄金法则**：
- 自传类章节（第一部分）→ 按时间线分段，每段一个关键事件
- 方法论章节（第二、三部分）→ 按概念/原则分段，每段一个核心方法论
- 每段要有叙事张力：不只说"他做了什么"，还要说"为什么这么做"和"这导致了什么"
- 融入热门划线中最能代表该段落核心观点的句子
- 标注跨章节的因果关联："上一章的 X 在这里变成了 Y"

**正在阅读的章节**：标题前加 `📖`，拆解内容在用户读完之前用一句话占位，不展开。同时在上方新增「✨ 正在阅读」专区。

**未读章节**：统一放在「📑 未读章节速览」表格里，每章只给一句话钩子，不展开。

### 第八步：生成「💡 阅读引导」

- 已读章节的思考题跟随在章节拆解里（`.🤔 思考` 板块）
- 不建独立的「阅读引导」板块，避免内容重复

### 第九步：组装并写入文件

写入 `读书/书名.md`，先确保 `读书/` 目录存在。

**文件板块顺序**：
1. 书籍信息（frontmatter + 标题 + 简介）
2. 📋 阅读路线图
3. 📑 全书大纲（含进度标记）
4. ✨ 当前章节高亮（读前提示）
5. 📖 章节拆解（已读展开 + 未读速览）
6. 📝 我的笔记
7. 🔥 章节精华（热门划线，只显示已读章节）
8. 🏆 金牌拆书（含 ⚠️ 剧透警告）
9. 📊 同步信息

**章节进度标记规则**：
- 基于 `/book/getprogress` 的 `chapterUid`/`chapterIdx` 精确定位
- 之前的章节 `[x]`，当前章节 `[📖]`，之后的 `[ ]`
- 付费章节标 🔒

## 检查清单

生成前确认：
- [ ] 搜索回了完整回退链
- [ ] 7 个 API 并行调用（含 `/review/list`）
- [ ] 个人想法做了分页
- [ ] 📋 阅读路线图放在简介之后、大纲之前
- [ ] 每个已读章节按「🧭 读前 + 🏃 脉络分段 + 📝 表格总结 + 🤔 思考」完整格式展开
- [ ] 脉络分段有叙事张力，不是罗列要点，标注了跨章节因果
- [ ] 正在读的章节有「✨ 当前章节高亮」区
- [ ] 未读章节只有一句话钩子，不展开
- [ ] 热门划线只展示已读章节
- [ ] 金牌拆书放在末尾 + ⚠️ 剧透警告
- [ ] 时间戳 → `YYYY-MM-DD`，时长 → `X小时Y分钟`

## 异常处理

| 场景 | 行为 |
|------|------|
| 搜索全部策略无结果 | 告知用户，建议换关键词 |
| 某个 API 调用失败 | 跳过该板块，标注"数据暂未同步"，继续生成其他 |
| 公开书评为空 | 金牌拆书仅用简介+划线+目录生成，标注"基于书籍元数据" |
| 用户未设置 API Key | 提示 `export WEREAD_API_KEY=wrk-xxxx` |
| 回包有 `upgrade_info` | 暂停，按指引升级后重试 |
| 书名含特殊字符 | 清理为文件系统合法字符 |
