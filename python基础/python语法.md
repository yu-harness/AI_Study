## 第 1 讲：对象、名字与可变性（一切的地基）

### 核心思想：内存里只有"对象"，变量名只是贴上去的"标签"

```python
a = [1, 2, 3]     # 内存造了一个列表对象，把标签 a 贴上去
b = a             # 不是复制！是给【同一个对象】再贴一个标签 b
b.append(4)
print(a)          # [1, 2, 3, 4]  ← a 也变了，因为 a 和 b 指着同一个对象
```

但如果是**不可变对象**：
```python
a = "hi"
b = a            # 同一对象，两个标签
a = "hello"      # 不是改 "hi"，而是造了个新字符串，把 a 挪过去
print(b)         # "hi" ← b 还指着原来的
```
字符串没有"原地修改"能力，所以看起来"a 变了 b 没变"。**可变对象（list/dict/set）能原地改；不可变对象（int/str/tuple）不能改，只能换标签。**

### 推出①：函数传参 = 传引用（不是传值，也不是传引用副本）

```python
def add_one(lst):
    lst.append(99)     # 原地改 → 外面那个列表也被改了

x = [1]
add_one(x)
print(x)              # [1, 99]  ← 改了外面

def reassign(lst):
    lst = [999]       # 只是把局部标签 lst 挪到新对象 → 外面无感

y = [1]
reassign(y)
print(y)              # [1]  ← 没变
```
**面试黄金句**：Python 参数传递传的是"引用（标签）的绑定关系"。函数内 `对象.方法()` 会改原对象；函数内 `变量 = 新东西` 只是换局部标签，动不了外面。

### 推出②：三大高频面试题

**题 A：可变默认参数陷阱**
```python
def f(x, lst=[]):      # 默认 list 只创建一次，被所有调用共享！
    lst.append(x)
    return lst

print(f(1))   # [1]
print(f(2))   # [1, 2]  ← 不是 [2]！两次调用共用一个默认列表
```
本质：默认参数在 **def 执行那一刻**求值一次，之后每次调用都是同一个对象。**正解：默认用 `None`，函数内再建。**
看参数签名，它分两种：
- `x` —— **没有默认值** → 调用时**必须**给它，不给你就报错（`missing 1 required positional argument`）
- `lst=[]` —— **自带默认值 `[]`** → 调用时**可以不给**，不给就用默认的空列表


**题 B：`is` vs `==`**
```python
a = [1, 2]; b = [1, 2]
a == b   # True  ← 比内容
a is b   # False ← 比"是不是同一个对象"

x = 5; y = 5
x is y   # True（小整数 -5~256 被解释器缓存，俩标签贴同一个对象）
```
本质：`==` 问"值一样吗"，`is` 问"是同一个东西吗"。
```python
a = [1, 2]
b = [1, 2]

print(id(a))   # 比如 140489334328896
print(id(b))   # 比如 140489334329088   ← 不同！是两个对象

a is b         # False ← 不是同一个对象
a == b         # True  ← 但内容一样

```


**题 C：为什么 `append` 和 `+` 表现不同**
```python
a = [1]; b = a
a += [2]     # list 的 += 是原地扩展 → a 和 b 都变 [1,2]
# 但 str/int 的 += 是"换新对象"→ 另一标签不变
```
本质：`+=` 对可变对象走原地，对不可变对象走"新建+换标"。

### 第 1 讲收尾

> 记住根：**对象在内存里是"实体"，名字是贴上去的标签；`=` 永远只是贴标签。** 可变/不可变决定了"原地改"还是"换标签"。这两句话能解释传参、默认参数、`is` vs `==`、`+=` 几乎所有坑。

## 一、名字的搜查路线：LEGB

函数里用了一个名字，Python 按固定顺序一层层往上找：

```
L  Local        当前函数内部
E  Enclosing    外层函数（嵌套时）
G  Global       模块级（当前 .py 文件）
B  Built-in     Python 内置名字（len、print…）
```

```python
x = "global x"              # G 层

def outer():
    x = "outer x"           # E 层（对 inner 来说）
    def inner():
        print(x)            # inner 里没定义 x → 向上找到 outer 的
    inner()

outer()   # outer x
```

**面试一句话**：Python 名字查找是"由内向外"，就近原则，找到第一个就停。

## 二、关键坑：一赋值，就"叛变"到本层

先看这个经典报错：

```python
x = 10                       # G 层

def f():
    print(x)                 # 想读外面的 10？
    x = 20                   # 但函数内给它赋值了……

f()   # UnboundLocalError: local variable 'x' referenced before assignment
```

为什么会报错而不是打印 10？

**本质：名字的归属在"编译期"就定了，不是运行期。** Python 看到函数内任何地方给 `x` 赋值了，就提前把整个函数里的 `x` 都判定为"局部变量"。于是上面的 `print(x)` 读的是"还没赋值的局部 x"，直接报错。

> 记住：**函数内只要出现 `x = ...`，这个 `x` 从此就是局部的**——哪怕赋值写在后面。

想突破这条规矩，用两个关键字：

| 关键字          | 作用          | 场景         |
| ------------ | ----------- | ---------- |
| `global x`   | 声明 x 用模块级的  | 直接改模块级变量   |
| `nonlocal x` | 声明 x 用外层函数的 | 嵌套函数里改外层局部 |

## 三、闭包：函数带走的"环境背包"

```python
def make_adder(n):          # n 是参数
    def add(x):             # 内部函数"记住"了 n
        return x + n
    return add              # 把 add 交出去

add5  = make_adder(5)
add10 = make_adder(10)

print(add5(3))    # 8    ← 5+3
print(add10(3))   # 13   ← 10+3
```

`make_adder(5)` 已经执行完了，`n` 按理说该消失了——但 `add5` 还能用 `n=5`。为什么？

**本质：函数对象不只有代码，还带一个"环境背包"（`__closure__`）。** 每次调用 `make_adder` 都会新建一个装着 `n` 的背包，随内部函数一起被带走。`add5` 背的是 `n=5` 的背包，`add10` 背的是 `n=10` 的背包，互不干扰。

> 把定义环境"关"进去随函数带走，就叫**闭包（closure）**。

配合 `nonlocal` 还能改造背包里的值——计数器：

```python
def counter():
    count = 0
    def inc():
        nonlocal count      # 声明：去外层背包里改这个 count
        count += 1
        return count
    return inc

c = counter()
c()   # 1
c()   # 2
```

不加 `nonlocal` 就会报错——因为 `count += 1` 里的赋值让 count 被判成本地变量了。

## 四、真题收尾：为什么全是 3？

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])   # 输出多少？
```

直觉可能是 `[0, 1, 2]`，实际是 **`[2, 2, 2]`**。

**本质剖析（结合刚讲的背包）**：

1. 循环变量 `i` **自始至终只有一个**，是同一个变量；
2. 三个 lambda 的背包里，装的不是"当时 i 的值"，而是 **`i` 这个变量本身**（引用）；
3. 它们只在**被调用时**才现去查 `i` 现在等于几；
4. 等循环跑完，`i` 停在 `2`，三个函数一调用，查到的全是 `2`。

> **闭包记住的是"变量"（引用），不是"值"。取值是调用时现取的。**

修正方案——用默认参数当场"抓拍"：

```python
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])   # [0, 1, 2]  ✓

# 等价写法，便于看清：
for i in range(3):
    funcs.append(lambda i=i: i)   # i=i：把当前的 i 值立刻定给参数 i
```

为什么有效？因为**默认参数在 `def` 执行那一刻就求值**。`i=i` 把循环"当时的值"瞬间绑定成新参数 `i`，lambda 体里用的是这个参数，不再去外层背包查那个会变的 `i` 了。

> 本质一句话：**"默认参数 = 当场抓拍快照" vs "闭包 = 事后去查现值"。**
