# 第三章 闭包和装饰器

按黑马《大模型 Python 语言进阶》第三章的目录顺序整理。

## 1 闭包的背景

先看一个现象：

```python
def fn_outer():
    a = 10

fn_outer()
print(a)        # NameError: name 'a' is not defined
```

`a` 只在函数执行的那段时间里存在。函数一返回，这块局部空间就回收了，外面拿不到它。**函数执行完，里面的变量就销毁**，这就是那个现象。

**疑问**

**有时候正需要把这个变量留下来，还要在它的基础上反复做运算**。比如每次调用都往上累加一点，最后把总数拿回来。这时候就撞上刚才那个问题：变量跟着函数一起没了。

不用闭包的老办法是全局变量，问题是全局变量谁都能改，多个函数共用一份，容易互相干扰。还有一种办法是把值一路传参、一路返回，调用方得自己保管，代码会越写越长。

**用返回值试一试**

```python
def func():
    num = 10
    return num

num = func()
print(num + 1)    # 11
print(num + 1)    # 11
```

两次都打印 11。`num` 只是那次调用的返回值，加完的结果没有存回 `num` 里，所以第二次还是从 10 开始。想让它攒起来，只能自己补一行 `num = num + 1`；代码一长，或者换个人接手，这一行很容易漏掉。

这就是刚才那个疑问的具体样子：变量留不住，累加就留不住。

闭包给出第三种做法：**把变量藏在外层函数的局部作用域里，只让内层函数看见**。

## 2 闭包要满足的三个条件

课件的定义：在函数嵌套的前提下，内部函数使用了外部函数的变量，并且外部函数返回了内部函数，这个用到外部变量的内部函数就叫**闭包**。

也就是三条：

1. **有嵌套**：函数里面**再定义函数**。
2. **有引用**：内部函数**使用了外部函数的变量**，外部函数的参数也算。
3. **有返回**：外部函数**返回了内部函数名**。

三条同时满足才是闭包。少一条，变量就会被正常回收。

**语法模板**

```python
# 外部函数
def 外部函数名(外部参数):
    # 内部函数
    def 内部函数名(内部参数):
        ...              # 这里使用外部函数的变量
    return 内部函数名    # 返回出去的就是闭包
```

模板里的参数**可有可无**，看需要：外层要接一个初始值就带参数，内层要接调用时的输入就带参数，都不需要就留空括号。

**案例：求和的闭包**

```python
# 需求：定义求和的闭包，外部函数有参数 num1，内部函数有参数 num2，
# 调用后求两数之和，观察结果。

# 1. 定义外部函数
def fn_outer(num1):
    # 2. 定义内部函数
    def fn_inner(num2):                # 有嵌套
        # 3. 求和
        sum = num1 + num2              # 有引用
        print(f'求和结果: {sum}')
    return fn_inner                    # 有返回


# 4. 调用上述的函数
fn_inner = fn_outer(10)
fn_inner(20)                           # 求和结果: 30
print('-' * 23)

fn_outer(100)(200)                     # 求和结果: 300
```

**这个例子的内存样子**

`num1` 存在哪，为什么两次调用都拿得到 10：

![[闭包-内存分布.svg|704]]


调用结束后，那几块临时区域会清掉；函数对象留在方法区，`fn_inner` 的函数体又引用着 `num1`，于是 `num1 = 10` 跟着函数对象一起活下来。闭包在内存层面就是这么回事：**临时区域会清，函数对象不清，被它引用的变量跟着留下**。

## 3 nonlocal：修改外层变量

前面的案例只是读 `num1`，读的时候不用写任何声明。要**改**外层变量，必须先声明：

```python
def fn_outer():
    a = 100

    def fn_inner():
        nonlocal a          # 声明：下面改的是外层那个 a
        a = a + 1
        print(f'a: {a}')

    return fn_inner


fn_inner = fn_outer()
fn_inner()      # a: 101
fn_inner()      # a: 102
fn_inner()      # a: 103
```

三次调用依次得到 101、102、103，说明 `a` 一直跟着这个闭包，没有被重新初始化。

前两次为什么是 101 和 102，而不是都从 100 起算，看内存：

![[闭包-nonlocal内存.svg|796]]

**不加 nonlocal 会怎样**

`a = a + 1` 里的 `a` 会被当成「在 `fn_inner` 里新建的局部变量」，等号右边要用它时还没赋值，直接抛：

```text
UnboundLocalError: cannot access local variable 'a' where it is not associated with a value
```

**为什么读的时候不用声明**

Python 找变量按四层顺序：**局部、外层函数、模块全局、内置**。读的时候一层层往上找，外层有就直接用；一旦某行出现赋值，这个名字就被记成局部变量，不再往外找，所以才需要 `nonlocal` 说明「它是外层的」。


## 4 函数名与函数名()

```python
def get_sum(a, b):
    return a + b

print(get_sum)                 # <function get_sum at 0x...>，是函数对象
print(get_sum(a=10, b=20))     # 30，是调用之后拿到的返回值
```

- **不带括号**：拿到的是函数对象本身，可以赋给别的名字，也可以当参数传出去。
- **带括号**：立刻执行一次，拿到的是返回值。

**函数名可以赋值给变量**

```python
my_sum = get_sum               # 不加括号，把函数对象交给另一个名字
print(my_sum)                  # <function get_sum at 0x...>，同一个对象
print(my_sum(a=100, b=200))    # 300，两个名字都能调用
```

## 5 闭包总结

**1. 闭包的作用是什么？**

保存函数里的变量，也就是外部函数的变量，让它不随外层函数返回而消失。

**2. 闭包的语法格式？**

```python
# 外部函数
def 外部函数名(外部参数):
    # 内部函数
    def 内部函数名(内部参数):
        ...              # 使用外部函数的变量
    return 内部函数名    # 返回出去的就是闭包
```

外层定义内层、内层用外层变量，最后 `return 内层函数名`，这一行不带括号。参数可有可无，看要不要接初始值。

**3. 构成闭包的条件？**

有嵌套、有引用、有返回，三条齐全。

**4. `nonlocal` 关键字的作用？**

声明这个变量来自外层函数，**让内部函数能改它**。不写的话，内层会把赋值当成新建一个自己的局部变量，外面那份一直不动。

## 6 装饰器

装饰器的作用：**不改变原有函数，给它增加额外功能**。它本质上就是一个**闭包函数**。

大白话讲，装饰器像装修队：房屋结构不动，只做装饰，装完还是那间房，功能变强了。

**四个条件**

1. **有嵌套**：函数里面再定义函数。
2. **有引用**：内部函数使用了外部函数的变量，外部函数的参数也算。
3. **有返回**：外部函数返回了内部函数名。
4. **有额外功能**：给需要装饰的那个原有函数增加功能。

前三条和闭包完全一样，第四条是**装饰器多出来的**。闭包只负责把变量留住，装饰器还要在调用原函数的前后做事。

**例子：传统方式**

```python
def check_login(fn_name):              # fn_name 是被装饰的函数对象
    def fn_inner():                    # 有嵌套
        print('校验登陆... 登陆成功!')   # 有额外功能
        fn_name()                      # 有引用
    return fn_inner                    # 有返回


def comment():
    print("发表评论")


def payment():
    print('充值中...')


# 传统方式：先装饰，再调用
comment = check_login(comment)
comment()
```

输出两行：

```text
校验登陆... 登陆成功!
发表评论
```

换一个函数照样能用，`check_login(payment)()` 会先校验再打印「充值中...」。一个装饰器写好，所有需要登录的函数都能套。

**语法糖写法**

在要装饰的函数定义前写一行 `@check_login`，之后直接调原函数名：

```python
@check_login
def comment():
    print("发表评论")

comment()      # 调的就是被装饰后的版本
```

两种写法效果完全一样。`@check_login` 就是 `comment = check_login(comment)` 那行赋值的简写：把原函数传进去，拿回加工过的函数，再赋给同一个名字，所以调用方式一点没变。

## 7 可变类型与不可变类型

**不可变对象**：一旦创建就不能修改。字符串、元组、数值类型（整型、浮点型）都属于这一类。它指向的那块内存里的值改不了，所以「改」的时候相当于把原来的值复制一份再改，于是开出一块新地址，变量转向新地址。

**可变对象**：可以修改。列表、字典、集合属于这一类。它指向的那块内存里的值能直接改，改完不复制、不开新地址，变量还指着原来那块，通俗说法就是原地改。

**怎么验证**

判断标准只有一条：改完之后 `id()` 变不变。

```python
s = "abc"
print(id(s))       # 例如 1402451823...
s = s + "d"
print(id(s))       # 变了，新开了一块

lst = [1, 2]
print(id(lst))     # 例如 2109301842...
lst.append(3)
print(id(lst))     # 没变，还是原来那块
```

**一条容易错的线**

元组不可变，但里面装着可变元素时，那个元素本身还能改：

```python
t = (1, [2])
t[1].append(3)
print(t)           # (1, [2, 3])
```

元组约束的是「这几个位置各指向谁」，指向的列表里面怎么变，它管不着。

**对函数传参的影响**

```python
def add_item(lst):
    lst.append(4)          # 改的是外面那个 list


def add_num(n):
    n = n + 1              # 只是让局部的 n 指向新对象


nums = [1, 2, 3]
add_item(nums)
print(nums)                # [1, 2, 3, 4]

x = 1
add_num(x)
print(x)                   # 1
```

传列表进去，函数里的修改外面看得到；传数字进去，函数里怎么加，外面那个 `x` 还是 1，因为数字不可变，函数里的 `n` 早就指向了另一个对象。

**和拷贝的关系**

浅拷贝、深拷贝只在可变对象上才有区分：不可变对象每次「改」都是新建，不存在「复制一份再改」这一步。

## 8 引用与浅拷贝

**变量赋值的执行原理**

写 `a = "python"`，Python 解释器做三件事：

1. 创建变量 `a`，此时它只是个名字。
2. 创建一个对象，分配一块内存存 `"python"`。
3. 用指针把变量与对象连起来。这条连接叫**引用**，变量引用对象。

所以变量本身不装值，装的是对象的地址。`a` 更像一张标签，贴在对象上。

![[引用-变量与对象.svg|685]]

**普通赋值，两种类型都一样**

```python
def 普通赋值():
    # 不可变类型
    a = 10
    b = a
    print(id(a), id(b), id(10))    # 三个是同一个地址

    # 可变类型
    a = [1, 2, 3]
    b = [11, 22, 33]
    c = [a, b]
    d = c
    print(id(c), id(d))            # 仍是同一个地址
```

赋值只是多起一个名字，对象还是原来那一个。`d = c` 之后改 `d[0]` 里的元素，`c` 也跟着变，因为两个名字说的是同一个 list。`id(10)` 与 `id(a)` 相同，是因为小整数在 Python 里被缓存，同一个 10 只有一个对象。

赋值和拷贝不是一回事：赋值只是多了个名字，拷贝会新建出一个对象。

**浅拷贝是什么**

定义：创建一个新对象，内容是**原对象的引用**。

它只拷一层：最外层的容器是新的，里面的每个元素只是把引用抄了一份，没有复制元素本身。

原始数据这样准备：

```python
a = [1, 2, 3]
b = [11, 22, 33]
data = [a, b]          # data 两格里存的是两个 list 的地址
```

按地址看：`a` 指向 0x11 那块，`b` 指向 0x22 那块，`data` 里两格分别存着 0x11 与 0x22。

![[浅拷贝-原始数据.svg|703]]

现在浅拷贝一份：

```python
import copy

data2 = copy.copy(data)

print(data2 is data)   # False，外层确实是新对象
print(data2[0] is a)   # True，内层还是原来那个 list
```

**改内层会一起变，改外层不会**

```python
data2[0].append(4)
print(a)               # [1, 2, 3, 4]，两个容器共用同一个内层 list

data2[1] = [7, 8]
print(b)               # [11, 22, 33]，换掉外层那一格不影响原来的 b
```

`data2[0]` 与 `data[0]` 存的是同一个地址，所以往里加元素两边都看得见；`data2[1] = ...` 只是把 `data2` 自己那格改成新地址，`data` 那格没动。

**深拷贝**

`copy.deepcopy()` 会把里面的元素也各复制一份，连里层的列表都是新的：

```python
import copy

data3 = copy.deepcopy(data)

print(data3 is data)       # False
print(data3[0] is a)       # False，内层也换成了新的 list

data3[0].append(9)
print(a)                   # [1, 2, 3]，不受影响
```

浅拷贝只换外层，深拷贝连里层一起换，两者的差别就这一处。

**三条要记住的**

- 浅拷贝是 `copy.copy()`，深拷贝是 `copy.deepcopy()`，两个都在 `copy` 模块里。
- 大白话：深拷贝抄得多，浅拷贝抄得少。
- 深浅拷贝只对可变类型才有区分。不可变类型上，它们和普通赋值一个样，`copy.copy(s) is s`、`copy.deepcopy(s) is s` 都是 True。
