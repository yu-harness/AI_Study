## 一句话结论

这是第一篇系统整理大模型智能体记忆机制的综述：把散落在各篇论文里的记忆设计，统一成「**来源、形态、操作**」三个维度（外加「**直接评估、间接评估**」两条评估路线），并给出一个把**写入、管理、读取**三个算子串起来的统一公式。

## 这篇综述想解决什么问题

记忆机制的研究散落在不同论文里，各写各的实现，缺一个能**横向比较的框架**，也抽象不出共同的设计规律。作者要做的就是补齐这一层：先把「是什么」「为什么需要」讲清，再系统梳理「怎么设计、怎么评估」，最后给应用场景与未来方向。

## 三个基本问题

这篇综述的骨架就是三问：

```text
什么  → 智能体的记忆指什么（狭义与广义两种定义）
为什么 → 认知心理学、自我进化、实际应用三个角度
怎么   → 怎么设计（来源 / 形态 / 操作）与怎么评估（直接 / 间接）
```

## 定义：狭义与广义

**狭义定义**：记忆只涉及同一次试验（trial）内的历史信息，也就是**第 t 步之前的动作与观测序列**；这次试验一结束，记忆就清空。

**广义定义**：记忆的来源更宽。给定一串任务，某个任务第 t 步的记忆来自三处——**同一次试验内的历史**、**跨试验的历史**（含本任务此前失败过的尝试）、以及**交互之外的外部知识**。

**两者的分界就是「记忆能不能活过一次试验」。** 狭义对应工作记忆，广义对应长期记忆。

## 统一公式：三个算子

作者把所有实现都归到三个算子上，公式可以读成「动作 → 写入 → 管理 → 读取 → 下一个动作」：

```text
下一步动作 = 大模型{
    读取(
        管理( 上一步记忆, 写入( { 本步动作, 本步观测 } ) ),
        下一步的上下文
    )
}
```

- **写入（W）**：把原始观测投影成**真正存下来的内容**，可以存原文，也可以存摘要
- **管理（P）**：对已存内容做加工，让**记忆更有效**
- **读取（R）**：按下一步动作的上下文，从记忆里**取出有用的部分**，拼进 prompt

**这个框架的价值在于能把不同论文的实现对上号**：有的工作让读取和管理用同一个函数、且只在试验结束时生效；有的工作把管理实现成反思，把读取实现成相似度加时间间隔加重要性三项打分。方法名字不同，落到这三个算子上位置是清楚的。

## 为什么需要记忆：三个角度

**认知心理学角度**：记忆是人学习知识、形成社会规范、做出合理行为的基础。智能体的目标之一是替代人完成任务，因此按**人的工作机制**来设计记忆是自然选择；心理学本身积累了大量的记忆理论与架构可以直接借用。

**自我进化角度**：记忆支撑三件事——**经验积累**（记住过去的错误规划与失败经历，提升后续相似任务的效率）、**环境探索**（依据历史决定何时探索、探索哪里，例如更关注失败过的尝试或探索次数少的动作）、**知识抽象**（把原始观测总结成高层信息，这是适应新环境的基础）。

某些应用里，没有记忆任务直接跑不成。
- **对话类**：语言的指代与省略依赖历史。用户问「加拿大有多少人」，再问「他们的国歌叫什么」，这个「他们」只能从历史里取。没有记忆，agent 只能反问一句，对话断开
- **角色与模拟类**：人设是一堆散在过去交互里的事实——身份、经历、关系、已经许过的承诺。记不住就会前后不一致，论文用的说法是走出角色（step out of the role），这类应用里这等于任务失败
- **共同的职责**：决定当前这一步有哪些信息必须出现在 prompt 里。上下文装不下全部历史，记忆负责把「这一步必须知道的」挑出来

和前两条的分工：认知心理学回答「凭什么像人一样记忆」，自我进化回答「记忆怎么让 agent 越用越强」，这一条回答「不用记忆会当场翻车」。判断标准一句话：信息需求超过单轮能塞下的量，或需要跨会话延续，记忆就是必需品。

## 怎么做之一：记忆来源（三处）

判断标准是「记忆内容从哪来」。前两处在交互过程中动态产生，第三处在循环之外。

**一，试验内信息（inside-trial）**：同一次试验里的**历史动作与观测，还包括时间、地点这类交互上下文**。最直接、最相关，几乎所有工作都会用。代表工作是**日常行为模拟、对话历史、自生成多条思考、以及游戏里可执行的基础动作代码**。局限是只用这一处，跨任务积累不出可复用的知识。

**二，跨试验信息（cross-trial）**：多次试验（含其他任务）累积的成功与失败动作，以及从中得到的洞察，比如**失败原因、常见成功模式**。代表工作是 Reflexion（把经验写成自然语言用于后续尝试）、Retroformer（微调反思模型来更好提取跨试验信息）、Synapse（把成功样例当参考）、ExpeL（存轨迹、召回相似轨迹并对比成功与失败找规律）。这一处相当于长期记忆；局限是仍然要求智能体亲自与环境交互，外部经验与知识进不来。

**三，外部知识（external knowledge）**：环境之外、以文本形式或通过工具与数据库取得的知识，来源可以是公开或私有，实时调用还能缓解知识过时。代表工作是 **ReAct**（查 Wikipedia）、GITM（游戏 Wiki 与合成配方）、CodeAgent（网页搜索代码依赖与文档）、ChatDoctor（医学数据库检索）。价值是突破自身交互的边界，拿到**大量、最新**、有出处可查的知识。

**作者用一张表把 28 个模型按这三处逐项标注**，一眼能看出多数工作只用了第一处。

## 怎么做之二：记忆形态（文本与参数化）

**文本形态**：显式保留，用自然语言召回，内部再分四类。

- **完整交互**：把全部交互历史留下来，靠长上下文能力承载。问题有三处：注意力计算随长度二次增长，算力与延迟高；超出预训练长度要截断，信息会丢；长上下文里内容的位置会影响使用，结果不够稳
- **最近交互**：只留最近的**记忆窗口**，思路是「就近原则」。代表是分层的快慢两级的做法、以及把上下文当操作系统的做法。问题是在长任务里取不到远处关键信息
- **检索到的交互**：按**相关性、重要性或主题检索**。写入时生成向量索引并记下辅助信息，读取时算匹配分取前 K 条；有的工作用 SQL 检索符号化的记忆。问题是**依赖检索质量与效率**，重型检索系统算力与延迟高，而且更适合同质信息
- **外部知识**：通过调用工具与接口把外部知识转成自身记忆。问题是外部信息可能有误与偏见，跨上下文的理解成本高，接口还涉及隐私与合规

**参数化形态**：把记忆编码进模型参数，不受 prompt 长度限制，但研究得还不够。

- **微调**：把领域知识灌进参数。好处是弥补通用模型与专用模型的差距，在专业任务上有效。问题是容易过拟合与灾难性遗忘、成本高、多为离线完成，难以应付逐步交互的在线场景
- **记忆编辑**：只精准改动需要变更的事实，不动无关知识。成本低，可用于在线场景；对智能体来说，它也可以当作一种「遗忘」机制。问题是元训练成本高，如何保护无关记忆仍是难题

**两种形态的三个维度对比**（作者的原话值得记住）：

- **效果**：文本更全面细致，但受 token 限制，存不了太多；参数不受长度限制，但文本转参数有信息损失
- **效率**：文本每次推理都要把记忆并进上下文，写起来容易但读起来贵；参数省掉上下文开销，读起来快但写起来贵。一句话概括：文本记忆写更高效，参数记忆读更高效
- **可解释**：文本人类可读，参数在隐空间；但文本的可解释性以信息密度为代价

**选择建议**：需要回忆近期交互（对话、上下文相关的任务）用**文本记忆**；需要承载大量记忆或成型知识**用参数化记忆**。

## 怎么做之三：记忆操作（写、管、读）

**写入**：把感知到的原始信息投影成实际存储内容，可以存原文也可以存摘要，关键是判断「**哪些信息值得存**」。代表做法有**抽取实体关系**存进结构化库、由**控制器**决定何时执行操作、完全自主地由模型自己更新、以及对每段对话做话题摘要当作索引。

**管理**：三个子操作，都受人类大脑工作机制的启发。
- **反思（reflection）**：从已有记忆里生成更高层的结论，例如把对话蒸馏成日事件摘要与人格洞察，或者积累足够事件后生成抽象想法
- **合并（merging）**：合并冗余条目，例如把多个计划里的关键动作归并成一份**通用参考计划**
- **遗忘（forgetting）**：丢掉不重要或早期的记忆，**去掉负面影响**

**读取**：按任务导向的因素从海量记忆里取有用信息。可以先生成查询语句再检索，可以从记忆池里按样例忽略某些记忆，也可以按向量相似度取前 K 条。读写是协同的：写入的形态决定了读取的方式；参数化记忆的读取是隐式的，直接用更新后的参数推理。

## 怎么评估：直接与间接两条路

**一，直接评估**（单独衡量记忆模块本身）

- **主观评估**：看两方面——**连贯性**（召回的记忆是否自然、是否与当前上下文矛盾）与**合理性**（召回的记忆是否讲得通）。执行时要定两件事：评估者怎么选（要熟悉任务且背景多样，减少偏倚）、怎么标注（直接打分量表，还是两两比较）。优点是适用面广、能给出理由；缺点是人力和偏倚成本高，难复现、难横向比较
- **客观评估**：三类数值指标——**结果正确性**（按预置问题比对标准答案算准确率）、**引用准确性**（检索出来的中间记忆是否匹配预置的标准记忆，常用 F1）、**时间与硬件成本**（总时间分成记忆适配与推理两段，算力开销看显存峰值）

**二，间接评估**（通过端到端任务完成情况看记忆有没有用），四类任务：

- **对话**：看一致性（回复是否与上下文一致）与参与度（用户是否愿意继续聊）
- **多源问答**：同时用上试验内、跨试验与外部知识，能暴露多源记忆互相矛盾与知识更新的问题
- **长上下文应用**：长文检索与长文摘要两类任务，用 ROUGE 这类匹配分数
- **其他任务**：成功率（空间任务、游戏物品制作、代码题、计算机控制）与探索程度（探索到多少不同物品）

**作者的判断**：**间接评估更容易做**，公开基准多，但结果受多个因素混淆、容易有偏；直接评估更可靠，但目前还没有专门面向智能体记忆模块的开源基准。此外，几乎所有记忆类工作都会做「**有记忆与无记忆**」的对照实验——这一点和你项目里的三档对照实验思路一致。

## 这份综述的独特点

- 自称为首篇针对大模型智能体记忆机制的综述
- 用写入、管理、读取三个算子把不同实现统一到同一个公式下，于是可以横向比较
- 三个维度（来源、形态、操作）彼此正交，构成一张能落坐标的分类网
- 评估单独成章，分成直接与间接两路，并指出各自的可靠性与成本差异
- 用三张表对 28 个模型逐项标注，另外单设一章对已有的大模型与智能体综述做定位

## 局限与未来方向（作者列的四条，每条自带对应方向）

- **参数化记忆还太弱**：现在以文本记忆为主，效率不如参数化。方向是提高文本转参数的效率、探索元学习式的参数修改；难点是参数记忆缺可解释性，在医疗这类高信任领域尤其突出
- **多智能体场景下的记忆**：记忆同步（统一知识库、决策一致）、通信（记忆驱动的通信框架）、信息不对称（竞争场景）都是新问题，需要有新的记忆模块设计
- **基于记忆的终身学习**：记忆要能长期存储与应用历史观测，需要刻画时序性、需要应对海量记忆的按需检索，也需要遗忘机制
- **类人智能体的记忆**：能力应模仿人而非越强越好，因此记忆要符合人类认知过程（记忆扭曲、遗忘等），并具备「知识边界」——扮演小孩的智能体不该掌握超出年龄的数学知识

## 与 Tether 现行做法的对照

拿这三维给 Tether 的记忆层定位，坐标很清楚：

- **来源**：只用试验内信息。跨试验信息与外部知识都没有，恢复会话时也只能看到同一任务的历史
- **形态**：纯文本形态，落在「最近交互」与「检索到的交互」之间——清单与摘要属于最近交互，跨轮笔记属于按相关性检索
- **操作**：写入有，但写入权收在工具执行这一步；管理只有隐式的部分（上限截断相当于遗忘、指纹失效相当于作废），没有反思与合并；读取是轻量的相似度加时间衰减
- **评估**：走的是间接评估路线（端到端任务加开关对照），没有直接评估，也就是没有引用准确性、记忆适配耗时这类针对记忆本身的指标

**可以直接借用的三处**：

- **重要性维度**：经典记忆流打分用相关性、近期性、重要性三项，Tether 的排序表只有相关性（标签与关键词）和近期性（时间、编号），缺重要性这一维
- **反思（reflection）**：把若干条零散笔记抽象成一条更高层的结论，这是当前笔记区最缺的一步——现在每条笔记都是孤立的一句话
- **显式遗忘**：现在只有「超过上限就丢掉最早那条」，没有按重要性或访问频次决定遗忘

**这份综述没给出答案、但和你项目直接相关的一处**：多智能体场景下的记忆同步（对应你项目里的 delegate 子智能体）。子智能体查完只回一段摘要，主智能体的记忆里不会留下它探索的过程，这正好是综述里「信息同步」那一节的问题。
