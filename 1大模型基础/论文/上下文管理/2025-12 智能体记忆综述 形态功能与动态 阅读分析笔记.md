## 一句话结论

这篇综述认为「长期记忆与短期记忆」这套分法已经装不下 2025 年之后的方法，于是改用三个视角重看记忆：**形态（forms）** 问记忆住在哪里，**功能（functions）** 问为什么需要它，**动态（dynamics）** 问它怎么形成、怎么演化、怎么被取回。

## 这篇综述要解决什么

**两个动机。**

- **旧分类不够用**：2025 年前后出现的新做法在旧框架里放不进去。作者举的例子有「从过往经验里提炼可复用工具的记忆框架」与「记忆增强的测试时扩展」，这两类在按时间划分的分类里都找不到位置
- **概念碎片化**：大家都说自己在研究 agent memory，但实现、目标、假设差异极大；术语还在不断增殖——declarative、episodic、semantic、parametric memory 并存，反而把概念搞得更糊

**目标**：立起一套统一框架，调和已有定义、接上刚出现的趋势、说清记忆在智能体系统里的基本原理。

**三个视角的分工**：

- **形态（forms）**：记忆以什么结构承载，有哪些实现方式
- **功能（functions）**：为什么需要记忆，它扮演哪些角色
- **动态（dynamics）**：记忆如何随时间形成、演化、被取回

## 第一部分：术语与边界

### 怎么形式化一个智能体

先把环境与交互写成一套符号，后面所有讨论都挂在这套符号上：

- 智能体集合 I，只有一个成员就是单智能体，多于一个就是多智能体（辩论、规划者与执行者这类）
- 环境由状态空间刻画，状态按受控随机过程转移
- 每个智能体拿到的观测来自三样东西：环境状态、它自己可见的那部分交互历史、以及任务说明
- **任务说明（task specification）** 包含用户指令、目标描述与外部约束，在一次任务内视为固定
- 动作空间是异构的：不止文本生成，还包括调用工具、规划动作、控制环境、与其他智能体通信
- 策略写成动作等于「在观测、记忆信号、任务说明给定下」的输出，也就是说记忆是策略的一个输入项
- 一次完整执行导出轨迹：状态、观测、动作依次交替，直到终止条件满足

### 怎么定义智能体记忆

作者没有给记忆规定具体的内部结构，只把它写成**一个随时间演化的记忆状态**，它可以是一段文本缓冲、一个键值存储、一个向量库、一张图，或者任意混合形式。

三个算子：
- **形成（formation）**：这一步产生的信息碎片（工具输出、推理痕迹、局部计划、自评、环境反馈）被选择性地转成记忆候选。重点是抽取**对将来有用**的部分，而不是逐字保存整段交互
- **演化（evolution）**：把新候选整合进记忆库——合并冗余条目、消解冲突、丢弃低价值内容、重排结构以便检索。结果是跨决策步、跨任务持续存在的状态
- **检索（retrieval）**：按当前上下文与任务说明构造查询，取回相关记忆，整理成可直接使用的文本片段或结构化摘要，作为策略的输入

**这里有一个很关键的判断**：这三个算子不需要每一步都调用。有的系统只在任务开始时检索一次，之后再不检索；有的间歇触发，有的持续触发。所以长期与短期的差别来自**算子被调用时机的模式**，并没有两个彼此独立的存储模块。作者明确反对把长短期当成两个架构部件。

**记忆与智能体的耦合方式**：智能体的每一步是这四件事交织起来的——观察环境、可选地检索记忆、让模型计算、执行动作并推动下一次状态转移。检索被禁用时，记忆信号可以看成一个特定的空值。

### 三组边界对比

#### 一，智能体记忆与 LLM 记忆

- 高层判断：智能体记忆几乎把传统所说的 LLM 记忆整个装了进去
- 依据：2023 到 2024 年社区对「什么算 LLM agent」没有稳定共识——有人让模型调个计算器就算，有人要求规划、工具使用、记忆、反思都齐。现在趋于统一：语言模型加推理、规划、记忆、工具使用、自我改进、多轮交互、感知
- 所以 MemoryBank、MemGPT 这类自称 LLM memory 的系统，按今天的说法属于早期智能体记忆
- 但覆盖并不绝对。真正属于 LLM 内部记忆的一支是：管理 Transformer 的 KV 缓存、长上下文处理、以及改架构（RWKV、Mamba、基于扩散的语言模型）
- **分界点在于目标**：这类机制的意图是扩大或重组底层模型的表征能力，它不支持跨任务持久、环境驱动的适应、以及有意的记忆操作（形成、演化、检索）

#### 二，智能体记忆与 RAG

- 两者在概念上有重叠：都在构造、组织、利用**超出模型固有参数知识**的信息库，都用到知识图、索引、向量与语义检索这些部件
- 经典 RAG 的定位：给模型接上相对静态的知识源，用处是让生成有事实依据、缓解幻觉、提升知识密集型任务的准确率
- **关键差别**：RAG 一般不维护「会演化的过往交互记忆」；智能体记忆嵌在持续的交互里，把自己每一步的动作与环境反馈写进持久记忆库
- 作者借 RAG 的三支划分来说明对应关系：
  - **模块化 RAG**（索引、候选召回、重排、过滤、上下文拼装）对应智能体记忆里的检索阶段，Memary、MemOS、Mem0 属于这一类
  - **图 RAG**（用图遍历与排序做多跳关系推理）对应 Mem0g、A-Mem、Zep、G-Memory；区别在于只有智能体记忆会把这张图当成**活的、持续演化的经验表征**，可以在存储期里不断构造与重排
  - **智能体式 RAG**（把检索并入自主决策循环，自己想清楚何时查、查什么）与智能体记忆最接近，分界落在操作对象：这一支操作的是外部的、往往针对单个任务的数据库，智能体记忆维护的是内部、持久、自我演化的记忆库
- **更实用的分界是评测任务**：RAG 一侧是 HotpotQA、2WikiMQA、MuSiQue 这类多跳与知识密集基准；智能体记忆一侧是 LoCoMo、LongMemEval（长对话）、GAIA、xBench、BrowseComp（深度研究）、SWE-bench Verified（代码）、StreamBench（终身学习）

#### 三，智能体记忆与上下文工程

- 定位：两者相交，但属于不同的运作范式，不存在谁包含谁
- **上下文工程**把上下文窗口当成受限的计算资源来设计，优化的是指令、知识、状态、记忆这些信息负载怎么摆；它处在资源管理的范式里
- **智能体记忆**做的是对一个持续存在、身份在演化的实体做认知建模
- 互看的关系：站在上下文工程的角度，记忆只是上下文拼装函数里一个需要高效调度的变量；站在智能体的角度，上下文工程是保证认知连续性不超物理上限的实现层
- 重合的地方在长时程交互里的工作记忆：两者都靠压缩、组织、选择这套技术，剪枝 token、按重要性筛选、滚动摘要既是缓冲管理手段，也是短期情景记忆机制
- 职责差别：上下文工程管信息在推理时**以什么形式出现**，强调格式正确与执行效率（工具集成、模型上下文协议这类接口层）；智能体记忆管智能体**知道什么、经历过什么、这些如何随时间变化**

## 第二部分：形态（forms）——记忆住在哪里

判别标准是两件事：记忆存在什么地方、以什么形式表征。三大类：

### 一，token-level memory

- **定义**：以持久、离散、外部可访问且可检查的单元保存信息。这里的 token 是广义的，视觉 token、音频帧等任何可写、可检索、可重组、可修订的离散元素都算
- **特点**：单元显式，所以透明、易编辑、易解释，是检索、路由、冲突处理与跨记忆协调的天然层次；也是目前最常见、工作最多的一类
- **子类按单元之间的结构组织划分**，从没有拓扑到多层拓扑：

**平铺记忆（1D，flat）**：单元之间没有显式拓扑，记忆累积成序列或一袋内容。按设计目标分成五组：

- **对话**：MemGPT（操作系统式分层管理，启发了后续的无限上下文管理）、Think-in-Memory、RMM、MOOM、Mem0（把记忆维护操作标准化）、ComoRAG
- **偏好**：RecMind、InteRecAgent、Memocrs（用户专属记忆加跨用户通用记忆）
- **画像**：MemoryBank、AI Persona、ChatHaruhi、RoleLLM
- **经验**：Reflexion（短期存轨迹、长期存自我反思）、ExpeL、Buffer of Thoughts、AgentKB、AWM、ReasoningBank、Voyager、DGM、LEGOMem、ToolMem
- **多模态**：Ego-LLaVA、MovieChat、MA-LMM、VideoAgent、Context-as-Memory、KARMA

优点：简单可扩展，追加与剪枝成本极低，相似度检索灵活，适合大范围召回与快速变化的交互史。代价：没有显式关系组织，连贯性与相关性严重依赖检索质量；记忆变大之后冗余与噪声累积；能取到单元却不理解关系，限制了组合推理、长时程规划与抽象形成。

**平面记忆（2D，planar）**：单元之间有显式组织拓扑，但只在一层内——树、图、表或隐式连接。核心意义是从「单纯存放」走向「有组织」。

- **树**：HAT（层级聚合树，支持由粗到细检索，长上下文问答优于扁平向量索引）、MemTree（动态层级，把具体事件逐级摘要成抽象概念）
- **图**（主流）：Ret-LLM、HuaTuo、KGT、PREMem、TeaFarm、A-Mem（卡片式单元按相关性组网）、Intrinsic Memory Agents（私有加共享记忆）、M3-Agent（图文音实体图）、SALI
- **混合**：Optimus-1（静态知识有向图加动态多模态经验池）、D-SMART（知识图加遍历式推理树）

优点：节点之间建链接产生协同，能编码更完整的上下文，支持键值查找与沿边遍历。代价：没有层级机制，所有记忆挤进一个单层模块，复杂度一升就不够用；**构建与搜索成本高，阻碍实际部署**。

**层级记忆（3D，hierarchical）**：跨层组织信息，用层间连接把记忆撑成立体结构，既能在层内横向走，也能跨抽象层纵向走。

- **金字塔型**：HiAgent（围绕子目标的层级工作记忆）、GraphRAG（社区检测形成的多级图索引）、Zep（时序知识图加社区划分）、EMG-RAG（三级可编辑记忆图）、G-Memory（洞察、查询、交互三层图）
- **多层型**：H-Mem（按语义抽象排序的多级对话记忆）、HippoRAG（关联索引图加段落库，做多跳检索）、HippoRAG 2（非参数化的持续学习）、AriGraph（语义图加事件层）、CAM（增量聚类重叠语义图）、SGMem、MAGMA

优点：层级乘上关系两个维度交叉，知识更整体、更情境化，支持跨层多路径查询，检索精度高、任务表现强。难点：结构复杂、信息密集，检索效率与整体效果都受挑战；保证每一层记忆都语义有意义、设计出最优的三维布局，至今没有答案。

### 二，parametric memory

把信息直接存进模型参数，让模型内化知识，不依赖外部存储即可回忆。按存储位置分两类：

- **内部参数记忆**：写进原始权重。按训练时相分三段——预训练（LMLM 把检索记忆放模型内而知识本体放外部知识库、StreamingLLM、Function Token）、继续预训练（Agent-Founder、Early Experience 把智能体经验融入）、后训练（Character-LM、SELF-PARAM 用蒸馏注入知识、KnowledgeEditor、MEND 用小网络改梯度做快速编辑、PersonalityEdit、APP 减少对邻近知识的扰动、AlphaEdit）
  - 优点：结构简单，不给原模型增加推理开销，也没有部署成本
  - 代价：参数难更新，写新记忆要重训，昂贵且容易忘掉旧记忆；更适合大规模领域知识与任务先验，不适合短段个性化内容或工作记忆
- **外部参数记忆**：存在附加参数里，不动原权重——适配器一路（K-Adapter 用任务专属适配器持续扩展、WISE 用双参数记忆加路由缓解终身编辑冲突、ELDER 用多 LoRA 加路由自适应选择、T-Patcher、Memory Decoder、MemLoRA）、辅助小模型一路（MAC 用摊销网络把调制量压进记忆库、Retroformer 用强化学习学过往成败）
  - 优点：兼顾适应性与稳定性，可以增删替换而不干扰基座预训练表征，支持模块化更新、任务个性化与受控回滚
  - 代价：外部模块仍要接进内部表征流，影响是间接的，效果取决于它能否良好对接内部知识

### 三，latent memory

隐式承载在模型内部表征里——KV 缓存、激活、隐状态、隐向量。优点是记忆不以明文暴露、推理延迟更低，还可能因为保留细粒度上下文而拿到更好效果。按隐状态来源分三类：

- **生成（generate）**：由独立模型或模块产生隐表征作为可复用记忆。单模态侧有 Gist、Taking a Deep Breath、SoftCoT、CARE、AutoCompressor、MemoRAG、MemoryLLM、M+、LM2、Titans（在线更新一组 MLP 权重）、MemGen；多模态侧有 CoMem、ACM、Time-VLM、MemoryVLA、XMem
  - 有一处需要单独记住：它和参数化记忆容易混，因为很多方法都用一个单独训练的模型来产生隐表征。作者的分类标准是**记忆的形式**而非学习机制——生成出来的隐表征是被显式实例化、作为独立记忆单元复用的
  - 代价：生成过程本身会带来信息损失与偏差；多次读写之后状态会漂移、误差累积；训练专用生成模块要额外算力、数据与工程投入
- **复用（reuse）**：直接沿用先前的计算，最典型的是复用 KV 缓存（轮内或跨轮），以及传播隐状态的循环控制器。代表有 Memorizing Transformers（存历史 KV，用最近邻检索）、FOT（用记忆注意力层做近邻查找）、LONGMEM（轻量残差侧网络当持久 KV 存储）
  - 优点：完整保真，没有剪枝或压缩带来的损失，概念简单、易集成
  - 代价：原始 KV 随上下文长度迅速膨胀，内存开销升高、检索变低效，效果高度依赖索引策略
- **变换（transform）**：修改、压缩、重构既有隐状态，相当于把 KV 与激活当成可塑材料。代表有 Scissorhands（按注意力分数剪 token）、SnapKV（按头投票聚合高重要前缀）、PyramidKV（跨层重新分配 KV 预算）、SirLLM（按 token 熵判断重要）、Memory3、RazorAttention、H2O（只留最近 token 加高注意力 token）
  - 优点：产出更紧凑、信息密度更高，降低存储成本并支持长上下文高效检索
  - 代价：有信息损失风险；压缩后的状态比原始 KV 更难解释与验证；剪枝、聚合、重编码本身又添一层复杂度

### 四，怎么选（3.4 一节）

作者的观点是：选择哪种记忆形态，等于在设计智能体的行为方式——它决定了信息以什么方式塑造行动，所以这不是一个随手的组合选择。

- **token-level 适合**：需要显式推理、可控与可问责的场景；要实时高频更新；需要精确增删改；需要把决策追溯到具体记忆单元的高风险场景（法律、合规）；以及聊天与多轮对话、长时程或终身智能体、个性化画像、推荐、企业知识库
- **parametric 适合**：概念理解与广泛模式归纳；跨情境的通用规则；需要结构性洞察与深厚风格模式的任务——角色扮演与人格一致、数学推理、编码、游戏、结构化问题求解、对齐与规范行为先验、领域专家式回答
- **latent 适合**：在显式数据与固定权重之间取平衡；可读性低反而天然保护隐私；以性能与可扩展性优先于可解释性；多模态与高度集成的架构、端侧与边缘部署、加密或隐私敏感领域

三种形态的核心对比可以记成一句：token-level 符号化、可寻址、透明，增删改都很快，也不会灾难性遗忘；parametric 隐式、抽象、可泛化，性能增益通常更大，但更新更慢、灾难性遗忘更严重；latent 机器原生、省 token，效率与灵活性兼顾，代价是人读不懂。

## 第三部分：功能（functions）——为什么需要记忆

作者先承认时间维度的划分（长期对短期）有其用处，但认为它太粗，于是按**用途**重新划成三支柱：

- **事实记忆（factual）**：声明性知识库，回答「智能体知道什么」
- **经验记忆（experiential）**：程序性与策略性知识，回答「智能体怎么变强」
- **工作记忆（working）**：容量受限、动态控制的工作区，回答「智能体此刻在想什么」

时间维度的对应关系是：长期落在事实记忆与经验记忆上，短期落在工作记忆上。三者合成一个循环——**编码**（把交互结果经摘要、反思、抽象沉淀进长期）→ **处理**（在工作区内推理）→ **取回**（从事实与经验记忆里取回上下文与技能填充工作区）。这个「编码、处理、取回」的序列既是核心架构模式，也是记忆发挥作用的完整路径。

### 一，事实记忆

- **存什么**：过往事件、用户信息、外部环境状态的显式事实，覆盖对话历史、用户偏好、外部世界属性
- **理论对应**：认知科学里的陈述性记忆，含亲历事件（何时何地发生什么）与一般事实（概念与词义）两部分；落到智能体身上是一条连续的谱，两种成分都有
- **形成流水线**：先记原始轨迹（对话轮次、用户动作、环境状态），再经摘要、反思、实体抽取、事实归纳，存进向量库、键值库或知识图，并做去重与一致性检查
- **要保证三件事**：一致性、连贯性、适应性

两个子类：

- **用户事实记忆**：维持人机交互一致性的事实——身份、稳定偏好、任务约束、历史承诺。目标是防止指代漂移、重复提问、前后矛盾。两类抽取策略：按相关性、时近性、重要性、区分度做启发式选择；以及语义抽象。两个应用面：对话连贯（保持人设与偏好稳定）与目标一致（跟踪任务状态、抑制意图漂移）。代表方法有 MemGPT、Think-in-Memory、MemoryBank、AI Persona、Livia、Mem0、RMM、D-SMART、MEMENTO、MemInsight、Memoria
- **环境事实记忆**：记录用户之外的其他实体与状态，比如长文档、代码库、工具、交互轨迹。目标是提供一个可更新、可检索、可治理的外部事实层，解决事实召回不全、来源不可验证、多智能体之间矛盾冗余。两条实现路线：知识持久化（HippoRAG 用知识图做证据传播、MemTree 动态层级、LMLM 把事实从权重里解耦外化；参数化路线有 MemoryLLM、M+、WISE）与多智能体共享访问（Memory Sharing、MetaGPT、G-Memory）
- **难点**：访问成本有上限、去重与一致性、来源可验证、以及在不破坏基座稳定性的前提下纠正过时事实

### 二，经验记忆

- **存什么**：历史轨迹、蒸馏出来的策略、交互结果，编码成持久可检索的表示
- **与工作记忆的分工**：不管临时的上下文，专注跨 episode 的知识累积与迁移
- **理论对应**：人的非陈述性记忆（程序性与习惯系统）。但有一处不同——智能体用显式数据结构存放，所以它能**自省、编辑、并且对自己掌握的程序性知识做推理**
- **为什么重要**：它是持续学习与自我演化的基础，提供了一条**不更新参数**的适应路径，绕开了频繁调参的高成本
- **四层抽象，从低到高**：
  - **案例型（case-based）**：保留最少加工的历史 episode，追求高保真，支持直接回放与模仿。含轨迹（交互序列）与解法（已验证的解法库）。代表有 ExpeL、Synapse、FinCon、MapCoder、Memento、JARVIS-1、MemGen、DreamGym、MemRL。形成方式是试错采集或轨迹留存，使用方式是当作上下文示例检索复用。难点是检索效率与上下文占用，而且它不含编排逻辑与调用接口
  - **策略型（strategy-based）**：抽取「该怎么做」的可迁移知识——推理模式、任务分解、洞察、工作流。三个粒度：洞察（原子级）、工作流（顺序级）、图式（网络级）。代表有 H2R、R2D2、ToolMem、ACE、Dynamic Cheatsheet、PRINCIPLES（洞察）；AWM、Agent KB（工作流）；Buffer of Thoughts、ReasoningBank（图式）。形成方式是轨迹蒸馏、反思或离线自博弈；使用方式是当作规划的高层脚手架。局限是它只是结构性指引，不能直接与环境交互
  - **技能型（skill-based）**：把抽象策略变成可执行的程序能力，编码「智能体能做什么」。判定标准有三条：可调用、结果可验证、可组合。形态从代码片段（Voyager、Darwin Gödel Machine）到函数与脚本（CREATOR、LEGOMem、SkillWeaver）到 API（Gorilla、ToolLLM、ToolRerank）到模型上下文协议封装的工具（Alita、MemTool）
  - **混合型（hybrid）**：融合多种表示。案例加策略的有 ExpeL、Agent KB、R2D2；进一步把生命周期并入技能组件的有 ChemAgent、LARP（统一语义、情景与程序性记忆）、G-Memory、MemVerse
- **三者的分工一句话**：策略给抽象规划逻辑，技能负责真正执行，案例作为可验证的事实基底
- **类间有一条转化路径**：反复成功的案例会被逐步**编译成技能**，从重检索走向快执行。这正好是经验记忆那四层抽象构成的一条阶梯

### 三，工作记忆

- **认知科学的定义**：容量受限、动态控制的机制，通过对当前任务相关信息的选择、维持与变换支持高阶认知；重点是资源受限之下的主动控制
- **对照语言模型**：标准的上下文窗口只是一个被动的只读缓冲，缺少选择与变换工作区的机制，现有模型并不具备人类式的工作记忆
- **本综述的定义**：在单个 episode 内主动管理与操作上下文的一整套机制，目标是把上下文窗口从被动缓冲变成可控、可更新、抗干扰的工作区
- **收益**：在固定的注意力预算下提高任务相关信息密度、抑制冗余噪声、靠改写与压缩保持思维链连贯
- **单轮（single-turn）**：面向一次前向处理海量输入（长文档、高维多模态流），两条路线——
  - 输入压缩：硬压缩（LLMLingua、LongLLMLingua、CompAct）、软压缩（Gist、ICAE、AutoCompressors，压成隐空间记忆槽）、混合（HyCo2）
  - 观测抽象：把原始界面重写成状态摘要（Synapse）、按视野重叠筛帧（Context as Memory）、把视频流转成事件描述（VideoAgent）
  - 判断：它是一层主动压缩，但严格限于单轮之内，解决的是静态输入的广度，不是交互在时间上的连续性
- **多轮（multi-turn）**：瓶颈从瞬时容量变成任务状态与历史相关性的持续维护——历史累积会饱和注意力、增加延迟、诱发目标漂移。做法是外化成状态载体，形成读、评、写的持续循环。三种策略：
  - 状态归并（MemAgent、MemSearcher、ReSum、MEM1、MemGen）
  - 按子目标分层折叠（HiAgent、Context-Folding、AgentFold、DeepAgent）
  - 认知规划，把计划与世界模型外化成前瞻结构（PRIME、SayPlan、Agent-S、KARMA）
- **与前两类的关系**：工作记忆是 episode 内临时的；检索从事实记忆与经验记忆里取内容填充工作区，工作区的产出又能经编码沉淀回长期

## 第四部分：动态（dynamics）——记忆怎么形成、演化、被取回

第 3、4 章给的是静态框架，缺了动态性：记忆可以动态构造与更新，检索也是按查询定制的。这一章按记忆生命周期的三个阶段展开，三者构成循环而非独立模块——形成产出内容，演化把它整合，检索支撑推理，推理结果与环境反馈又回流到形成与演化。

### 一，形成（formation）：五类做法

总论先说清一件事：五类**并不互斥**，同一个算法可以组合多种策略，知识也可以在表示之间转移。

- **语义摘要（semantic summarization）**：把冗长原始数据压成保留全局语义的摘要，过滤冗余。分增量式（MemGPT、Mem0、Mem1、MemAgent）、分段式（MemoryBank、ReadAgent、LightMem）、多模态（DeepSeek-OCR、FDVS、LangRepo）
  - 代价：有损，分辨率下降，细节被抹掉，不适合需要逐字取证的任务
- **知识蒸馏（knowledge distillation）**：更细粒度地抽取可复用知识，分事实一路（Think-in-Memory、RMM、MemGuide、M3-Agent）与经验一路（AgentRR、AWM、Memp、SAGE、R2D2、ExpeL、H2R、Memory-R1）
  - 优点：跨任务泛化，支撑终身学习
  - 代价：对提示词设计敏感；产出的是扁平单元，忽略语义与层级关系
- **结构化构造（structured construction）**：把不成形的数据组织成显式拓扑。实体级有 KGT、Mem0g、D-SMART、GraphRAG、AriGraph、HippoRAG、Zep；块级有 HAT、RAPTOR、MemTree、H-MEM、A-Mem、SGMem、CAM、G-Memory
  - 优点：可解释，支持复杂关系查询与多跳推理
  - 代价：模式刚性（难以表达含混与细微的信息），抽取与维护成本高
- **隐空间表示（latent representation）**：直接编码进机器原生的潜空间。文本侧有 MemoryLLM、M+、MemGen；多模态侧有 CoMEM、Mem2Ego、KARMA
  - 优点：密度高、信息损失少，利于跨模态对齐
  - 代价：不透明，难以调试、编辑与验证
- **参数内化（parametric internalization）**：把外部记忆写进权重，绕开外部存储与检索开销。分知识内化（MEND、ROME、MEMIT）与能力内化（ToolFormer、各类后训练、Memory Decoder）
  - 优点：从「去检索」变成「已拥有」，零延迟，成为模型固有能力
  - 代价：灾难性遗忘、更新成本高、对无关知识有连带影响、难以精确删除

### 二，演化（evolution）：三个动作

背景问题很直接：简单地往记忆里追加，会忽略语义依赖、冲突与时间有效性。

- **归并（consolidation）**：触发条件是新的短期记忆到达；做法是识别语义关系并向上抽象。三个粒度——局部（RMM 对前 K 条判断是否合并、容量饱和时触发池化）、簇级融合（PREMem、EverMemOS、CAM）、全局整合（MOOM、Matrix、Context Folding）
  - 风险：**信息被过度平滑**，异常与个例在抽象过程中被抹掉
- **更新（updating）**：触发条件是出现冲突或新事实。两路——
  - **外部记忆更新**：规则式替换与删除（MemGPT、Mem0g）→ 带时间戳的软删除（Zep）→ 延迟一致（MOOM、LightMem 用在线软更新加离线反思）→ 用强化学习学「何时、如何、是否更新」（Mem-α）
  - **模型编辑**：显式定位与定向更新（ROME、Model Editor Networks）；隐空间自更新（MemoryLLM 周期性替换记忆 token、M+ 双层记忆）；混合（ChemAgent 外存更新与内部编辑同步）
  - 核心难题：**稳定性与可塑性的两难**——误更新会覆盖关键信息，导致知识退步
- **遗忘（forgetting）**：触发条件是无界累积带来的噪声、检索延迟与过期干扰。三个依据——
  - 按时间：MemGPT 溢出时逐出最早消息、MAICC 对记忆权重做软衰减
  - 按频率：XMem 用最少使用淘汰、KARMA 用计数布隆过滤器、MemOS 用最近最少使用加归档高频项
  - 按重要性：MemoryBank 与 MOOM 用时间衰减加访问频率的复合分、Livia 用情绪显著性加上下文相关度、Think-in-Memory 与 MemTool 让大模型判断重要性后主动剪枝
  - 风险提示：按频率淘汰这类启发式会误删**长尾知识**；作者给的规律是——存储成本不作为关键约束时，不要直接删除
- **三条演化趋势**（作者总结的历史脉络）：摘要从启发式融合走向学习式优化；更新从规则式走到时间感知，再到延迟一致，最后是学出来的策略；遗忘从静态数值打分走向语义判断
- 还有一个元层面的方向：MemEvolve 提出同时演化记忆内容**与记忆架构本身**

### 三，检索（retrieval）：四个环节

- **时机与意图**：从被指令触发转向自主决定。简化做法是把决定权交给模型或外部控制器；激进做法是每轮都查全部记忆库；快慢思考的做法是先给快答再自评、不够再触发深检索（ComoRAG、PRIME）；也有从隐空间状态里检测关键时刻的可训练触发器（MemGen）。意图方面有按环境反馈在低层模板与高层经验间切换（AgentRR）、在参数记忆与激活记忆与明文记忆之间调度（MemOS 的调度器）、按索引由粗到细路由（H-MEM）
  - 未解风险：过度自信而不检索会陷入**静默失败**，直接表现为幻觉；需要在「及时给信息」与「避免检索噪声」之间取平衡
- **查询构造**：它是用户表层说法与记忆潜在结构之间的翻译层。两个动作——
  - 分问题：Visconde、ChemAgent、PRIME、MA-RAG（先用规划智能体做全局计划再分查询）、Agent KB（教师看学生失败后生成更细的子查询）
  - 改写：HyDE 生成假设文档、MemoRAG 用压缩后的全局记忆生成草稿当查询、MemGuide 生成命令式高层意图、Rewrite-Retrieve-Read 用强化学习训练改写器、ToC 做澄清树
  - 有一条明确结论：**查询质量对推理性能影响很大**，Auto-RAG 在相同检索条件下比较不同改写策略并择优；研究重心正从「设计更复杂的记忆架构」转向「检索构造」
- **检索策略**，五类：
  - 词法检索（TF-IDF、BM25）：适合要精确匹配的场景，缺点是对表述差异敏感
  - 语义检索（Sentence-BERT、CLIP 这类编码器）：多数框架的默认选择；缺点是语义漂移，以及强制取前 K 条带来的噪声
  - 图检索（AriGraph、EMG-RAG、SGMem 的自我图扩展、HippoRAG 的个性化 PageRank、CAM、Zep 的时序约束）：优势在多跳、长程依赖，可对接精确规则
  - 生成式检索：直接生成文档标识符，小规模常优于传统方法，但需要额外训练，语料演化时扩展性差；作者评价为「关注少，潜力还没挖出来」
  - 混合检索：词法加语义（Agent KB、MIRIX）、语义与符号并行（Semantic Anchoring）、按近期性与重要性加相关性累加打分（Generative Agents）、按相似度加预测回报的混合效用（MAICC）
- **取回后处理**：把噪声、冗余、碎片化的结果整理成简明一致的上下文。两块——
  - 重排与过滤：启发式对齐（Semantic Anchoring、按角色与阶段与时近性过滤的 RCR-Router）、把打分聚合当成强化学习问题来学、按时间戳与有效期过滤（Zep）、用大模型当评估器（Memory-R1 的作答智能体）、用小模型预测贡献概率（Memento 用 Q 学习、MemGuide 微调一个小模型按边际收益重排）
  - 聚合与压缩：合成全局抽象摘要（ComoRAG 的整合智能体）、抽取局部细粒度片段（MA-RAG 的抽取智能体）、多智能体场景按角色定制提示词（G-Memory）
  - 好处：不改动底层检索器，能兼容任意预训练检索模型，也能做任务特化优化

**这一章作者给出的推荐做法**：混合检索融合异质信号；用强化学习学打分聚合，胜过手调超参；分层路由由粗到细，既提精度又缓解信息过载；取回后处理做成附加层，不动底层检索器。

## 第五部分：资源与框架

### 一，基准与数据集分两大类

**第一类：为记忆、终身学习、自演化专门设计的**，内部再分三小类。

- **记忆导向**：MemBench、LoCoMo、WebChoreArena、MT-Mind2Web、PersonaMem、PerLTQA、MPR、PrefEval、LOCCO、StoryBench、DialSim、LongBench 与 LongBench v2、RULER、BABILong、MM-Needle、HaluMem。测的是用户建模、偏好跟踪、会话级一致性，以及在多轮对话、用户会话、长合成叙事里的信息保留与取回
- **终身学习**：LongMemEval、MemoryBank、MemoryBench、LifelongAgentBench、StreamBench。测的是灾难性遗忘、前向与后向迁移、测试时适应——不只看当前任务，还要看先前任务的性能是否保持
- **自演化**：MemoryAgentBench、Evo-Memory 以及多 episode 与任务式环境。测的是自我反思、记忆编辑、工具增强的存储、跨 episode 的策略改进

规模上举几个具体数字：MemBench 五万三千条、MM-Needle 约二十八万条、ToolBench 十二万六千条、LongMemEval 五个任务五百个样本、PersonaMem 十五个任务一百八十个样本、MemoryBench 四个任务约两万条。绝大多数基准是模拟环境，只有少数用真实环境。

**第二类：本为其他目的设计，但长时程特性与记忆评测相关**。

- 具身与交互：ALFWorld、ScienceWorld、BabyAI
- 网页与工具：WebShop、WebArena、MMInA、ToolBench
- 多任务与通用平台：AgentGym、AgentBoard、基于 PDDL 的规划
- 真实场景：SWE-Bench Verified、GAIA、xBench-DS、GenAI-Bench

**三处局限**：记忆导向的基准多在模拟环境里跑，标准答案可以被精确控制，与真实环境有差距；它们常隐含假设记忆库本身已经整理好，只测访问精度；自演化那一类多是把既有环境改造成自演化设定，并非原生设计。第二类的问题是记忆并非显式测量目标，效果靠长上下文管理与跨步一致性间接体现，难以直接归因。

### 二，开源框架

- **以智能体为中心、自带层级记忆抽象**：MemGPT（分层短期与长期记忆）、Mem0（图加向量）、Memobase（结构化画像）、MIRIX、MemoryOS（短期、中期、长期三层）、MemOS（树形记忆加记忆立方）、Zep（时序知识图）、HippoRAG
- **通用后端与向量库**：SuperMemory、Cognee（知识图）、Memary（流式加实体库）、Pinecone、Chroma、Weaviate（向量加图）
- **记忆管理与其他**：Second Me、MemU、MemEngine、Memori、ReMe、AgentMemory、MineContext、Acontext、PowerMem、HindSight

作者的观察：多数框架显式区分短期与长期存储，提供图、画像或模块化的记忆空间；纯向量库这一类把智能体行为与评测协议留给应用层去定。两个方向都在表示灵活性与系统设计上快速成熟。

## 第六部分：八个前沿方向

### 一，检索与生成的转向

- **回顾**：主流一直是检索式——在既有记忆库里按当前上下文查找、过滤、挑选，靠向量检索、混合检索、重排、知识图提升精度，隐含假设是记忆库已经成型。近来转向**生成式**：按需主动合成新的记忆表示，又分「先检索再生成」（ComoRAG、G-Memory、CoMEM）与「直接生成」（MemGen 直接构造隐空间记忆 token，跳过显式检索）
- **展望**：生成式记忆应具备三种性质——按预期未来需求调整粒度与抽象层级、整合跨异质信号（隐空间记忆是一条可行路径）、以及用强化学习或长时程表现来学「何时生成、如何生成」，让记忆成为策略的一部分

### 二，自动化的记忆管理

- **回顾**：现有系统靠手工策略决定存什么、何时用、如何更新——固定指令、预设阈值、专家规则。好处是可解释、可复现、可控、工程成本低；坏处是僵化，难以泛化到动态环境，长程与开放交互中表现差。已有的自动化尝试有 CAM（让模型自动把细粒度条目聚成高层抽象单元）与 Memory-R1（辅助智能体加专门的记忆管理工具），但仍受规则驱动或只针对窄目标
- **展望**：把记忆的构造、演化、检索直接并入智能体的决策循环，通过显式的工具调用（新增、更新、删除、检索）让智能体自己推理记忆操作；并发展能自我优化的记忆结构，让架构具备自组织能力

### 三，强化学习与记忆

- **回顾**：三段演化——**无强化学习**（启发式、阈值、语义检索、提示驱动，如 MemOS、Mem0、Dynamic Cheatsheet、ExpeL、G-Memory）→ **辅助增强**（用策略梯度重排片段、让强化学习智能体接管记忆构建、工作记忆方向有 Context Folding 与 Memory-as-Action）→ **完全由强化学习驱动**
- **展望**：记忆架构应尽量少依赖人写的先验（不再照搬皮层与海马体的类比、不再套用情景与语义的分类），让智能体通过强化学习自己发明格式与更新规则；智能体要完整掌控记忆的全部阶段，需要端到端的训练。作者的立场是记忆会从外挂辅助机制变成与智能体共同演化的可学习子系统

### 四，多模态记忆

- **回顾**：两条线——多模态智能体存储与检索来自图像、音频、视频的记忆（视觉与视频最成熟，支持视觉定位、时间追踪、长期场景一致性；音频仍欠探索）；以及把记忆当作统一模型的一个组件，用来维持实体一致与跨帧世界状态
- **展望**：多模态记忆会成为智能体系统不可缺少的一部分。现状是**尚无真正的全模态记忆系统**，多数局限在单一模态或松耦合；难点在于设计既能容纳多模态、又能保住语义对齐与时间一致性的表示与操作，并让记忆从被动存储走向抽象、跨模态推理与长期适应

### 五，多智能体共享记忆

- **回顾**：从「各自孤立、靠显式消息传递」（避免干扰，但冗余、上下文碎片化、通信开销高）走到「集中式共享记忆」（全局向量库、黑板、共享文档，支持联合注意、减少重复、长程协调，但带来记忆堆积、写入竞争、缺少按角色与权限的访问控制）
- **展望**：共享记忆要从被动仓库变成主动管理的集体表示——按角色、专长、信任度决定读写权限；用长程团队表现训练「何时贡献什么、如何贡献」，替代手写的同步与冲突解决策略；并在开放多模态环境中支持跨异质信号的抽象

### 六，世界模型的记忆

- **回顾**：世界模型需要高保真、实时、可无限延展地模拟世界，记忆是基石。路径从早期的帧采样（上下文碎片化、感知漂移）到滑动窗口（受固定窗口限制，物体出窗就忘，无法闭环）到 2025 年底转向结构化状态表示——状态空间模型（Mamba 系，固定递归状态、常数推理成本）、显式记忆库（WorldMem、Context-as-Memory 用视野重叠做几何检索）、稀疏记忆与检索
- **展望**：从「缓存数据」转向「模拟状态」。两个方向——双系统架构（快速直觉层用状态空间模型处理即时物理，慢速推理层用大视觉语言模型或显式记忆库维持一致性）；以及主动记忆管理，把记忆当成认知工作区，主动整理、摘要、丢弃，从「记住最近 N 个 token」转向「维持一个连贯且可查询的世界状态」

### 七，可信记忆

- **回顾**：信任议题从 RAG 的幻觉与事实性扩展而来。区别于 RAG，智能体记忆存的是用户相关、持久、可能敏感的内容——事实知识、过往交互、偏好、行为轨迹，于是多了隐私、可解释与安全三重挑战。有研究显示记忆模块可以被间接的提示词攻击套出隐私数据；也有研究主张需要访问控制、可验证的遗忘、可审计的更新。可解释性仍是瓶颈：难以追溯哪些记忆被检索、又如何影响了生成
- **展望**：三根支柱——**隐私保护**（细粒度权限、用户可控的保留期、加密或端侧存储、联邦访问、差分隐私、记忆脱敏、自适应遗忘）、**可解释**（可追溯的访问路径、能自我解释的检索、反事实推理、可视化与因果图）、**抗幻觉**（冲突检测、低置信时弃答、回退到模型先验、多智能体交叉核对、机制可解释性）。长期设想是把记忆做成类操作系统的抽象：分段、可版本控制、可审计、由智能体与用户共管

### 八，与人类认知的对照

- **回顾**：当代的智能体记忆架构与人类认知模型高度相似——容量受限的上下文窗口加外部向量库，对应多存储模型里的工作记忆与长期记忆；把记忆分成交互日志、世界知识、代码技能，对应情景、语义、程序性的分类。但检索与维护的动态存在根本分歧：人类记忆是**建构过程**，按当前认知状态重建过去；多数智能体仍靠逐字检索，把记忆当成不可变的 token，因此缺少记忆扭曲、抽象与动态重塑的能力
- **展望**：引入离线固化周期（类似睡眠的固化间隔），依据互补学习系统理论，在离线期做记忆重组与生成式回放、抽取可泛化的图式、主动遗忘剪噪、优化内部索引（不受实时延迟约束）；记忆形式从显式文本检索转向生成式重建（隐空间记忆 token），周期性地把情景流压成参数化的直觉，用来缓解稳定性与可塑性的两难

## 第七部分：作者明确的代价与未解问题

**各类做法的代价，集中记一遍**：

- 平铺记忆：连贯性依赖检索质量，记忆一大就积噪声
- 平面记忆：构建与搜索成本高，阻碍实际部署
- 层级记忆：最优布局没有答案，检索效率受结构复杂度拖累
- 结构化构造：模式刚性，难以表达含混信息
- 语义摘要：有损，分辨率下降，不适合逐字取证
- 隐空间表示：不透明，难以调试与验证
- 参数内化：灾难性遗忘、更新贵、难精确删除
- 归并：过度平滑会把异常与个例抹掉
- 更新：稳定性与可塑性的两难没有判定准则
- 遗忘：按频率淘汰会删掉长尾知识
- 检索时机：过度自信不检索会造成静默失败与幻觉

**仍未给出设计准则的环节**：五类形成策略的取舍依据、归并的匹配与合并粒度、更新的覆盖判据、遗忘的删除阈值、检索触发的边界。

**作者认为最紧要的开放问题**：从检索中心走向生成式记忆，并让它自适应上下文、整合异质信号、可学习；把记忆全生命周期交给智能体自主掌控（工具调用或端到端强化学习）；做出真正全模态的记忆系统；把可信记忆的三根支柱做实，最终走向可审计、用户与智能体共管的类操作系统抽象；借鉴人类认知的离线固化，用生成式重建来缓解稳定性与可塑性的两难。

## 第八部分：与 2024 那篇综述的对照

2024 年那篇用的是「来源、形态、操作」三个维度，这一篇用的是「形态、功能、动态」三个视角。放在一起看，四处变化：

- **形态**升级了：从「文本形式与参数化形式」扩到「token-level、parametric、latent」。新纳入的是隐空间这一大类——KV 缓存的复用、压缩与生成，这是 2024 年那篇完全没有覆盖的部分
- **来源**消失了：2024 年那篇把记忆来源单列一类（试验内、跨试验、外部知识），这一篇没有再单独设章，而是摊进形成方式与事实、经验两类功能里
- **功能**是全新的：factual、experiential、working 三分取代了长期与短期的二分，其中经验记忆的四个抽象层级（案例、策略、技能、混合）是那篇里没有的
- **操作**升级成动态：写入、管理、读取三算子扩成形成、演化、检索三个阶段，演化里多了归并这一动作、把更新细到时间感知与学到的策略、把遗忘分成按时间、按频率、按重要性三套依据
- **评估**换了形态：2024 年那篇把评估单独成章、分直接与间接两路；这一篇改成资源清单，列基准与开源框架，并指出「记忆库已经整理好」这类隐含假设
- **一致的地方**：两篇都反对把记忆做成一个大召回池，都强调检索要能解释、要轻量可控，也都认为记忆是智能体的基础而非附属

## 第九部分：与 Tether 现行做法的对照

把 Tether 的记忆层放进这套新坐标里逐项定位：

- **形态**：落在 token-level 的平铺记忆（1D）里。任务摘要、路径清单、文件摘要、跨轮笔记都是扁平的离散单元，没有单元间拓扑，也没有层级。好处是透明、易编辑、写入成本低；代价正是这一章点出的那两条——没有关系组织，连贯性依赖检索质量
- **功能**：事实记忆那边只占到环境事实记忆的一角（记的是文件状态与出错情况），用户事实记忆基本空缺；经验记忆整块空缺——没有案例库、没有策略、没有可调用技能；工作记忆靠 history 的裁剪与 memory 的总览段凑合，没有主动的选择与变换机制
- **动态**：形成只有最粗的一档语义摘要（取前三行用竖线拼起来，属于机械式压缩）；演化只有隐式遗忘（超过上限丢掉最早那条）与冲突处理（文件内容变了就让摘要失效）；检索只做了混合检索里很浅的一层——标签命中加关键词重叠，既没有查询构造，也没有取回后处理

**可以借用的四处，按性价比排**：

1. **经验记忆**：把测试结论、失败原因、用户偏好沉淀成可复用的策略与技能，这是当前最大的空缺。综述的结论很直接——经验记忆提供了一条不更新参数的适应路径，跨轮复用成本最低
2. **查询构造**：现在是把用户原话直接当查询。综述给了一条明确结论：查询质量对推理性能影响很大，研究重心正从记忆架构转向检索构造。把请求改写成更有指向的查询，成本低、收益直接
3. **取回后处理**：现在是取前三条原样贴上去。综述推荐的做法是加一层附加的重排与压缩，不动底层检索器就能提升信噪比
4. **归并**：把多条零散笔记归并成一条更高层的结论，对应演化里的归并动作，也对应 A-Mem 那条记忆演化线

**两条已经写在综述里的经验规律，正好能用来判断现有实现**：

- 存储成本不紧要时不要直接删除记忆。Tether 现在超过上限就丢掉最早那条，按这条规律属于过早删除，更稳的做法是把旧笔记归档或降权
- 遗忘按频率或时间淘汰会误伤长尾知识。Tether 是按插入顺序淘汰，误伤的是最久没被写进来的内容，这类内容未必不重要

**还有一处直接对应项目现状**：多智能体共享记忆那一节讲两个极端——各自孤立加消息传递（冗余、碎片化）与集中共享（记忆堆积、写入竞争）。Tether 的子智能体探索完只回一段摘要，主智能体记忆里不留过程，正是这一节所说的隔离与冗余问题。
