因为在 Decoder-only 的底层物理实现中，**“输入”和“输出”根本没有物理隔离，它们共享同一套显存缓存（KV Cache）和位置编码空间。**
本质原因有三点：
### 1. 自回归生成的本质是“不断把输出变成输入”
Decoder-only 架构是一步步往后吐词的：
- 假设输入 10 个词，生成第 1 个词；
- 生成第 2 个词时，前面的输入（10 个）和刚才生成的第 1 个词（1 个），**合并变成了 11 个词的“新输入”**；
- 生成第 100 个词时，前面的输入和已经生成的 99 个词，**全都在作为它的上下文**。
    对模型来说，生成的词只是**序列在时间轴上的自然延长**。
### 2. KV Cache 显存必须统一且连续存储
为了避免每生成一个词都重新算一遍整段前文，推理引擎会把所有已处理词的 Key 和 Value 缓存进显存（即 **KV Cache**）。
- 输入的 Prompt 需要存进 KV Cache；
- 每一个新生成的 Token 也必须追加写入同一个 KV Cache。
    显存分配是**按整个序列的总长度（输入 + 输出）来预留或动态扩充的**。如果只限制输入，输出无限膨胀，显存照样会瞬间 OOM（显存溢出）。
### 3. 位置编码（Positional Encoding）有绝对上限
像 RoPE（旋转位置编码）等机制，模型在预训练时能稳定表达的最大序列长度是**固定**的（例如 8k、32k 或 128k）。
- 无论一个 Token 来自用户的提问，还是来自模型自己的输出；
- 它的绝对位置索引 $pos$ 都在从 $0, 1, 2, \dots$ 一直往后累加。
    一旦 `输入长度 + 输出长度 > 最大上下文限制`，后续生成的 Token 就会超出预训练的位置编码有效范围，注意力打分失真，模型直接开始胡言乱语或报越界错误。
### 一句话总结
**“输入”是初始序列，“输出”是追加序列，它们共用同一个位置计数器和同一块 KV Cache 显存池，所以预算只能算总量。**
