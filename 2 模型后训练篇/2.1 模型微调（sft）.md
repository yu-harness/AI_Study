### 大模型监督微调（SFT）六大典型应用场景（优化版）

1. **风格化交互输出**   PEFT
   针对特定语料风格进行适配训练，例如将模型输出调整为《甄嬛传》古风对话体，满足文体一致性与场景沉浸感要求。

2. **限定域问答优化**   PEFT
   适用于**查询空间高度受限**的业务场景（如 5,000～6,000 条标准问题库），通过精准问答对训练提升匹配准确率。需注意：当业务复杂度超出阈值时，应升级为全参数后训练（Full Fine-tuning）。

3. **轻量级领域知识注入**  
   适合专业复杂度不高的垂直领域知识迁移。对于医学、法律等高复杂度专业，建议采用领域预训练（Post-pre-training）而非单纯微调。
4. **数学/代码等专项能力强化**  
   主流路径包括代码生成优化与数理逻辑提升。如 DeepSeek、Kimi 等模型在发布前，常基于特定数据集定向微调以刷新技术榜单。
5. **函数调用（Function Calling）支持优化**  
   通过结构化输出训练，增强 API 调用、工具使用等函数执行能力，构建模型与外部系统的标准化交互接口。
6. **智能体（Agent）协作能力强化**   PEFT
   针对多 Agent 协同、任务拆解与状态维护等复杂场景，通过定制化训练提升模型的流程控制、策略规划与跨智能体协调能力。

**业界共识**

1、Prompt的**质量和多样性**远比数量重要，全量微调一个30B量级的base model只需要10w条数据即可，lora微调一个30B的大约需要2w条。（经验值）
	参考：《LIMA：Less Is More for Alignment》
2、合成数据很重要！数据需要尽可能覆盖所有类别的业务问题，要通过不同方式进行多路合成，减少合成数据的bias。
	参考：《Phi-3 Technical Report： A Highly Capable Language Model Locally onYour Phone》
3、可以加点预训练的数据进去，减少**灾难性遗忘**。
	参考：《The Llama 3 Herd ofModels》
4、一般训练1~3个epoch。
5、可以**全量微调**，就不要 **[[PEFT]]**。（比如上述六大应用场景中，只有1、2、6适合做PEFT）
6、SFT阶段不能做太多知识注入，过多的知识注入，或者超出模型能力本身的回答过多会导致**对齐税**（Alignment Tax）。

| 维度      | 全量微调               | 参数高效微调（PEFT）                              |
| ------- | ------------------ | ----------------------------------------- |
| 参数调整范围  | **更新预训练模型的所有参数**   | 仅更新少量新增参数（如适配器、LoRA层）或部分原参数               |
| 计算资源需求  | **高（需存储和计算全量梯度）**  | 低（仅需计算部分梯度，显存和算力需求大幅降低）                   |
| 过拟合风险   | **较高（尤其在小数据集场景）**  | 较低（冻结大部分参数，保留预训练知识）                       |
| 模型保存与部署 | **需保存完整模型参数（体积大）** | 仅需保存少量新增参数（体积小，共享基础模型）                    |
| 多任务适配能力 | **需为每个任务保存完整模型**   | 可复用同一基础模型，仅切换少量参数                         |
| 典型方法    | **直接微调所有层**        | LoRA、Adapter、Prefix-Tuning、Prompt Tuning等 |
#### 2.1.1 LoRA

通过在模型的关键层（多头注意力和Feed-Forward）中添加 **[[低秩矩阵]]**，并将其加到原始权重矩阵上。
该方法不用改变整个模型的结构，在推理时不需要额外的计算量，并且能保持原有的性能。
与之相比，[[Adapter]]引入了额外的层，该层必须按顺序处理，影响并行训练；
[[Prefix-tuning]]在用户输入前加可训练的前缀，减少了可用于处理下游任务的sequence长度，性能较差。
