# 训练循环：五件套如何装配

## 一句话

**损失函数打分 → 正则项加约束 → 反向传播给梯度 → 优化器改参数 → 调度器调步长**，五件事按固定顺序串成一个 step。

## 五个角色，各管一件事

| 组件                            | 回答什么问题      | 常见选择                   |
| ----------------------------- | ----------- | ---------------------- |
| [[交叉熵损失\|损失函数]]               | 这次错得多严重     | 交叉熵、MSE                |
| [[正则项]] | 允不允许参数长太大   | L2、L1、Dropout          |
| [[优化策略\|优化器]]                 | 梯度拿到了，怎么改参数 | AdamW、SGD+momentum     |
| [[学习率调度]]                     | 这一步该走多大     | warmup + cosine        |
| [[梯度裁剪]]                      | 这一步会不会太大    | `clip_grad_norm_(1.0)` |

前三者通过**梯度**串在一起：损失和正则共同决定梯度，优化器消费梯度；后两者是对更新过程的外围控制。

## 一次 step 的完整顺序

```python
for step, batch in enumerate(loader):
    logits = model(**batch)                       # ① 前向
    loss = criterion(logits, labels)              # ② 数据损失（不含正则时）

    loss.backward()                               # ③ 反传，梯度写进 param.grad

    torch.nn.utils.clip_grad_norm_(              # ④ 裁剪：必须在 step 之前
        model.parameters(), max_norm=1.0)

    optimizer.step()                              # ⑤ 按梯度和内部状态更新参数
    scheduler.step()                              # ⑥ 推进学习率
    optimizer.zero_grad(set_to_none=True)         # ⑦ 清梯度
```

顺序不能乱的三处：

- **`backward` 必须在 `clip` 之前**，否则裁的是上一次残留的梯度
- **`clip` 必须在 `step` 之前**，裁剪的目的是限制这次更新幅度
- **`scheduler.step()` 在 `optimizer.step()` 之后**，否则第一步用的是第 0 步的学习率

## 正则项的两条接入路径

### 路径 A：手动加进 loss

```python
ce  = F.cross_entropy(logits, labels)
l2  = 0.5 * lam * sum((p ** 2).sum() for p in model.parameters())
loss = ce + l2
```

反传时梯度自然多出 $\lambda w$ 一项，等价于在梯度里加惩罚。适合 L1、自定义正则。

### 路径 B：交给优化器

```python
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4, weight_decay=0.1)
```

衰减不进梯度，而是每步单独减 $\eta\lambda w$。**语义与「权重衰退」一致，且不受 $\sqrt{\hat v}$ 缩放**（原因见 [[Adam#和 AdamW 的区别]]）。

### 两个必须避开的坑

**重复惩罚**：loss 里加了 L2，又传了 `weight_decay`，等于衰减做了两遍，模型会明显欠拟合。

**无差别衰减**：`weight_decay` 不应作用于 bias 与 LayerNorm 的缩放参数，标准写法是分组：

```python
decay, no_decay = [], []
for n, p in model.named_parameters():
    if p.ndim < 2 or "bias" in n or "norm" in n:
        no_decay.append(p)
    else:
        decay.append(p)

optimizer = torch.optim.AdamW([
    {"params": decay,    "weight_decay": 0.1},
    {"params": no_decay, "weight_decay": 0.0},
], lr=1e-4)
```

## 一个 batch 的具体数值

设交叉熵 1.20、L2 项 0.05、学习率 $1\times10^{-4}$：

| 步骤 | 数值 |
| --- | --- |
| loss | $1.20+0.05=1.25$ |
| 反传后梯度范数 | 3.8（超过阈值 1.0） |
| 裁剪 | 整体乘 $1.0/3.8\approx0.263$ |
| Adam 更新 | 方向不变，实际位移约为 $\eta$ 量级 |
| scheduler | 学习率按下一条曲线微调 |

裁剪把"方向准但步子过大"的更新压回安全范围，这就是它和优化器分工的地方：**优化器决定方向和相对大小，裁剪只负责封顶。**

## 四种典型配方

| 场景 | 损失 | 正则 | 优化器 | 调度 |
| --- | --- | --- | --- | --- |
| LLM 预训练 | 交叉熵（末位 `-100`） | `weight_decay=0.1`，不进 loss | AdamW | warmup 0.5%–2% + cosine |
| SFT / LoRA | 交叉熵（prompt 段 `-100`，可加 label smoothing） | `wd=0.01`，LoRA 常设 0 | AdamW | warmup 3%–10% + cosine |
| 图像分类 | 交叉熵 | 少量 L2 + 数据增广 | SGD + momentum 0.9 | step decay |
| 回归 | MSE | 视情况 L2 | Adam | 常数或 cosine |

差异集中在三点：**loss 怎么屏蔽无效位置、正则走哪条路径、优化器与调度怎么配**。

## 顺序之外的三条经验

**梯度累积时，只在真正 `step()` 前裁剪一次**，不要在 micro-batch 里裁——否则等效 batch 的梯度被反复削平。

**混合精度下先 `scaler.unscale_(optimizer)` 再裁剪**，否则裁的是放大 $2^{16}$ 倍后的梯度。

**`zero_grad(set_to_none=True)`** 比默认清零更省内存，且能区分"梯度为 0"与"没有梯度"。

## 常见故障对照

| 现象 | 先查哪里 |
| --- | --- |
| loss 不降 | 学习率太小、loss 掩码写错（把该学的屏蔽了） |
| loss 变 NaN | 学习率太大、没裁剪、fp16 溢出 |
| 训练集好、验证集差 | 正则不足、数据太少、过拟合 |
| 前几百步剧烈抖动 | warmup 太短、batch 太小 |
| 后期完全不降 | 学习率已衰减到接近 0，或 Adagrad 类优化器衰减过度 |
