### Spider (1.0)：时代的先驱与基石

作为 Text2SQL 领域最经典的“老大哥”，**Spider** 开创了跨领域评估的先河，但放到今天来看，它已经无法全面评估最先进大模型的能力了。

- **时间与背景**：2018 年由耶鲁大学发布。由于大模型的降维打击，官方在 2024 年初已经停止维护其排行榜，并呼吁大家转向 2.0。

- **难度与现状**：目前属于**基础难度**。现代的顶级大语言模型在 Spider 上的准确率轻松超过 85% 甚至 90%。

- **特点**：
  - **重结构，轻数据**：它考察模型是否能写出包含嵌套、多表 JOIN 等复杂语法的 SQL。
  - **脱离真实环境**：数据库里的大多是“干净”的模拟数据（甚至有些是空表）。模型只需要看表结构（Schema）像做翻译题一样写 SQL，不需要去查阅数据库里的真实数值。

### BIRD：走向真实业务逻辑的转折点

当学术界发现 LLM 在 Spider 上刷榜太容易后，BIRD（A **B**ig Bench for Large-Scale **D**atabase Grounded Text-to-SQLs）横空出世，把重点拉回了真实世界的“泥沼”中。

- **时间与背景**：2023 年 5 月由香港大学等机构联合发布。

- **难度与现状**：**非常困难**。根据 2025-2026 年的最新榜单，人类 DBA（数据库管理员）的准确率约为 92.9% 左右，而目前最顶尖的 AI 代理（依靠多步推理）的执行准确率徘徊在 75% - 82% 之间。

- **特点**：
  - **大规模与脏数据**：数据库体积庞大，且数据充满了现实中的噪音、缩写和不规范拼写。模型不仅要懂表结构，还得懂数据库里存的具体值（Database Grounding）。
  - **引入外部知识（External Knowledge）**：用户的提问往往包含公司黑话或业务逻辑（例如：“帮我查出上个月的高净值客户”）。模型必须结合提供的额外业务文档，推导出“高净值=资产>100万”并转换为 SQL 条件。
  - **不仅要对，还要快**：BIRD 引入了 VES（Valid Efficiency Score）指标，这意味着如果你的 SQL 写法极其消耗数据库性能（例如用了极其低效的交叉连接），分数会被大打折扣。

### Spider 2.0：企业级 Agent 的试金石

这是目前 Text2SQL 领域**最前沿、最具挑战性**的基准。它不再把 Text2SQL 看作是一个单纯的“翻译任务”，而是把它看作一个“数据科学家（Data Scientist）日常的数据处理工作流”。

- **时间与背景**：2024 年末发布（入选 ICLR 2025 Oral）。

- **难度与现状**：**极高挑战性**。发布初期的基准模型准确率仅在 30% 左右，不过随着 2025-2026 年 AI Agent 技术（如自我纠错、多轮工具调用）的飞速发展，榜首分数目前已经推进到了极高的水平（部分高级专有Agent已突破 90%）。

- **特点**：
  - **真实企业环境与方言**：不再局限于 SQLite，全面拥抱企业级数据仓库，包含 Snowflake 和 Google BigQuery（Spider2-Snow, Spider2-Lite）。
  - **变态级 Schema 规模**：很多企业的单张宽表列数超过 1000+ 列。Spider 2.0 考察模型在超长上下文中精准筛选可用列（Schema Linking）的能力。
  - **Agentic 工作流（结果导向）**：它不要求模型单纯输出一条 SQL 字符串。模型被放入一个代码沙箱中，可以通过运行 Python/SQL 脚本去探索数据库，最终只要输出正确的**数据结果（CSV 文件）** 即可。这高度还原了程序员“写代码 -> 报错 -> 查数据 -> 修改代码 -> 得到最终图表/数据”的真实循环。
