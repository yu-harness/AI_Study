## 大白话总览

这套流程只做一件事：把 30K 条「用户提问 → Agent 思考 → 调工具 → 拿到结果 → 再回答」的完整过程喂给模型，让它学会照这个格式办事。

五个环节各管一件事，缺一不可：

- **数据构造**决定模型见没见过这种场景
- **数据清洗**决定模型学的是对的还是错的
- **Loss 掩码**决定模型学哪几句话
- **Packing** 决定 8 张卡能不能跑满
- **LoRA + DeepSpeed** 决定 14B 模型装不装得下

一句话：**数据决定学什么，掩码决定学哪句，并行决定跑不跑得动。**

## 一、五个核心概念拆解

### 1. 为什么用 LoRA，而不是全参微调

**先说结论**：基座已经会做事，只是不懂金融口径，所以只改一小部分参数就够了。

Qwen2.5-14B-Instruct 本身会指令跟随、会输出工具调用格式、会多步推理。项目缺的不是“会不会调工具”，而是“调哪个工具、传什么参数、按什么口径说”。这是**领域适配**，不是**能力重建**。

全参微调要更新 140 亿参数，**8 张 A100 装不下**（优化器状态就要 3 倍参数量的显存），而且容易把通用能力训坏。

**四个具体配置的作用**：

| 配置                  | 值                      | 为什么这么设                                                                                              |
| ------------------- | ---------------------- | --------------------------------------------------------------------------------------------------- |
| `lora_rank`         | 64                     | 秩越大，适配器容量越大。常见值 8–32，这里取 64 是因为任务复杂（多智能体角色 + 工具调用格式 + 金融口径），需要更大容量                                  |
| `lora_alpha`        | 128                    | 缩放系数，实际生效比例是 `alpha / rank = 2`。这个比例比绝对值更重要                                                         |
| `lora_target`       | all                    | 对 attention 和 MLP 的所有**线性层**都加适配器，不只加在 q/v 上。任务跨度大时全挂效果更稳                                           |
| `additional_target` | `embed_tokens,lm_head` | 这两个不是线性层，是词嵌入和输出头。**工具名、参数名、特殊 token 全靠它们表达**，不训这两个，模型容易把 `get_realtime_stock` 写成 `get_stock_price` |

**面试可以这么说**：

> LoRA 的 rank 和 alpha 决定适配器容量，target 决定改哪些层。我们任务跨度大，所以 rank 取 64、alpha 取 128（比例 2:1），并且把 embed_tokens 和 lm_head 也加进可训练范围——因为工具调用格式的稳定性主要靠这两个层，光调 attention 不够。

**⚠️ 一个要提前知道的坑**：加上 `embed_tokens` 和 `lm_head` 之后，可训练参数就不止“全参的 1%–2%”了。Qwen2.5 的词表约 15 万，hidden 5120，embedding 一层就是 7.7 亿参数，两层接近 15 亿。面试说“只训 1%”会被追问“加了 embed 还是 1% 吗”，答不上就尴尬。稳妥说法是：**适配器部分约 1%，加上 embedding 和输出头会明显增加，但仍是全参的十分之一量级**。

### 2. 30K 轨迹数据怎么拼出来的

四类数据，各自解决一个能力缺口：

| 类型          | 数量   | 解决什么            | 例子                                   |
| ----------- | ---- | --------------- | ------------------------------------ |
| 单步工具调用      | 10K+ | 学会“一问一调一答”的基本格式 | “我 500 股苹果现在值多少” → 查行情 → 算市值         |
| 多跳多工具       | 10K+ | 学会按顺序串多个工具      | “加息对我的银行股持仓有什么影响” → 查加息 → 查持仓 → 分析影响 |
| Critic 打回改写 | 5K+  | 学会被拒绝后怎么改       | “推荐必涨股” → 被驳回 → 改写成客观陈述              |
| 多轮打断恢复      | 5K+  | 学会挂起和恢复任务       | 分析财报中途问汇率 → 挂起 → 答汇率 → 恢复            |

**多跳数据是难点，靠五步造出来**：

1. **种子抽样**：从真实日志里**聚类出 200 个高频意图模板**（持仓分析、宏观影响、个股对比）
2. **Self-Instruct 扩展**：每个模板用 GPT 生成 5–8 个变体问法，配对应**推理链**
3. **工具轨迹模拟**：用 LangGraph 模拟器 + Mock API 返回固定快照，保证数值前后一致。这部分占 40%
4. **对抗样本注入**：随机插 15% 的中断/纠错分支
5. **自动校验**：工具名合法 → 参数 Schema 合规 → 最终回答引用了 Observation，三道都过才入库

**第 3 步最关键**：如果 Mock 返回的数据每次不一样，模型会学到“工具结果是随机的”，从而不信任结果、自己编数字。固定快照才能让它学会“先看结果再算”。

**清洗环节被删掉的东西**：
- **格式错误样本**（JSON 解析失败、角色标签缺失）约 3.2%
- **金融语义错误**：ticker 和市场不匹配（`AAPL` 配 `SH`）、权重之和不为 1、出现“稳赚不赔”这类禁用语
- **MinHash + LSH 去重**：相似度阈值 0.92，删掉 4.7K 条模板化冗余样本
- **长度处理**：超 2048 token 的滑窗切片；超长财报只保留摘要字段，丢原文

**MinHash + LSH 为什么不用简单哈希**：模板生成的数据往往是“改几个词”的近似重复，精确哈希查不出来。MinHash 把文本压成签名，LSH 把签名分桶，相似的会落进同一个桶，比对次数从 O(n²) 降到近似线性。

### 3. Loss 掩码：遮住什么、放开什么

**原则一句话**：只学模型“该说”的部分，不学“别人说”的部分。

| 角色              | 是否算 loss | 为什么                      |
| --------------- | -------- | ------------------------ |
| `system`        | ❌ -100   | 这是人写的设定，不是模型输出           |
| `user`          | ❌ -100   | 用户的话不该被模型预测              |
| `tool`（工具返回）    | ❌ -100   | 这是外部系统给的，模型学它等于学“编造工具结果” |
| `assistant`     | ✅ 算      | 这才是要学的东西                 |
| `<thought>` 推理链 | ✅ 算      | 要学的不只是最终答案，还有中间怎么想       |

**为什么 tool 返回必须遮掉**（高频考点）：工具结果是外部 API 给的，模型永远不该生成它。如果放开，模型会学到“我可以自己编一个 JSON 当工具结果”，这正是幻觉的源头。

**为什么 `<thought>` 要算进去**：多跳任务的能力体现在“先想清楚要调哪几个工具”。如果不算 thought，模型只学会输出最终答案，遇到**多步任务就会跳步、漏步骤**。算进去，等于把规划能力也当成学习目标。

**Critic 改写样本的掩码更细**：

```
Quant 原始违规输出  → -100（要学的是“不要这么说”）
Critic 审核意见      → -100（这是另一个角色的输出）
改写后的合规输出    → 算 loss（这才是目标行为）
```

这类样本教的是「**被拒绝之后怎么改**」，所以只有改写结果算损失。如果整段都算，模型会同时学会“说违规话”和“说合规话”，等于没纠偏。

**代码上怎么实现**：LLaMA-Factory 的 `sharegpt` 格式会自动把非 assistant 角色设成 -100，`<thought>` 在 assistant 内容里，天然算 loss。如果自己写，就是手工构造 labels 张量。

### 4. packing 与 neat_packing

**packing 解决什么**：短样本拼满定长序列，减少 padding 浪费。

假设 `cutoff_len=2048`，但样本平均只有 400 token。不拼的话，每条样本后面 1600 个位置全是 padding，GPU 四分之三的算力在算空气。

拼起来后，一条 2048 的序列塞进 5 条样本，等效 batch 提升到 2.3 倍——这就是文档里那个数字的来源。

**neat_packing 解决什么**：拼接带来的副作用——跨样本注意力泄漏。

如果只是简单拼接，第 2 条样本的第一个 token 能“看到”第 1 条样本的全部内容。模型会学到不存在的上下文关联，loss 也会算错。

`neat_packing: true` 的作用是：**在拼好的序列内部再加一层块对角掩码**，让每条样本只能看自己那一段。这和前面预训练里的 Document Mask 是同一个东西。

**面试可以这么说**：

> packing 是把多条短样本拼成一条长序列，提高 GPU 利用率，等效 batch 能提升一倍以上。但它会带来跨样本注意力泄漏，所以必须配 neat_packing，在序列内部做块对角掩码，保证每条样本只看自己那一段。

**⚠️ 一个坑**：开了 packing 之后，`per_device_train_batch_size` 的含义变了——一个 batch 里装的是“拼好的长序列”，实际样本数比配置值多。调学习率和 warmup 时要按**实际 token 数**换算，不能只看 batch size。

### 5. lr、warmup、cosine、bf16、梯度裁剪、ZeRO-2

| 配置                       | 作用              | 为什么取这个值                                                                                    |     |
| ------------------------ | --------------- | ------------------------------------------------------------------------------------------ | --- |
| `lr=5e-5`                | 学习率             | LoRA 只训适配器，可以用比全参（常见 1e-5）更大的学习率。5e-5 是 Grid Search 试过 5e-5 / 8e-5 / 1e-4 后的折中：再大就开始遗忘基座能力 |     |
| `warmup_ratio=0.1`       | 前 10% 步数线性升温    | 训练初期梯度方向不稳定，直接上大学习率容易炸。3 epoch 大约 300 步预热                                                  |     |
| `cosine`                 | 余弦衰减            | 前期快速下降、后期缓慢收敛，比 step 衰减更平滑，末端学习率趋近 0 有利于稳定收尾                                               |     |
| `bf16`                   | 混合精度            | 相比 fp16 不需要 loss scaling，动态范围更大，不容易溢出。A100 原生支持                                            |     |
| `gradient_checkpointing` | 不存中间激活，反向时重算    | 用时间换显存，让 14B + 更长序列能塞进 80G                                                                 |     |
| `gradient_clipping=1.0`  | 梯度范数超过 1 就等比缩放  | 多智能体轨迹长、依赖远，偶发梯度爆炸，裁剪是保险丝                                                                  |     |
| `ZeRO-2`                 | 切分优化器状态和梯度，不切参数 | 14B + LoRA 参数量不大，stage 2 已经够；stage 3 要切参数、通信开销更高，没必要                                       |     |

**ZeRO 三个 stage 的区别**（常被追问）：

| Stage | 切什么        | 显存节省   | 通信开销 |
| ----- | ---------- | ------ | ---- |
| 1     | 优化器状态      | 约 4 倍  | 低    |
| 2     | 优化器状态 + 梯度 | 约 8 倍  | 中    |
| 3     | 再加参数本身     | 与卡数成正比 | 高    |

LoRA 的可训练参数少，优化器状态本来就小，stage 2 切完已经够用。stage 3 会把基座参数也切开，每次前向都要 all-gather，通信成为瓶颈——**不是越高级越好**。

`ds_z2_config.json` 里三个参数的作用：

- `overlap_comm: true`：通信和计算重叠，隐藏 all-reduce 的等待时间
- `reduce_scatter: true`：用 reduce-scatter 代替 all-reduce，通信量减半
- `contiguous_gradients: true`：梯度放在连续显存里，减少碎片、提升带宽利用率

**⚠️ 配置里的一处冗余**：`gradient_clipping: 1.0` 和 `max_grad_norm: 1.0` 在 LLaMA-Factory 里指同一个东西，写两遍不报错，但说明是复制来的。面试被问“这两个有什么区别”要能答：**没有区别，一个是 HF Trainer 的参数名，一个是 DeepSpeed 的参数名，同时写以 DeepSpeed 为准**。

## 二、五个高频追问与标准回答

### Q1：lora_rank 为什么是 64？调到 8 或 128 会怎样？

> rank 决定适配器的表达能力。8 只能学很浅的模式调整，适合单一任务；64 能容纳更复杂的行为改变，比如同时学多角色语气和工具调用格式。再往上到 128，收益递减但显存和过拟合风险上升。
> 判断依据是任务跨度：只调风格用 8–16，要改行为模式用 32–64。我们是后者。
> **这是合理设计，不是拍脑袋**——rank 和 alpha 应该按 `alpha/rank` 比例一起调，单改一个没意义。

### Q2：为什么 tool 返回不算 loss？算了会怎样？

> tool 返回是外部系统给的事实，模型永远不该生成它。算进去等于教模型“可以自己编工具结果”，这是幻觉最直接的来源。
> 而且 tool 内容是 JSON，格式高度重复，算了会让 loss 被这批易学的 token 拉低，掩盖真正该学的 assistant 部分。
> **这是硬性原则，不是取舍**——所有做 tool-calling 微调的项目都必须这样遮。

### Q3：packing 会不会让 loss 算错？

> 会，如果不加隔离。简单拼接后，后一条样本能通过注意力看到前一条，loss 会把不存在的上下文关联算进去。
> 所以要配 neat_packing，在序列内部做块对角掩码，每条样本只看自己那段。
> **这是“必须成对出现”的配置**：只开 packing 不开 neat_packing 是常见错误。

### Q4：为什么用 ZeRO-2 不用 ZeRO-3？

> ZeRO-3 会切分模型参数，每次前向都要 all-gather，通信开销大。我们是 LoRA 微调，可训练参数只占很小一部分，优化器状态和梯度本来就小，stage 2 切完显存已经够用。
> 用 stage 3 属于“为了解决不存在的问题引入新瓶颈”。
> **这是取舍**：如果换成全参微调 14B，就必须上 stage 3。

### Q5：lr=5e-5 对 LoRA 来说算大还是小？

> 对 LoRA 算中等偏大。全参微调通常 1e-5 量级，LoRA 因为只训适配器、每步改动局限在低秩子空间，可以用更大学习率加快收敛。
> 5e-5 是 Grid Search 的结果：8e-5 和 1e-4 在验证集上开始出现基座能力退化（通用问答变差），5e-5 是效果和遗忘的平衡点。
> **回答要点**：说清楚“为什么 LoRA 能用更大 lr”，比背数字重要。
